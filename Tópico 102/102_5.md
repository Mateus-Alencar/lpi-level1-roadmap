# Utilização do sistema de pacotes RPM e YUM

## 1. Visão geral

Distribuições da família **Red Hat** (RHEL, CentOS, Fedora, Rocky Linux, AlmaLinux, openSUSE) usam o formato de pacote **RPM** (*RPM Package Manager*). Existem dois níveis de ferramentas:

| Camada | Ferramenta | Função |
|---|---|---|
| Baixo nível | `rpm` | Instala, remove, consulta e verifica pacotes **individuais**, sem resolver dependências automaticamente |
| Alto nível | `yum` / `dnf` | Resolve **dependências**, gerencia repositórios remotos, faz download automático dos pacotes |

> **Ideia central para a prova:** o `rpm` trabalha com arquivos `.rpm` já baixados e não resolve dependências. O `yum`/`dnf` trabalha com repositórios e resolve dependências automaticamente.

O DNF (*Dandified YUM*) é o sucessor do YUM (usado por padrão desde Fedora 22 e RHEL 8+), mas mantém compatibilidade de sintaxe — praticamente todo comando `yum` funciona como `dnf`.

## 2. O comando `rpm`

### 2.1 Estrutura básica

```
rpm [opções] [pacote(s)]
```

As operações principais são indicadas por uma letra maiúscula "modo":

| Modo | Significado |
|---|---|
| `-i` | Install (instalar) |
| `-U` | Upgrade (instala ou atualiza; remove versão antiga) |
| `-F` | Freshen (atualiza **somente se** já houver uma versão instalada) |
| `-e` | Erase (remover) |
| `-q` | Query (consultar) |
| `-V` | Verify (verificar integridade) |

### 2.2 Instalação, atualização e remoção

```bash
rpm -ivh pacote.rpm       # instala (verbose + hash de progresso)
rpm -Uvh pacote.rpm       # atualiza (ou instala se não existir)
rpm -Fvh pacote.rpm       # atualiza somente se já instalado
rpm -e pacote             # remove o pacote
```

Opções comuns combinadas com os modos acima:

| Opção | Significado |
|---|---|
| `-v` | verbose |
| `-h` | exibe hashes (`#`) de progresso |
| `--test` | simula a operação sem executá-la |
| `--nodeps` | ignora verificação de dependências |
| `--force` | força a instalação (sobrescreve conflitos) |
| `--replacepkgs` | reinstala pacote já existente |

> **Atenção:** `rpm -e` **não resolve dependências** — se outro pacote depender do que está sendo removido, o `rpm` recusa a operação (a menos que se use `--nodeps`, o que pode quebrar o sistema).

### 2.3 Consultas (`-q`)

O modo de consulta é um dos pontos mais cobrados na prova. Sintaxe geral:

```
rpm -q[opções extras] pacote
```

| Comando | Resultado |
|---|---|
| `rpm -qa` | Lista **todos** os pacotes instalados |
| `rpm -qi pacote` | Mostra **informações** (versão, tamanho, descrição, licença) |
| `rpm -ql pacote` | Lista os **arquivos** instalados pelo pacote |
| `rpm -qc pacote` | Lista os arquivos de **configuração** do pacote |
| `rpm -qd pacote` | Lista os arquivos de **documentação** do pacote |
| `rpm -qf /caminho/arquivo` | Descobre a **qual pacote** um arquivo pertence |
| `rpm -qp pacote.rpm` | Consulta informações de um **arquivo .rpm ainda não instalado** |
| `rpm -qR pacote` | Lista as **dependências** (requires) do pacote |
| `rpm -q --changelog pacote` | Mostra o histórico de mudanças do pacote |

Combinações muito cobradas:

```bash
rpm -qpi pacote.rpm     # informações de um pacote não instalado
rpm -qpl pacote.rpm     # lista arquivos de um pacote não instalado
rpm -qf /usr/bin/vim    # qual pacote instalou esse arquivo
```

### 2.4 Verificação (`-V` / `--verify`)

Verifica se os arquivos de um pacote instalado foram alterados desde a instalação (comparando tamanho, permissões, dono, checksum MD5, etc.):

```bash
rpm -V pacote
rpm -Va          # verifica TODOS os pacotes instalados
```

Saída típica (cada coluna representa um teste; um ponto `.` significa "OK", uma letra indica falha):

```
S.5....T.  c /etc/httpd/conf/httpd.conf
```

| Código | Significado |
|---|---|
| `S` | Tamanho (Size) diferente |
| `M` | Modo/permissões diferentes |
| `5` | Checksum MD5 diferente |
| `D` | Dispositivo diferente |
| `L` | Link simbólico diferente |
| `U` | Dono (User) diferente |
| `G` | Grupo diferente |
| `T` | Data de modificação (mTime) diferente |
| `c` | Marca o arquivo como **arquivo de configuração** |

### 2.5 Importação de chaves GPG

Pacotes RPM podem ser assinados digitalmente. Para importar a chave pública do fornecedor (necessária para validar assinaturas):

```bash
rpm --import /caminho/RPM-GPG-KEY-nomedistro
rpm -qa gpg-pubkey*        # lista chaves importadas
```

### 2.6 Extraindo conteúdo sem instalar

```bash
rpm2cpio pacote.rpm | cpio -idmv
```

Converte o `.rpm` para o formato `cpio` e extrai os arquivos no diretório atual, sem instalar o pacote no sistema.

## 3. O gerenciador YUM (Yellowdog Updater Modified)

O YUM trabalha sobre repositórios definidos em arquivos `.repo`, geralmente em `/etc/yum.repos.d/`. Ele resolve dependências automaticamente baixando os pacotes necessários da internet ou de um repositório local.

### 3.1 Arquivo de configuração

- Configuração global: `/etc/yum.conf`
- Repositórios individuais: `/etc/yum.repos.d/*.repo`

Exemplo de definição de repositório:

```ini
[meurepo]
name=Meu Repositório Local
baseurl=http://servidor/repo/
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY
```

### 3.2 Comandos essenciais

| Comando | Função |
|---|---|
| `yum install pacote` | Instala um pacote e suas dependências |
| `yum remove pacote` | Remove um pacote (e, por padrão, tenta remover dependências órfãs) |
| `yum update` | Atualiza todos os pacotes do sistema |
| `yum update pacote` | Atualiza um pacote específico |
| `yum check-update` | Lista pacotes com atualização disponível, sem instalar |
| `yum list installed` | Lista pacotes instalados |
| `yum list available` | Lista pacotes disponíveis nos repositórios |
| `yum search termo` | Busca pacotes pelo nome/descrição |
| `yum info pacote` | Mostra informações detalhadas do pacote |
| `yum provides /caminho/arquivo` | Descobre qual pacote fornece determinado arquivo |
| `yum deplist pacote` | Lista as dependências de um pacote |
| `yum clean all` | Limpa o cache local (metadados e pacotes baixados) |
| `yum history` | Mostra o histórico de transações do yum |
| `yum history undo ID` | Desfaz uma transação específica |

### 3.3 Grupos de pacotes

```bash
yum grouplist                  # lista grupos disponíveis
yum groupinstall "Nome Grupo"  # instala um grupo inteiro de pacotes
yum groupremove "Nome Grupo"   # remove um grupo
```

### 3.4 Gerenciamento de repositórios

```bash
yum repolist              # lista repositórios habilitados
yum repolist all          # lista todos (habilitados e desabilitados)
yum-config-manager --enable nome-repo
yum-config-manager --disable nome-repo
```

### 3.5 DNF — sucessor do YUM

Sintaxe praticamente idêntica; principais diferenças conceituais cobradas na prova:

- DNF usa a biblioteca **libsolv** para resolução de dependências (mais eficiente que o algoritmo do YUM).
- Arquivo de config principal: `/etc/dnf/dnf.conf`.
- Mantém compatibilidade: `dnf install`, `dnf remove`, `dnf update`, `dnf search`, `dnf history` funcionam da mesma forma.

## 4. Comparativo rápido RPM x YUM

| Característica | `rpm` | `yum` / `dnf` |
|---|---|---|
| Resolve dependências | Não | Sim |
| Trabalha com repositórios remotos | Não (só arquivo local) | Sim |
| Instala a partir de arquivo `.rpm` | Sim | Sim (`yum install ./pacote.rpm`) |
| Consulta pacotes instalados | Sim (`-q`) | Sim (`list installed`) |
| Verifica integridade de arquivos | Sim (`-V`) | Não (não é sua função) |
| Desfazer operações | Não | Sim (`yum history undo`) |

---

## 5. Pontos de atenção para a prova

1. `rpm -e` falha se houver dependentes; `yum remove` resolve isso automaticamente, avisando o que mais será removido.
2. `rpm -qf` e `yum provides` fazem a mesma pergunta ("de qual pacote veio este arquivo?") em ferramentas diferentes.
3. `-F` (freshen) só atualiza pacotes **já instalados**; não instala pacotes novos — diferente de `-U` (upgrade).
4. `rpm2cpio` é a forma de **extrair** um `.rpm` sem instalá-lo (não confundir com `--test`, que apenas simula a instalação).
5. Repositórios YUM ficam em `/etc/yum.repos.d/`, com extensão `.repo`.
6. `yum clean all` não remove pacotes instalados — apenas limpa cache de metadados/pacotes baixados.
7. Códigos de saída do `rpm -V`: memorizar pelo menos `S`, `M`, `5`, `U`, `G`, `T`.

#### Ex.3
No openSUSE, qual comando do zypper é usado para atualizar todos os pacotes instalados para as versões mais recentes disponíveis nos repositórios configurados?  

A) zypper update  
B) zypper refresh  
C) zypper install --all  
D) zypper patch  

Resposta: A  
> zypper update (ou zypper up) é o comando que efetivamente atualiza os pacotes instalados para as versões mais novas disponíveis nos repositórios.  
> zypper refresh não atualiza pacotes — ele apenas atualiza os metadados dos repositórios (equivalente ao apt-get update ou yum makecache)
