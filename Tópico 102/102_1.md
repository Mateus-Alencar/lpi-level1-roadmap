# Resumo LPIC-1 — Tópico 102.1: Dimensionar Partições de Disco

## 1. Alocação de Sistemas de Arquivos e Swap

O particionamento de discos permite organizar o armazenamento, separar dados de diferentes finalidades e controlar o espaço disponível para cada sistema de arquivos.

A separação de diretórios em partições distintas pode evitar que o esgotamento de espaço em uma área, como `/var/log`, comprometa diretamente o espaço disponível para outras áreas do sistema.

### `/` — Root (Raiz)

- **Função:** Contém a estrutura principal do sistema Linux, incluindo diretórios essenciais, programas e arquivos de configuração.
- **Estratégia:** Caso não existam outras partições ou sistemas de arquivos montados separadamente, os diretórios do sistema estarão armazenados na partição raiz.
- **Importante:** A raiz deve possuir espaço suficiente para o sistema operacional e seus componentes.

### `/boot`

- **Função:** Armazena arquivos necessários para a inicialização do Linux, incluindo o kernel, initramfs e arquivos relacionados ao GRUB.
- **Estratégia:** Pode ser criada como uma partição separada, especialmente quando existem requisitos de compatibilidade com o carregador de boot.
- **Dimensionamento:** O tamanho depende da distribuição, da quantidade de kernels mantidos e dos arquivos de inicialização.
- **Importante:** Não é obrigatória em todas as instalações Linux.

#### Initramfs

O `initramfs` (Initial RAM Filesystem) é um sistema de arquivos temporário carregado na memória RAM durante o processo de inicialização.

Sua função é fornecer ferramentas e módulos necessários para que o kernel consiga localizar e montar o sistema de arquivos raiz definitivo.

### `/home`

- **Função:** Armazena os diretórios pessoais dos usuários comuns.
- **Estratégia:** Pode ser separada da raiz para facilitar reinstalações do sistema operacional sem precisar formatar os dados pessoais.
- **Importante:** A separação não garante a preservação dos dados caso a partição seja formatada durante a reinstalação.

### `/var`

- **Função:** Armazena dados variáveis do sistema.
- **Exemplos:**
  - `/var/log`: arquivos de log.
  - `/var/cache`: dados de cache.
  - `/var/spool`: filas de processamento.
  - `/var/lib`: dados persistentes de aplicações e serviços (mysql, postgres, etc).
- **Estratégia:** Pode ser isolada em servidores para evitar que o crescimento de logs, caches ou dados de aplicações esgote o espaço da raiz `/`.

### `/tmp`

- **Função:** Armazena arquivos temporários criados por aplicações e pelo sistema.
- **Estratégia:** Pode ser montada em uma partição separada ou utilizar `tmpfs`, que armazena os dados na memória RAM e/ou memória de swap.
- **Importante:** Os arquivos de `/tmp` podem ser removidos durante a inicialização, mas isso depende da configuração do sistema.

### Swap — Memória de Troca

- **Função:** Fornece espaço de armazenamento utilizado pelo mecanismo de memória virtual do Linux.
- **Utilização:** Pode armazenar páginas de memória que não precisam permanecer na RAM naquele momento.
- **Importante:** A swap não é simplesmente utilizada somente quando a RAM está completamente esgotada.
- **Formas de implementação:**
  - Partição dedicada.
  - Arquivo de swap (`swapfile`).

O tamanho da swap depende da quantidade de RAM, da carga de trabalho e da necessidade de hibernação.


### Regra do FHS (muito cobrada)

`/etc`, `/bin`, `/sbin`, `/lib` e `/dev` precisam estar no mesmo sistema de arquivos da `/`, porque são necessários para o boot e para montar as demais partições. Portanto **`/etc` nunca é uma partição separada**. Já `/boot`, `/home`, `/var`, `/tmp`, `/opt` e `/usr` podem ser separadas.

## 2. Adaptação do Particionamento ao Uso do Sistema

O dimensionamento das partições deve considerar o propósito do servidor ou estação de trabalho.

| Tipo de sistema | Estratégia de particionamento |
|---|---|
| Servidor de arquivos | Destinar espaço significativo aos dados, utilizando `/home` ou uma partição específica como `/data`. |
| Servidor Web | Considerar o espaço utilizado por logs, aplicações e arquivos publicados. |
| Servidor de Banco de Dados | Considerar o espaço para dados, logs e desempenho do armazenamento. |
| Estação de trabalho | Priorizar espaço para `/home`, aplicações e arquivos pessoais. |
| Sistema embarcado | Pode utilizar uma estrutura simplificada, com uma única partição raiz. |

### Vantagens de separar sistemas de arquivos

- Isolar o consumo de espaço entre diferentes áreas.
- Facilitar o gerenciamento do armazenamento.
- Permitir a utilização de opções específicas de montagem.
- Simplificar estratégias de backup e manutenção.
- Reduzir o impacto do esgotamento de espaço em determinadas áreas.

### Desvantagens

- Maior complexidade no planejamento.
- Possibilidade de dimensionar incorretamente as partições.
- Uma partição pode ficar sem espaço enquanto outra ainda possui espaço livre.

## 3. Garantia de Inicialização do Sistema (Boot)

O esquema de particionamento pode ser influenciado pelo firmware e pelo carregador de boot.

### BIOS / Legacy BIOS

- Utiliza o firmware BIOS tradicional.
- É frequentemente associado ao particionamento MBR.
- Sistemas antigos apresentavam limitações relacionadas ao acesso de discos e à localização dos arquivos de boot.
- O limite histórico dos primeiros 1024 cilindros está relacionado a antigas limitações de endereçamento CHS.
- Em sistemas modernos com suporte a LBA, essa limitação histórica não se aplica da mesma forma.

### UEFI

- Utiliza o firmware UEFI.
- Geralmente trabalha com discos particionados em GPT.
- Requer uma EFI System Partition (ESP) para o carregador de boot.
- A ESP utiliza normalmente o sistema de arquivos FAT32.
- No Linux, a ESP costuma ser montada em `/boot/efi`.

### EFI System Partition (ESP)

A ESP contém arquivos de carregadores de boot utilizados pelo firmware UEFI.

Características:

- Tipo de partição específico para EFI.
- Sistema de arquivos FAT, geralmente FAT32.
- Normalmente possui tamanho de algumas centenas de MB.
- Não deve ser confundida com a partição `/boot`.

## 4. Conceitos de LVM (Logical Volume Manager)

O LVM é uma tecnologia de gerenciamento de armazenamento que adiciona uma camada de abstração entre os dispositivos físicos e os sistemas de arquivos.

Permite agrupar dispositivos e criar volumes lógicos com maior flexibilidade de dimensionamento.

### PV — Physical Volume (Volume Físico)

- É um dispositivo ou uma partição preparada para utilização pelo LVM.
- Pode ser um disco inteiro ou uma partição.
- Exemplo: `/dev/sda3`.

### VG — Volume Group (Grupo de Volumes)

- É um agrupamento de um ou mais PVs.
- Funciona como um pool de armazenamento.
- O espaço disponível pode ser utilizado para criar volumes lógicos.

### LV — Logical Volume (Volume Lógico)

- É criado dentro de um VG.
- Funciona como um dispositivo de armazenamento virtual.
- Pode receber um sistema de arquivos, como ext4 ou XFS.
- Pode ser montado em diretórios do Linux.

### Estrutura do LVM

```text
Discos / Partições
       |
       v
      PVs
       |
       v
      VG
       |
       v
      LVs
       |
       v
Sistema de arquivos
       |
       v
Ponto de montagem
```

### Exemplo prático

```text
/dev/sda3
    |
    v
PV: /dev/sda3
    |
    v
VG: ubuntu-vg
    |
    v
LV: ubuntu-lv
    |
    v
Sistema de arquivos ext4
    |
    v
/
```

### Comandos importantes do LVM

| Comando | Descrição |
|---|---|
| `pvs` | Lista os Physical Volumes. |
| `vgs` | Lista os Volume Groups. |
| `lvs` | Lista os Logical Volumes. |
| `pvdisplay` | Exibe informações detalhadas dos PVs. |
| `vgdisplay` | Exibe informações detalhadas dos VGs. |
| `lvdisplay` | Exibe informações detalhadas dos LVs. |

### Vantagens do LVM

- Flexibilidade para redimensionar volumes.
- Agrupamento de múltiplos dispositivos físicos.
- Melhor aproveitamento do espaço de armazenamento.
- Possibilidade de criação de snapshots.
- Permite adicionar novos dispositivos ao grupo de volumes.

**Importante:** O redimensionamento depende do sistema de arquivos utilizado e de suas limitações. A expansão de volumes e sistemas de arquivos pode ser realizada online em muitos casos, mas a redução pode exigir desmontagem ou procedimentos adicionais.

## 5. MBR vs GPT

| Característica | MBR (Master Boot Record) | GPT (GUID Partition Table) |
|---|---|---|
| Limite de tamanho tradicional | Aproximadamente 2 TiB com setores de 512 bytes | Suporta discos muito maiores |
| Partições primárias | Máximo de 4 entradas primárias | Normalmente 128 entradas por padrão |
| Partição estendida | Permite uma partição estendida | Não utiliza partição estendida |
| Partições lógicas | Utilizadas dentro da partição estendida | Não são necessárias |
| Redundância da tabela | Não possui cópia de segurança equivalente ao GPT | Mantém cabeçalho e tabela de backup |
| Verificação de integridade | Sem CRC da tabela de partições | Utiliza CRC para verificar estruturas |
| Firmware associado | Comumente BIOS | Comumente UEFI |
| Ferramentas | `fdisk`, `parted` | `gdisk`, `parted`, `fdisk` moderno |

**Observação:** O GPT também pode ser utilizado em sistemas BIOS. A associação GPT/UEFI e MBR/BIOS é comum, mas não é uma regra absoluta.

### Partição Primária

- É uma entrada de partição diretamente registrada na tabela MBR.
- O MBR permite até quatro entradas primárias.
- Uma partição primária pode conter um sistema de arquivos ou ser utilizada para outros fins.
- Não é obrigatório que o sistema operacional esteja instalado em uma partição primária.

### Partição Estendida

- É um tipo especial de partição utilizado no esquema MBR.
- Ocupa uma das quatro entradas disponíveis na tabela.
- Funciona como um contêiner para partições lógicas.
- Não é utilizada para armazenar diretamente um sistema de arquivos convencional.

### Partição Lógica

- É criada dentro de uma partição estendida.
- Permite ultrapassar o limite de quatro entradas primárias do MBR.
- Pode armazenar sistemas de arquivos e dados.
- Pode ser utilizada para inicialização, dependendo da configuração do sistema e do carregador de boot.

### Exemplo de esquema MBR

```text
/dev/sda
├── /dev/sda1  # Partição primária
├── /dev/sda2  # Partição primária
├── /dev/sda3  # Partição primária
└── /dev/sda4  # Partição estendida
    ├── /dev/sda5  # Partição lógica
    └── /dev/sda6  # Partição lógica
```

**Importante:** A partição estendida é um contêiner. Ela não é uma partição de dados convencional.

## 6. Comandos para Identificar e Gerenciar Partições

| Comando | Descrição |
|---|---|
| `lsblk` | Lista discos, partições e volumes lógicos. |
| `lsblk -f` | Exibe sistemas de arquivos, UUIDs e pontos de montagem. |
| `fdisk -l` | Lista discos e tabelas de partições. |
| `gdisk -l /dev/sda` | Exibe informações sobre uma tabela GPT. |
| `parted -l` | Lista dispositivos e suas tabelas de partições. |
| `df -hT` | Exibe utilização de espaço e tipos de sistemas de arquivos montados. |
| `du -sh /var` | Exibe o tamanho ocupado pelo diretório `/var`. |
| `findmnt` | Exibe os sistemas de arquivos montados. |
| `blkid` | Identifica UUIDs e tipos de sistemas de arquivos. |
| `swapon --show` | Exibe os dispositivos e arquivos de swap ativos. |

### Exemplos

Listar dispositivos:

```bash
lsblk
```

Identificar sistemas de arquivos:

```bash
lsblk -f
```

Verificar a raiz:

```bash
findmnt /
```

Listar partições:

```bash
sudo fdisk -l
```

Verificar swap:

```bash
swapon --show
```

## 7. Pontos Importantes para a LPIC-1

- MBR suporta até quatro entradas primárias.
- Uma entrada MBR pode ser utilizada para criar uma partição estendida.
- Partições lógicas são criadas dentro da partição estendida.
- GPT não utiliza partições primárias, estendidas ou lógicas como o MBR.
- A ESP é utilizada por sistemas UEFI e geralmente é formatada em FAT32.
- `/boot` e `/boot/efi` são conceitos diferentes.
- LVM possui três componentes principais: PV, VG e LV.
- Swap pode ser implementada em uma partição ou em um arquivo.
- `/home`, `/var` e `/tmp` podem ser separados da raiz, mas não precisam ser.
- O particionamento deve considerar o propósito e a necessidade de armazenamento do sistema.
- `lsblk` permite visualizar a estrutura de discos, partições e volumes lógicos.

## Exercícios  
#### Ex.1
1. Um administrador de sistemas está configurando um novo servidor x86_64 que utilizará o firmware UEFI para inicializar o sistema operacional. Qual é o tipo de sistema de arquivos obrigatório que deve ser utilizado na partição do sistema EFI (ESP) para que o firmware consiga ler os gerenciadores de inicialização?  
A) ext4  
B) XFS  
C) VFAT  
D) btrfs  
E) swap  

Resposta Corret: C
Explicação: O padrão de firmware UEFI exige obrigatoriamente que a Partição do Sistema EFI (ESP) seja formatada em um sistema de arquivos baseado em FAT (geralmente FAT32, representado no Linux como **vfat**).  

#### Ex.2
2. Qual comando do Linux é utilizado exclusivamente para inicializar e formatar uma área de partição ou arquivo previamente criado para que ele funcione especificamente como espaço de paginação de memória (swap)?  

Resposta correta: `mkswap`  

#### Ex.3
3. Você precisa planejar o layout de disco de uma máquina Linux que possui apenas 4GB de memória RAM e executará serviços web básicos. O espaço swap precisa ser configurado. Pensando no particionamento tradicional MBR, qual das seguintes estratégias é a mais recomendada pela LPI para a distribuição do swap e do sistema de arquivos raiz?  
A) Criar o swap dentro do diretório /boot para acelerar o carregamento inicial.  
B) Configurar o swap como um volume lógico dentro do LVM para permitir flexibilidade de redimensionamento futuro.  
C) Colocar o swap na primeira partição primária e formatá-lo obrigatoriamente como ext3.  
D) Alocar o swap dentro de /home para garantir a segurança dos dados voláteis dos usuários.  
E) Eliminar completamente a partição swap, pois sistemas modernos com mais de 2GB de RAM não a utilizam.  

Resposta correta: B
Explicação: Uma das principais vantagens do LVM (Logical Volume Manager) é a flexibilidade. Alocar o swap como um volume lógico (LV) permite que você aumente ou diminua o espaço de paginação

#### Ex.4
4. Um analista de infraestrutura quer implementar o LVM (Logical Volume Manager) em um novo servidor para facilitar a expansão futura de partições como /home e /var. Qual das seguintes afirmações descreve corretamente uma característica fundamental ou limitação do LVM no contexto da inicialização do sistema?  
A) A partição /boot deve sempre residir em um volume lógico LVM striping (RAID 0) para inicializar o kernel.  
B) O LVM não permite que o volume lógico do sistema de arquivos raiz (/) seja redimensionado.  
C) Se o gerenciador de boot tradicional não tiver suporte nativo para ler volumes lógicos LVM complexos, o diretório /boot deve ser colocado em uma partição padrão fora do LVM.  
D) O LVM substitui completamente a necessidade de uma tabela de partições GPT ou MBR no disco rígido.  
E) Volumes lógicos LVM só podem ser criados a partir de arquivos de imagem, nunca de partições físicas de disco.

Resposta Correta: C  
Explicação: Se o gerenciador de boot ou o firmware antigo não conseguir ler estruturas LVM complexas, a recomendação oficial de projeto é criar uma partição padrão e separada para o /boot (fora do LVM).  

#### Ex.5
5. Um administrador precisa planejar um layout de disco para uma estação de trabalho Linux antiga que utiliza uma tabela de partições MBR (Master Boot Record). O projeto exige a criação de 6 sistemas de arquivos separados em partições distintas. Como o administrador deve estruturar o particionamento físico do disco?  
A) Criar 6 partições primárias.  
B) Criar 3 partições primárias e 3 partições estendidas.  
C) Criar 4 partições primárias e 2 partições lógicas dentro de uma das primárias.  
D) Criar 3 partições primárias e 1 partição estendida, contendo 3 partições lógicas dentro dela.  
E) O padrão MBR não suporta mais do que 4 partições no total, tornando o projeto impossível sem GPT.

Resposta correta: D
Explicação: O padrão MBR possui uma limitação histórica: ele só permite, no máximo, 4 partições primárias no disco rígido. No entanto, o projeto exige 6 sistemas de arquivos (6 partições). Para superar essa limitação, a arquitetura MBR permite transformar uma (e apenas uma) das 4 partições primárias em uma partição estendida.  

#### Ex.6  
Um administrador está projetando o particionamento de um servidor e quer colocar diretórios em partições separadas da raiz (/). Qual dos diretórios abaixo não pode ficar em uma partição separada, segundo o FHS, por ser necessário durante o boot?  

A. /home  
B. /var  
C. /etc  
D. /boot  
E. /opt  

Resposta: C  

> Explicação: O FHS exige que /etc, /bin, /sbin, /lib e /dev estejam no mesmo sistema de arquivos da /. São os diretórios de que o sistema precisa para subir e montar as demais partições. Se o /etc estivesse em outra partição, o sistema não conseguiria ler o /etc/fstab para montá-la.
