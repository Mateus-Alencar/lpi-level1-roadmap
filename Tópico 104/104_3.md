## 2. Conceitos fundamentais

### 2.1 A árvore única de diretórios

Diferente do Windows (`C:\`, `D:\`), o Linux possui **uma única árvore de diretórios** que começa em `/` (raiz). Todo dispositivo de armazenamento (partição, pendrive, DVD, volume LVM, compartilhamento de rede) é **anexado** a algum diretório dessa árvore. Esse "anexar" é a **montagem**.

```
/  (raiz, partição /dev/sda2)
├── bin
├── etc
├── home      ← pode ser outra partição (/dev/sda3)
├── mnt
│   └── dados ← pendrive montado manualmente (/dev/sdb1)
├── media
│   └── cdrom ← DVD montado (/dev/sr0)
└── var       ← pode ser outro disco (/dev/sdc1)
```

### 2.2 Vocabulário essencial

| Termo | Definição |
|---|---|
| **Dispositivo (device)** | O "lugar" onde os dados estão: `/dev/sdb1`, `/dev/nvme0n1p2`, `/dev/mapper/vg-lv`, `server:/export`. |
| **Sistema de arquivos (filesystem)** | A estrutura lógica gravada no dispositivo: ext4, XFS, Btrfs, FAT32, NTFS, iso9660... |
| **Ponto de montagem (mount point)** | O diretório onde o conteúdo do dispositivo ficará visível. |
| **Montar** | Tornar o conteúdo de um filesystem acessível em um ponto de montagem. |
| **Desmontar** | Desconectar o filesystem, garantindo que todos os dados pendentes foram gravados. |
| **VFS** | Camada do kernel que permite tratar todos os filesystems de forma uniforme. |

### 2.3 Ponto importante: montar "esconde" o conteúdo anterior

Se o diretório usado como ponto de montagem **já possui arquivos**, eles ficam **ocultos** (não são apagados!) enquanto o filesystem estiver montado ali. Ao desmontar, os arquivos originais voltam a aparecer.

```bash
mkdir /teste
echo "ola" > /teste/arquivo.txt
mount /dev/sdb1 /teste     # arquivo.txt some da vista
ls /teste                  # mostra o conteúdo do /dev/sdb1
umount /teste
ls /teste                  # arquivo.txt reaparece
```

**Boa prática:** use sempre um diretório **vazio** como ponto de montagem.

### 2.4 Por que desmontar corretamente?

O kernel mantém dados em **cache** (page cache) e grava no disco de forma assíncrona. Retirar um pendrive sem desmontar pode causar **perda de dados** ou **corrupção** do filesystem. O `umount` força o *flush* (descarga) do cache antes de liberar o dispositivo. O comando `sync` também força essa gravação, mas não substitui o `umount`.

## 3. Onde montar: `/mnt` e `/media`

O **FHS (Filesystem Hierarchy Standard)** define:

| Diretório | Uso previsto |
|---|---|
| `/mnt` | Montagens **temporárias feitas manualmente** pelo administrador. |
| `/media` | Ponto de montagem para **mídias removíveis** (CD/DVD, pendrives), geralmente montadas **automaticamente** pelo ambiente gráfico. |

**Observações do mundo real:**

- Em muitas distribuições modernas o automount de mídias removíveis acontece em `/run/media/<usuario>/<LABEL>` (Fedora, RHEL, Arch) ou `/media/<usuario>/<LABEL>` (Ubuntu, Debian). Isso é feito pelo **udisks2**, acionado pelo ambiente de desktop.
- Nada impede montar em qualquer outro diretório (`/dados`, `/backup`, `/var/lib/mysql`...). `/mnt` e `/media` são **convenções**, não regras do kernel.
- O ponto de montagem **precisa existir** (`mkdir -p`) antes do `mount`.

## 4. Descobrindo dispositivos e o que está montado

Antes de montar, você precisa saber **qual** dispositivo e **qual** tipo de filesystem.

### 4.1 `lsblk`: lista dispositivos de bloco em árvore

```bash
lsblk
lsblk -f                      # mostra FSTYPE, LABEL, UUID e MOUNTPOINT
lsblk -p                      # caminhos completos (/dev/sda1)
lsblk -o NAME,SIZE,FSTYPE,UUID,MOUNTPOINT
```

Exemplo de saída do `lsblk -f`:

```
NAME   FSTYPE LABEL  UUID                                 MOUNTPOINTS
sda
├─sda1 vfat   EFI    A1B2-C3D4                            /boot/efi
├─sda2 ext4   ROOT   3f8e9a2c-5d41-4b7e-9c1a-0e6b7d2f1a44 /
└─sda3 swap          9b7c1e55-2a3d-4f60-8e12-77aa31c0d9be [SWAP]
sdb
└─sdb1 ext4   DADOS  c0ffee00-1234-4abc-9def-0123456789ab
```

Uma coluna `MOUNTPOINT` vazia significa **não montado**.

### 4.2 `blkid`: mostra UUID, LABEL e TYPE

```bash
sudo blkid                           # todos os dispositivos
sudo blkid /dev/sdb1                 # um dispositivo
sudo blkid -s UUID -o value /dev/sdb1   # só o UUID, ideal para scripts
sudo blkid -L DADOS                  # qual dispositivo tem o label DADOS?
sudo blkid -U c0ffee00-1234-4abc-9def-0123456789ab   # qual dispositivo tem esse UUID?
```

Saída típica:

```
/dev/sdb1: LABEL="DADOS" UUID="c0ffee00-1234-4abc-9def-0123456789ab" TYPE="ext4" PARTUUID="8d2f1c3a-01"
```

> `blkid` normalmente exige **root** para ler os dispositivos (ou usa um cache em `/run/blkid/`). `lsblk -f` funciona sem root.

### 4.3 O que está montado agora?

| Comando / arquivo | O que mostra |
|---|---|
| `mount` (sem argumentos) | Lista **todos** os filesystems montados (inclusive virtuais: proc, sysfs, tmpfs...). |
| `mount -t ext4` | Lista só os montados do tipo ext4. |
| `findmnt` | Árvore de montagens, formato muito mais legível. |
| `df -hT` | Uso de espaço, tipo e ponto de montagem (só filesystems "reais" por padrão). |
| `/proc/mounts` | Lista **real e atual** mantida pelo kernel. |
| `/etc/mtab` | Historicamente um arquivo de texto mantido pelo `mount`. Hoje é um **link simbólico** para `/proc/self/mounts`. |

### 4.4 `findmnt`: o canivete suíço moderno

```bash
findmnt                          # árvore completa
findmnt /dados                   # detalhes de um ponto de montagem
findmnt -t ext4,xfs              # filtrar por tipo
findmnt -S /dev/sdb1             # filtrar por origem (source)
findmnt -S UUID=c0ffee00-...     # por UUID
findmnt -T /dados/projeto/a.txt  # qual filesystem contém ESTE caminho?
findmnt --fstab                  # mostra o conteúdo do /etc/fstab em formato de tabela
findmnt --verify                 # valida o /etc/fstab (detecta erros de sintaxe e de dispositivo)
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS
```

> `findmnt --verify` é excelente para **validar o fstab antes de reiniciar**.

### 4.5 Links estáveis em `/dev/disk/`

O **udev** cria links simbólicos que não mudam entre reboots:

```bash
ls -l /dev/disk/by-uuid/     # por UUID do filesystem
ls -l /dev/disk/by-label/    # por LABEL
ls -l /dev/disk/by-id/       # por fabricante/modelo/serial
ls -l /dev/disk/by-path/     # por caminho físico (porta SATA/USB)
ls -l /dev/disk/by-partuuid/ # por UUID da partição (tabela GPT)
```

## 5. O comando `mount`

### 5.1 Sintaxe geral

```bash
mount [-t TIPO] [-o OPÇÕES] DISPOSITIVO PONTO_DE_MONTAGEM
```

### 5.2 Exemplos básicos

```bash
# Montagem simples (o tipo é detectado automaticamente)
sudo mount /dev/sdb1 /mnt/dados

# Especificando o tipo
sudo mount -t ext4 /dev/sdb1 /mnt/dados

# Com opções
sudo mount -t ext4 -o ro,noexec /dev/sdb1 /mnt/dados

# Por UUID ou LABEL (preferível a /dev/sdX)
sudo mount UUID=c0ffee00-1234-4abc-9def-0123456789ab /mnt/dados
sudo mount LABEL=DADOS /mnt/dados
sudo mount -U c0ffee00-1234-4abc-9def-0123456789ab /mnt/dados
sudo mount -L DADOS /mnt/dados
```

### 5.3 Montagem usando só um argumento (consulta o fstab)

Se o dispositivo ou o ponto de montagem **já estiver no `/etc/fstab`**, basta informar **um só** deles. O `mount` busca o restante no fstab:

```bash
sudo mount /mnt/dados        # usa a linha do fstab cujo ponto é /mnt/dados
sudo mount /dev/sdb1         # idem, procurando pelo dispositivo
```

Este é também o mecanismo que permite a **usuários comuns** montarem (seção 10).

### 5.4 Principais opções do comando `mount`

| Opção | Função |
|---|---|
| `-t TIPO` | Tipo do filesystem (`ext4`, `xfs`, `vfat`, `ntfs-3g`, `iso9660`, `nfs`...). |
| `-o OPÇÕES` | Opções de montagem separadas por vírgula (seção 6). |
| `-a` | Monta **todos** os filesystems do fstab (exceto os marcados `noauto`). |
| `-r` / `-o ro` | Monta somente-leitura. |
| `-w` / `-o rw` | Monta leitura-escrita. |
| `-L LABEL` | Seleciona o dispositivo pelo label. |
| `-U UUID` | Seleciona o dispositivo pelo UUID. |
| `-v` | Verboso. |
| `-f` | *Fake*: simula, sem executar de fato (testes). |
| `-n` | Não grava no `/etc/mtab` (relevante em sistemas antigos). |
| `-T ARQUIVO` | Usa um arquivo alternativo no lugar do `/etc/fstab`. |
| `--bind` | Monta um diretório (ou arquivo) em **outro** lugar. |
| `--rbind` | Bind **recursivo** (inclui submontagens). |
| `--move` | Move um ponto de montagem existente para outro local. |
| `-O OPÇÕES` | Com `-a`, limita aos filesystems que tenham essas opções no fstab. |

```bash
sudo mount -a                  # monta tudo do fstab que ainda não esteja montado
sudo mount -a -t ext4          # só os ext4 do fstab
sudo mount -a -O nofail        # só os que têm a opção nofail
```

### 5.5 Remontagem (`remount`): alterar opções sem desmontar

```bash
# Colocar a raiz em leitura-escrita (comum em modo de emergência)
sudo mount -o remount,rw /

# Torná-la somente-leitura
sudo mount -o remount,ro /

# Mudar opções de um ponto específico
sudo mount -o remount,noatime /dados
```

> Atenção: `remount` **não** precisa informar o dispositivo, só o ponto de montagem (ou o dispositivo). Opções não citadas normalmente são **mantidas**.

### 5.6 Bind mount

Faz um diretório aparecer em dois lugares ao mesmo tempo (sem copiar nada):

```bash
sudo mount --bind /var/www /srv/ftp/site
# Equivalente no fstab:
# /var/www  /srv/ftp/site  none  bind  0 0
```

Muito usado em **chroot**, containers e para expor diretórios a serviços que só enxergam uma pasta. Para tornar o bind somente-leitura, faça em duas etapas:

```bash
sudo mount --bind /var/www /srv/ftp/site
sudo mount -o remount,bind,ro /srv/ftp/site
```

### 5.7 Montando uma imagem ISO (dispositivo *loop*)

```bash
sudo mkdir /mnt/iso
sudo mount -o loop /home/user/debian.iso /mnt/iso
# ou, explicitando o tipo
sudo mount -t iso9660 -o loop,ro debian.iso /mnt/iso
```

O `loop` faz um **arquivo regular** se comportar como um dispositivo de bloco (`/dev/loopN`). Funciona com qualquer imagem de filesystem, não só ISO.

### 5.8 Montando sistemas de arquivos de rede

```bash
# NFS
sudo mount -t nfs servidor:/export/dados /mnt/nfs

# CIFS/SMB (Windows/Samba)
sudo mount -t cifs //servidor/compartilhamento /mnt/smb -o username=maria,uid=1000
```

Para filesystems de rede no fstab, use `_netdev` (indica que depende da rede) e prefira `nofail` quando não for crítico.

### 5.9 Tipos de filesystem comuns

| Tipo | Uso |
|---|---|
| `ext2/ext3/ext4` | Padrão tradicional Linux |
| `xfs` | Padrão do RHEL/CentOS, ótimo para arquivos grandes |
| `btrfs` | Snapshots, subvolumes, checksums |
| `vfat` | FAT16/FAT32 (pendrives, partição EFI) |
| `exfat` | Pendrives/cartões grandes |
| `ntfs-3g` / `ntfs3` | NTFS (Windows) |
| `iso9660` | CD/DVD |
| `udf` | DVD/Blu-ray |
| `nfs` / `cifs` | Rede |
| `tmpfs` | Sistema de arquivos em **RAM** |
| `swap` | Área de troca (não é "montada", veja seção 11) |
| `proc`, `sysfs`, `devpts` | Filesystems virtuais do kernel |

## 6. Opções de montagem (`-o`)

As opções valem tanto na linha de comando quanto no **4º campo do fstab**.

### 6.1 As mais cobradas

| Opção | Significado | Oposto |
|---|---|---|
| `rw` | Leitura e escrita | `ro` (somente leitura) |
| `exec` | Permite executar binários | `noexec` |
| `suid` | Honra os bits SUID/SGID | `nosuid` |
| `dev` | Interpreta arquivos de dispositivo (`/dev/...`) | `nodev` |
| `auto` | Montado por `mount -a` / no boot | `noauto` |
| `user` | Usuário comum **pode montar** (só quem montou desmonta) | `nouser` |
| `users` | Qualquer usuário pode montar **e desmontar** | |
| `owner` | Dono do dispositivo (arquivo em `/dev`) pode montar | |
| `group` | Membro do grupo do dispositivo pode montar | |
| `sync` | Escritas **síncronas** (lento, mais seguro p/ removíveis) | `async` |
| `atime` / `relatime` / `noatime` | Política de atualização do tempo de acesso | |
| `remount` | Altera opções de algo já montado | |
| `defaults` | Atalho: `rw, suid, dev, exec, auto, nouser, async` | |
| `nofail` | Não falha o boot se o dispositivo estiver ausente | |
| `_netdev` | Filesystem de rede, só monta depois da rede | |
| `loop` | Usa um dispositivo loop | |
| `bind` | Bind mount | |

### 6.2 Atenção a detalhes

- **`defaults`** = `rw, suid, dev, exec, auto, nouser, async`. Memorize.
- **`relatime`** é o padrão moderno do kernel: atualiza o `atime` apenas se ele for mais antigo que `mtime`/`ctime` ou com mais de 24h. É um meio-termo de desempenho.
- **`user`, `users`, `owner` e `group`** implicam automaticamente **`noexec,nosuid,nodev`**, a menos que você escreva `exec`, `suid` ou `dev` **depois** deles na lista (a ordem importa!).

```fstab
# noexec,nosuid,nodev implícitos
/dev/sdb1  /mnt/usb  vfat  user,noauto  0 0

# exec reativado, pois aparece DEPOIS de user
/dev/sdb1  /mnt/usb  vfat  user,exec,noauto  0 0

# exec é sobrescrito por noexec (que vem implícito depois)
/dev/sdb1  /mnt/usb  vfat  exec,user,noauto  0 0
```

### 6.3 Opções específicas de alguns filesystems

| Filesystem | Opções úteis |
|---|---|
| `vfat` / `ntfs` | `uid=1000`, `gid=1000`, `umask=022`, `fmask=133`, `dmask=022`, `iocharset=utf8` |
| `ext4` | `errors=remount-ro`, `discard`, `data=ordered` |
| `tmpfs` | `size=512m`, `mode=1777`, `nr_inodes=` |
| `nfs` | `rw`, `soft`/`hard`, `vers=4`, `timeo=`, `_netdev` |
| `xfs` | `nouuid` (permite montar clone com UUID duplicado), `prjquota`, `usrquota` |

> FAT/NTFS **não suportam permissões Unix**. Por isso, quem define o dono e as permissões dos arquivos é o próprio `mount` (via `uid`, `gid`, `umask`).

## 7. O comando `umount`

### 7.1 Sintaxe

```bash
umount [opções] PONTO_DE_MONTAGEM | DISPOSITIVO
```

Note a grafia: é **`umount`** (sem o "n"), um dos erros mais comuns ao digitar.

```bash
sudo umount /mnt/dados          # pelo ponto de montagem (mais comum)
sudo umount /dev/sdb1           # pelo dispositivo (também vale)
sudo umount -a                  # desmonta tudo que está no mtab (cuidado!)
sudo umount -a -t nfs           # desmonta todos os NFS
```

### 7.2 Opções importantes

| Opção | Função |
|---|---|
| `-a` | Desmonta todos os filesystems listados (exceto `/` e os essenciais) |
| `-t TIPO` | Restringe por tipo |
| `-f` | **Força** (útil para NFS inacessível) |
| `-l` | **Lazy**: remove o ponto da árvore agora e finaliza quando deixar de estar ocupado |
| `-r` | Se falhar, tenta **remontar como somente-leitura** |
| `-R` | Desmonta recursivamente |
| `-v` | Verboso |

### 7.3 O clássico erro "target is busy"

```
umount: /mnt/dados: target is busy.
```

Significa que **há processos usando** o filesystem (um shell com `cd` dentro dele, um programa com arquivo aberto, outro mount aninhado). Para descobrir quem:

```bash
fuser -vm /mnt/dados            # lista processos usando o ponto de montagem
lsof +f -- /mnt/dados           # mostra os arquivos abertos
lsof /mnt/dados                 # alternativa
```

Resolução:

1. Saia do diretório (`cd ~`).
2. Encerre/feche os processos (`kill`) ou use `fuser -km /mnt/dados` (**mata** todos os processos que o usam, cuidado!).
3. Tente `umount` novamente.
4. Último recurso: `umount -l /mnt/dados` (lazy).

### 7.4 Quem pode desmontar?

- **root:** sempre.
- **Usuário comum:** somente se o filesystem estiver no fstab com `user` (e **foi ele** quem montou) ou `users`.

### 7.5 Antes de remover mídia

```bash
sync                    # força gravação do cache
sudo umount /mnt/usb
# Só então retire o pendrive
```

## 8. O arquivo `/etc/fstab`

O **fstab** (*file systems table*) descreve **quais** filesystems devem ser montados, **onde** e **como**. É lido:

- No **boot** (pelo systemd, via `systemd-fstab-generator`, ou pelo `mount -a` em sistemas SysV).
- Quando você executa `mount -a`.
- Quando você executa `mount` / `umount` informando **apenas um** argumento.

### 8.1 Estrutura: 6 campos separados por espaços ou tabs

```
<dispositivo>   <ponto de montagem>   <tipo>   <opções>   <dump>   <pass>
```

| # | Campo | Descrição |
|---|---|---|
| 1 | **Dispositivo (file system)** | `/dev/sdb1`, `UUID=...`, `LABEL=...`, `PARTUUID=...`, `servidor:/export`... |
| 2 | **Ponto de montagem** | Diretório de destino. Para swap usa-se `none` (ou `swap`). |
| 3 | **Tipo** | `ext4`, `xfs`, `vfat`, `nfs`, `swap`, `tmpfs`, `auto`... |
| 4 | **Opções** | Lista separada por vírgula, sem espaços (`defaults`, `noatime`...). |
| 5 | **dump** | `0` = ignorado pelo `dump`; `1` = incluir no backup do `dump`. Hoje quase sempre `0`. |
| 6 | **pass** | Ordem de verificação do `fsck` no boot: `0` = não verificar, `1` = raiz, `2` = demais. |

### 8.2 Exemplo comentado

```fstab
# <file system>                            <mount point>  <type>  <options>              <dump> <pass>

# Raiz: pass = 1 (verificada primeiro)
UUID=3f8e9a2c-5d41-4b7e-9c1a-0e6b7d2f1a44  /              ext4    errors=remount-ro      0      1

# Partição EFI
UUID=A1B2-C3D4                             /boot/efi      vfat    umask=0077             0      1

# /home em outra partição, identificada por label
LABEL=HOME                                 /home          ext4    defaults,noatime       0      2

# Disco de dados que PODE estar ausente (não trava o boot)
UUID=c0ffee00-1234-4abc-9def-0123456789ab  /dados         xfs     defaults,nofail        0      0

# Swap
UUID=9b7c1e55-2a3d-4f60-8e12-77aa31c0d9be  none           swap    sw                     0      0

# Pendrive: usuário comum pode montar, não monta sozinho no boot
/dev/sdb1                                  /media/usb     vfat    user,noauto,uid=1000   0      0

# Drive de CD/DVD
/dev/sr0                                   /media/cdrom   iso9660 ro,user,noauto         0      0

# Compartilhamento NFS
servidor:/export/dados                     /mnt/nfs       nfs     defaults,_netdev       0      0

# /tmp em memória RAM
tmpfs                                      /tmp           tmpfs   defaults,size=512m,mode=1777  0  0

# Bind mount
/var/www                                   /srv/ftp/site  none    bind                   0      0
```

### 8.3 Detalhes de cada campo

**Campo 1: como identificar o dispositivo**

| Forma | Estável? | Comentário |
|---|---|---|
| `/dev/sdb1` | ❌ | O nome pode **mudar** se a ordem dos discos mudar. Evite em fstab de discos extras. |
| `UUID=...` | ✅ | Identificador único do **filesystem**. **Recomendado.** |
| `LABEL=...` | ✅ | Legível, mas pode haver **duplicatas** entre discos. |
| `PARTUUID=...` | ✅ | UUID da **partição** (GPT). Útil quando o filesystem não tem UUID. |
| `PARTLABEL=...` | ✅ | Nome da partição (GPT). |
| `/dev/disk/by-id/...` | ✅ | Baseado no hardware. |

**Campo 3: tipo `auto`**

Com `auto`, o `mount` tenta detectar o tipo (típico em dispositivos removíveis).

**Campo 5: dump**

O utilitário `dump` é pouco usado atualmente. O valor `0` é praticamente universal.

**Campo 6: pass (fsck)**

- `1` → apenas o **root** (`/`).
- `2` → demais filesystems, verificados **após** o root (podem rodar em paralelo se estiverem em discos diferentes).
- `0` → **nunca** verificar. Use para swap, tmpfs, rede, e também para **XFS** e **Btrfs** (que não usam `fsck` tradicional no boot).

### 8.4 Regras de sintaxe

- Linhas iniciadas com `#` são comentários.
- Linhas em branco são ignoradas.
- Campos separados por **espaços ou tabs** (qualquer quantidade).
- Se o caminho tiver espaço, use `\040` (ex.: `/mnt/meu\040disco`).
- **Não** coloque espaços dentro da lista de opções.

### 8.5 Aplicando mudanças sem reiniciar

```bash
# 1. Edite o arquivo
sudo nano /etc/fstab

# 2. Valide a sintaxe e os dispositivos
findmnt --verify

# 3. Em sistemas com systemd, recarregue as units geradas
sudo systemctl daemon-reload

# 4. Monte tudo o que ainda não estiver montado
sudo mount -a

# 5. Confira
findmnt /dados
```

> **Regra de ouro:** **nunca reinicie** sem antes testar com `mount -a`. Um fstab com erro pode deixar o sistema em **modo de emergência**.

### 8.6 `noauto` vs. `auto` e `nofail`

| Opção | Efeito |
|---|---|
| `auto` (padrão) | Montado no boot e por `mount -a`. |
| `noauto` | **Não** é montado no boot nem por `mount -a`; só manualmente (`mount /ponto`). |
| `nofail` | Monta no boot, mas se o dispositivo não existir, **o boot continua** sem erro fatal. |

### 8.7 Opções específicas do systemd no fstab

O `systemd-fstab-generator` entende opções com prefixo `x-systemd.`:

| Opção | Função |
|---|---|
| `x-systemd.automount` | Monta **sob demanda**, no primeiro acesso ao diretório. |
| `x-systemd.device-timeout=10s` | Tempo máximo de espera pelo dispositivo. |
| `x-systemd.idle-timeout=60s` | Com automount, desmonta após ociosidade. |
| `x-systemd.requires=` / `x-systemd.after=` | Dependências extras. |

```fstab
UUID=c0ff...  /backup  ext4  noauto,x-systemd.automount,x-systemd.idle-timeout=120  0  0
```

## 9. UUID e LABEL

### 9.1 O problema dos nomes `/dev/sdX`

O kernel atribui `sda`, `sdb`, `sdc`... **na ordem em que detecta os discos**. Adicionar/remover um disco, trocar uma porta USB ou mudar o controlador pode **trocar os nomes**. Se o fstab usa `/dev/sdb1` e o disco virar `sdc1`, o sistema monta a coisa errada (ou falha).

**Solução:** identificar pelo **conteúdo**, e não pela posição física.

### 9.2 O que é cada identificador

| Identificador | Onde fica | Quem gera | Pode ser alterado? |
|---|---|---|---|
| **UUID** | Superbloco do filesystem | Gerado ao criar (`mkfs`) | Sim (`tune2fs -U`, `xfs_admin -U`), mas raramente é necessário |
| **LABEL** | Superbloco do filesystem | Definido por você | Sim, a qualquer momento |
| **PARTUUID** | Tabela de partições (GPT/MBR) | Criado com a partição | Sim (`sgdisk`, `fdisk`) |
| **PARTLABEL** | Tabela GPT | Definido por você | Sim |

> ⚠️ **Refazer o filesystem (`mkfs`) gera um novo UUID.** Se você reformatar uma partição, é preciso **atualizar o fstab**.

### 9.3 Consultar

```bash
sudo blkid
lsblk -f
ls -l /dev/disk/by-uuid /dev/disk/by-label
sudo tune2fs -l /dev/sdb1 | grep -Ei 'uuid|volume name'    # ext2/3/4
sudo xfs_admin -u -l /dev/sdb1                             # XFS (UUID e label)
```

### 9.4 Definir/alterar LABEL por tipo de filesystem

| Filesystem | Comando | Observação |
|---|---|---|
| ext2/3/4 | `e2label /dev/sdb1 DADOS` ou `tune2fs -L DADOS /dev/sdb1` | Até **16** caracteres |
| XFS | `xfs_admin -L DADOS /dev/sdb1` | Até **12** caracteres; **desmontado** |
| Btrfs | `btrfs filesystem label /dev/sdb1 DADOS` | |
| FAT/VFAT | `fatlabel /dev/sdb1 DADOS` (ou `dosfslabel`) | Até **11** caracteres |
| NTFS | `ntfslabel /dev/sdb1 DADOS` | |
| swap | `swaplabel -L SWAP0 /dev/sda3` | |
| Na criação | `mkfs.ext4 -L DADOS /dev/sdb1`, `mkfs.xfs -L DADOS`, `mkswap -L SWAP0` | |

### 9.5 Alterar UUID

```bash
sudo tune2fs -U random /dev/sdb1                      # ext: UUID aleatório novo
sudo tune2fs -U c0ffee00-1234-4abc-9def-0123456789ab /dev/sdb1   # ext: UUID específico
sudo xfs_admin -U generate /dev/sdb1                  # XFS (desmontado)
sudo swaplabel -U $(uuidgen) /dev/sda3                # swap
```

Útil quando você **clona** um disco (com `dd`, por exemplo) e acaba com dois filesystems com o **mesmo UUID** no mesmo computador, o que confunde o `mount` e o fstab. No XFS, a montagem de um filesystem com UUID duplicado é **recusada** a menos que se use `-o nouuid`.

### 9.6 Usando no `mount` e no fstab

```bash
sudo mount UUID=c0ffee00-... /dados
sudo mount LABEL=DADOS /dados
sudo mount PARTUUID=8d2f1c3a-01 /dados
```

```fstab
UUID=c0ffee00-1234-4abc-9def-0123456789ab  /dados  ext4  defaults  0  2
LABEL=DADOS                                /dados  ext4  defaults  0  2
```

### 9.7 UUID vs. LABEL: quando usar cada um?

| | UUID | LABEL |
|---|---|---|
| Unicidade | Praticamente garantida | **Não garantida** (dois discos podem ter o mesmo label) |
| Legibilidade | Ruim | Ótima |
| Mantém-se ao trocar o disco de lugar | ✅ | ✅ |
| Recomendação | **Servidores e fstab** | Mídias removíveis e uso pessoal |

## 10. Montagem por usuários comuns

Por padrão, **só o root** monta filesystems (porque `mount` precisa de privilégios e é binário **SUID root**). Para liberar o acesso a usuários comuns, é preciso uma linha no `/etc/fstab` com **`user`**, **`users`**, **`owner`** ou **`group`**.

### 10.1 Opções e diferenças

| Opção | Quem pode montar | Quem pode desmontar |
|---|---|---|
| `user` | Qualquer usuário | **Apenas quem montou** (e o root) |
| `users` | Qualquer usuário | **Qualquer usuário** |
| `owner` | O **dono** do dispositivo (`/dev/sdb1`) | O mesmo |
| `group` | Membros do **grupo** do dispositivo | O mesmo |

Todas elas incluem `noexec`, `nosuid` e `nodev` **implicitamente** por segurança (veja 6.2).

### 10.2 Exemplo completo

```fstab
/dev/sdb1   /media/usb    vfat      user,noauto,uid=1000,umask=022   0 0
/dev/sr0    /media/cdrom  iso9660   ro,user,noauto                   0 0
```

Uso pelo usuário comum, **sem sudo**:

```bash
$ mount /media/usb         # só o ponto de montagem! (as opções vêm do fstab)
$ ls /media/usb
$ umount /media/usb
```

**Importante:** o usuário comum **só consegue montar** *exatamente* o que está no fstab e **apenas informando o dispositivo OU o ponto de montagem**. Isto **falha**:

```bash
$ mount -t vfat /dev/sdb1 /mnt/outro
mount: only root can do that
```

### 10.3 Por que `noauto` junto com `user`?

`noauto` impede a montagem automática no boot. É o que se espera de mídia removível, que pode nem estar conectada.

### 10.4 Montagem automática no desktop (udisks2)

Nos ambientes gráficos, o **udisks2** e o gerenciador de arquivos montam mídias removíveis para o usuário logado **sem precisar do fstab**, em `/media/<usuario>/` ou `/run/media/<usuario>/`. É a razão pela qual, no dia a dia, raramente usamos `mount` para pendrives.

## 11. Swap e o fstab

Embora a **área de troca** não seja "montada", ela aparece no fstab e é gerenciada de forma análoga.

```bash
sudo mkswap /dev/sda3             # cria a área de troca (gera UUID)
sudo swapon /dev/sda3             # ativa
sudo swapon -a                    # ativa tudo que estiver no fstab como swap
sudo swapoff /dev/sda3            # desativa
swapon --show                     # lista as áreas ativas
cat /proc/swaps                   # idem, direto do kernel
free -h                           # mostra total de swap
```

Entrada no fstab:

```fstab
UUID=9b7c1e55-2a3d-4f60-8e12-77aa31c0d9be  none  swap  sw  0  0
```

- Campo 2 = `none`; campo 3 = `swap`; opção `sw` (ou `defaults`).
- Pode ser usado também um **arquivo** de swap: `/swapfile none swap sw 0 0`.
- Pode-se definir prioridade com `pri=`: `sw,pri=10`.

## 12. Unidades `.mount` e `.automount` do systemd

Em sistemas com **systemd**, **cada ponto de montagem é representado por uma unit** do tipo `.mount`.

### 12.1 De onde elas vêm?

1. **Geradas automaticamente a partir do `/etc/fstab`** pelo `systemd-fstab-generator` (ficam em `/run/systemd/generator/`, são **temporárias** e recriadas a cada `daemon-reload`/boot).
2. **Escritas manualmente** em `/etc/systemd/system/` (persistentes).

### 12.2 Regra de nomenclatura (muito cobrada!)

O **nome do arquivo** da unit deve corresponder ao **caminho do ponto de montagem**, com:

- A `/` inicial **removida**;
- Cada `/` restante substituída por `-`;
- Sufixo **`.mount`**.

| Ponto de montagem | Nome da unit |
|---|---|
| `/` | `-.mount` |
| `/home` | `home.mount` |
| `/mnt/dados` | `mnt-dados.mount` |
| `/var/lib/mysql` | `var-lib-mysql.mount` |

Para gerar o nome correto (inclusive com caracteres especiais):

```bash
systemd-escape -p --suffix=mount /var/lib/mysql
# var-lib-mysql.mount
```

> Se o nome do arquivo **não** corresponder ao `Where=`, o systemd **recusa** a unit.

### 12.3 Anatomia de uma `.mount`

`/etc/systemd/system/mnt-dados.mount`:

```ini
[Unit]
Description=Disco de dados
After=network-online.target      # exemplo; só se aplicável

[Mount]
What=/dev/disk/by-uuid/c0ffee00-1234-4abc-9def-0123456789ab
Where=/mnt/dados
Type=ext4
Options=defaults,noatime

[Install]
WantedBy=multi-user.target
```

| Diretiva | Equivalente no fstab |
|---|---|
| `What=` | Campo 1 (dispositivo) |
| `Where=` | Campo 2 (ponto de montagem), **absoluto** |
| `Type=` | Campo 3 |
| `Options=` | Campo 4 |

Não existe equivalente a `dump`/`pass` (o fsck é tratado por outras units).

Ativando:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mnt-dados.mount     # monta agora e no boot
```

### 12.4 Automount (montagem sob demanda)

Crie **também** um `.automount` com o **mesmo nome-base**:

`/etc/systemd/system/mnt-dados.automount`:

```ini
[Unit]
Description=Automount do disco de dados

[Automount]
Where=/mnt/dados
TimeoutIdleSec=300

[Install]
WantedBy=multi-user.target
```

Neste cenário você **habilita o `.automount`**, e não o `.mount`:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mnt-dados.automount
```

O filesystem só é montado no **primeiro acesso** a `/mnt/dados` e (com `TimeoutIdleSec`) é desmontado após o período ocioso.

### 12.5 Comandos úteis

```bash
systemctl list-units -t mount                  # mount units ativas
systemctl list-units -t automount
systemctl status mnt-dados.mount
sudo systemctl start  mnt-dados.mount          # monta
sudo systemctl stop   mnt-dados.mount          # desmonta
systemctl cat mnt-dados.mount                  # exibe o conteúdo da unit
systemctl show -p What,Where,Options mnt-dados.mount
journalctl -u mnt-dados.mount                  # logs
```

### 12.6 fstab vs. mount unit

| | `/etc/fstab` | Mount unit |
|---|---|---|
| Formato | Linha única, 6 campos | Arquivo INI com seções |
| Dependências finas | Limitadas (via `x-systemd.*`) | Total (`After=`, `Requires=`, etc.) |
| Compatibilidade | Todas as distribuições Linux | Só com systemd |
| Cobrado na LPIC-1? | **Sim, em profundidade** | **Conhecimento** (awareness) |

> O systemd **converte o fstab em mount units** na inicialização. Se existirem os dois para o mesmo ponto, a unit em `/etc/systemd/system/` **tem precedência**.

## 14. Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| `mount: wrong fs type, bad option, bad superblock` | Tipo errado, filesystem corrompido, falta o pacote do tipo (ex.: `ntfs-3g`) | Conferir com `blkid`/`lsblk -f`; instalar driver; rodar `fsck` desmontado |
| `mount: mount point does not exist` | Diretório de destino não foi criado | `mkdir -p /ponto` |
| `mount: special device /dev/sdX does not exist` | Dispositivo mudou de nome/ausente | Usar `UUID`/`LABEL`; `lsblk` |
| `only root can do that` | Usuário comum sem permissão no fstab | Adicionar `user` ao fstab |
| `target is busy` | Processos usando o filesystem | `fuser -vm`, `lsof`, sair do diretório, `umount -l` |
| `mount: ... already mounted or mount point busy` | Já montado, ou algo montado no ponto | `findmnt`, `umount` |
| `Read-only file system` | Montado `ro`, ou erro no disco forçou remount `ro` | `mount -o remount,rw`; verificar `dmesg` e `fsck` |
| Boot cai no **modo de emergência** | Linha do fstab com erro/dispositivo ausente | Veja o procedimento abaixo |
| Disco extra não aparece após o boot | Linha `noauto` ou fstab não recarregado | `mount -a`, `systemctl daemon-reload` |
| XFS: `Filesystem has duplicate UUID` | Clone de disco | `mount -o nouuid` ou `xfs_admin -U generate` |

### Recuperando de um fstab quebrado

No **modo de emergência** a raiz costuma estar somente-leitura:

```bash
mount -o remount,rw /           # 1. torna a raiz gravável
vi /etc/fstab                   # 2. corrija ou comente a linha com erro
systemctl daemon-reload         # 3. recarrega as units
mount -a                        # 4. teste
reboot
```

**Prevenção:** use `nofail` em discos não essenciais e `findmnt --verify` após editar.

### Ferramentas de diagnóstico

```bash
dmesg | tail                   # mensagens do kernel sobre o disco
journalctl -b -p err           # erros do boot atual
systemctl --failed             # units que falharam (inclui .mount)
```

## 15. Cheat sheet

### Comandos

```bash
lsblk -f                              # dispositivos, UUID, labels, pontos de montagem
blkid                                 # UUID/LABEL/TYPE
findmnt                               # árvore de montagens
findmnt --verify                      # valida o fstab
mount                                 # lista montados
mount DISP PONTO                      # monta
mount -t TIPO -o OPÇÕES DISP PONTO    # monta com tipo e opções
mount LABEL=X PONTO / UUID=X PONTO    # monta por label/uuid
mount -a                              # monta tudo do fstab
mount -o remount,rw PONTO             # altera opções sem desmontar
mount --bind ORIGEM DESTINO           # bind mount
mount -o loop IMAGEM.iso PONTO        # monta imagem
umount PONTO                          # desmonta
umount -l PONTO                       # lazy
fuser -vm PONTO                       # quem está usando
e2label DISP NOME                     # define label (ext)
tune2fs -L NOME DISP                  # idem
tune2fs -U random DISP                # novo UUID (ext)
xfs_admin -L NOME DISP                # label (XFS)
swapon -a / swapoff -a                # swap do fstab
systemctl daemon-reload               # recarrega fstab e units
```

### Campos do fstab

```
  1            2              3        4         5      6
dispositivo  ponto-montagem  tipo   opções    dump   pass(fsck)
                                               0/1    0/1/2
```

### Memorize

| Item | Valor |
|---|---|
| `defaults` | `rw,suid,dev,exec,auto,nouser,async` |
| `user`, `users`, `owner`, `group` | implicam `noexec,nosuid,nodev` |
| pass da raiz | `1` |
| pass dos demais | `2` |
| pass sem verificação | `0` (swap, tmpfs, rede, XFS, Btrfs) |
| `/etc/mtab` | link para `/proc/self/mounts` |
| mount unit de `/var/lib/x` | `var-lib-x.mount` |
| Diretório de montagens temporárias manuais | `/mnt` |
| Diretório de mídias removíveis | `/media` |

## 16. Pegadinhas de prova

1. **`umount`, não `unmount`.** Se uma alternativa escreve `unmount`, está errada.
2. **`mount -a` ignora entradas `noauto`.**
3. **Usuário comum só monta o que estiver no fstab** com `user`/`users`/`owner`/`group`, e deve informar **apenas o ponto de montagem (ou o dispositivo)**.
4. Com **`user`**, só **quem montou** pode desmontar; com **`users`**, **qualquer um**.
5. A **ordem** das opções importa: `user,exec` habilita exec; `exec,user` **não**.
6. **`/etc/mtab` ≠ arquivo "verdade"**: a fonte real é **`/proc/mounts`** (o kernel).
7. **UUID muda ao refazer o filesystem** (`mkfs`) → o fstab fica desatualizado.
8. O 6º campo do fstab é o **fsck pass**, e o 5º é o **dump**; não confunda a ordem.
9. **`nofail`** evita que a ausência do disco trave o boot; **`noauto`** impede a montagem automática.
10. **`remount`** altera as opções **sem desmontar**; é o método típico para `rw`/`ro` na raiz.
11. **`umount -l`** (lazy) ≠ **`umount -f`** (force, principalmente NFS).
12. **Mount unit:** `/mnt/dados` → **`mnt-dados.mount`**; o `Where=` **deve** corresponder ao nome do arquivo.
13. Para automount com systemd, **habilita-se o `.automount`**, não o `.mount`.
14. **FAT/NTFS** não têm permissões Unix: use `uid=`, `gid=`, `umask=` no `mount`.
15. **Montar sobre um diretório não vazio** não apaga os arquivos, apenas os **oculta** até desmontar.
16. `lsblk -f` e `blkid` mostram **UUID e LABEL**; `lsblk` sozinho **não** mostra UUID.
17. **swap** usa `swapon`/`swapoff`, não `mount`/`umount`, mas aparece no fstab com ponto `none`.
