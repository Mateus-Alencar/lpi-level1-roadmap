# LPIC-1 · Tópico 104.2 — Manutenção da Integridade de Sistemas de Arquivos

---

## 1. Conceitos essenciais

| Termo | O que é |
|---|---|
| **Superbloco** | Metadados do FS: tipo, tamanho, tamanho do bloco, total de inodes/blocos, **estado (clean/not clean)**, contador de montagens, última checagem. Existem **cópias (backup)** em alguns grupos de blocos |
| **Inode** | Guarda os metadados do arquivo (tipo, permissões, dono, tamanho, timestamps, nº de links, ponteiros para blocos). **NÃO guarda o nome**: o nome fica na entrada de diretório (nome → nº do inode) |
| **Bloco** | Unidade de alocação (1, 2 ou 4 KB). Um arquivo ocupa no mínimo 1 bloco |
| **Journal** | Área onde o FS anota a operação **antes** de executá-la. Após queda, o log é reexecutado (*replay*) em segundos |

- Em **ext2/3/4 o número de inodes é fixo na criação** (dá para ter espaço livre e não conseguir criar arquivos). **XFS e Btrfs** alocam inodes dinamicamente.
- **Estado do FS:** *clean* = desmontado corretamente (o `fsck` normalmente pula); *not clean* = estava montado na queda ou há erro (o `fsck` verifica).

| Sistema | Journal |
|---|---|
| ext2 | ❌ não |
| ext3 | ✅ (ext2 + journal) |
| ext4 | ✅ (extents, padrão em muitas distros) |
| XFS | ✅ só metadados (padrão RHEL/Rocky/Alma) |
| Btrfs | Copy-on-write, checksums |
| FAT/VFAT | ❌ não |

> ⚠️ Journal **não é backup** e **não elimina o `fsck`**: protege contra queda/desligamento súbito, não contra defeito físico.

## 2. Espaço livre: `df` e `du`

| | `df` | `du` |
|---|---|---|
| Pergunta | Quanto cada **sistema de arquivos** usa/tem livre? | Quanto estes **arquivos/diretórios** ocupam? |
| Fonte | Superbloco | Percorre a árvore somando |

### `df`

| Opção | Significado |
|---|---|
| `-h` / `-H` | Legível: base **1024** / base **1000** |
| `-T` | Mostra o **tipo** do FS |
| `-i` | Mostra **inodes** em vez de blocos |
| `-t tipo` / `-x tipo` | **Só** esse tipo / **exclui** esse tipo |
| `-a` | Inclui FS "dummy" (proc, sysfs...) |
| `-l` | Só FS locais |
| `--total` | Linha de total |

- `df -h /caminho` mostra **em qual partição** o caminho está.
- Em ext, **5% dos blocos são reservados ao root** → `Size ≠ Used + Avail`. Ajuste com `tune2fs -m`.

### `du`

| Opção | Significado |
|---|---|
| `-h` | Legível |
| `-s` | **Só o total** de cada argumento |
| `-a` | Inclui também **arquivos** |
| `-c` | Linha de **total geral** |
| `-d N` / `--max-depth=N` | Limita a profundidade |
| `-x` | **Não cruza** para outros FS |
| `--apparent-size` | Tamanho aparente (bytes lógicos), não o uso em disco |
| `--exclude=padrão` | Ignora arquivos |

```bash
du -sh /var/log                              # total de um diretório
du -h --max-depth=1 /var | sort -h           # quem ocupa mais (sort -h entende K/M/G)
du -ahx / 2>/dev/null | sort -rh | head      # maiores itens sem sair da partição
```

## 3. Inodes

Cada arquivo, diretório, link simbólico ou socket consome **1 inode**. Se acabam:

```
touch: cannot touch 'novo.txt': No space left on device     ← mesmo com df -h mostrando espaço livre
```

- **Detectar:** `df -i` (colunas `Inodes`, `IUsed`, `IFree`, `IUse%`).
- **Regra:** "No space left on device" com espaço livre → **rode `df -i`**.
- **Ver o inode de um arquivo:** `ls -i arquivo`, `stat arquivo`.
- **Resolver:** apagar arquivos (sessões, cache, filas); se for estrutural, **recriar** o FS com mais inodes (`mke2fs -i` / `-N`). **Não dá para aumentar** os inodes de um ext já criado.

## 4. Por que `df` e `du` divergem?

| Causa | Explicação |
|---|---|
| **Arquivo apagado mas ainda aberto** | O nome sumiu (o `du` não vê), mas os blocos só são liberados quando o processo fecha o arquivo. O `df` continua mostrando ocupado |
| Blocos reservados (5%) e metadados/journal | O `df` conta, o `du` não |
| FS montado sobre diretório que tinha arquivos | Os arquivos ficam **escondidos** sob o ponto de montagem |
| Arquivos esparsos / tamanho aparente | Tamanho lógico ≠ blocos usados |
| `du` sem permissão | Subestima o total |

**Caso clássico (cai muito):** apagou o log, o disco continua cheio.

```bash
sudo lsof +L1                          # arquivos apagados (link count 0) ainda abertos
sudo systemctl restart app             # libera o descritor e os blocos
sudo truncate -s 0 /proc/PID/fd/N      # ou truncar sem reiniciar
```

> Para esvaziar um log em uso, **não use `rm`**: use `truncate -s 0 arquivo` ou `> arquivo`.

## 5. `fsck` e `e2fsck`

`fsck` é um **front-end** que chama o verificador do tipo de FS:

```
fsck ─► fsck.ext2/3/4 (= e2fsck)    ─► fsck.vfat (= dosfsck)
     ─► fsck.xfs (não faz nada)     ─► fsck.btrfs (não faz nada)
```

`fsck -t ext4 /dev/sdb1` ≡ `fsck.ext4 /dev/sdb1` ≡ `e2fsck /dev/sdb1`

> ## ⚠️ REGRA DE OURO
> **Nunca execute `fsck` em FS montado em leitura/escrita** → risco de corrupção severa. **Desmonte antes** (`umount`). Para o `/`, veja a seção 7.

### Opções do `fsck` (front-end)

| Opção | Significado |
|---|---|
| `-t tipo` | Tipo do FS (se omitido, consulta `/etc/fstab`/`blkid`) |
| `-A` | Verifica **todos** os FS do `/etc/fstab` |
| `-R` | Com `-A`, **pula o raiz** |
| `-P` | Com `-A`, verifica em **paralelo** |
| `-N` | **Dry-run**: só mostra o que faria |
| `-M` | **Não** verifica FS montados |
| `-C` | Barra de progresso |

### Opções do `e2fsck` (muito cobradas)

| Opção | Significado |
|---|---|
| `-f` | **Força** a verificação mesmo com FS *clean* |
| `-n` | **Somente leitura**: responde "não" a tudo, **nada é alterado** (diagnóstico) |
| `-p` | **Preen**: corrige **só o trivial**, sem perguntar; se achar algo grave, **para**. Usado no boot (igual a `-a`, desencorajado) |
| `-y` | Responde **"sim" a tudo** (rápido, arriscado) |
| `-b N` | Usa o **superbloco de backup** no bloco N |
| `-B tam` | Tamanho do bloco ao procurar superbloco |
| `-c` | Roda `badblocks` e marca blocos ruins |
| `-D` | Otimiza diretórios |
| `-v` | Verbose |

> 🧠 **`-p`, `-n` e `-y` são mutuamente exclusivos.** Sem nenhum deles, o modo é interativo.

### As 5 fases (decore a ordem)

| Fase | Verifica |
|---|---|
| **1** | **Inodes, blocos e tamanhos** (blocos duplicados, fora do intervalo) |
| **2** | **Estrutura de diretórios** (entradas para inodes inválidos) |
| **3** | **Conectividade de diretórios** (órfãos vão para `lost+found`) |
| **4** | **Contagem de referências** (links; inodes não referenciados → `lost+found`) |
| **5** | **Resumo dos grupos** (bitmaps e contadores de livres) |

### Códigos de saída (soma dos valores)

| Valor | Significado |
|---|---|
| 0 | Sem erros |
| 1 | Erros **corrigidos** |
| 2 | Corrigidos e **deve reiniciar** |
| 4 | Erros **não corrigidos** |
| 8 | Erro operacional |
| 16 | Erro de uso/sintaxe |
| 32 | Cancelado pelo usuário |
| 128 | Erro em biblioteca compartilhada |

Ex.: saída **3** = 1 + 2 (corrigido e reiniciar). Consulte com `echo $?`.

### Exemplos

```bash
sudo umount /dev/sdb1
sudo e2fsck -fn /dev/sdb1      # 1º: avaliar sem alterar
sudo e2fsck -fp /dev/sdb1      # 2º: reparo automático seguro
sudo e2fsck -f  /dev/sdb1      # interativo, se o -p parou
sudo e2fsck -fy /dev/sdb1      # sim a tudo (ciente do risco)
sudo fsck -AN                  # simula a verificação de todos do fstab
```

## 6. Superblocos de backup e `lost+found`

**Sintomas de superbloco corrompido:** `bad superblock`, `Bad magic number in super-block`.

| Bloco do FS | Backups do superbloco |
|---|---|
| **1 KB** | **8193**, 24577, 40961, 57345... |
| **4 KB** | **32768**, 98304, 163840, 229376... |

```bash
sudo dumpe2fs /dev/sdb1 | grep -i superblock   # lista os backups (se o primário ainda lê)
sudo mke2fs -n /dev/sdb1                       # dry-run: mostra onde ficariam (mesmos parâmetros da criação)
sudo e2fsck -b 32768 /dev/sdb1                 # repara usando o backup (regrava o primário)
sudo e2fsck -b 8193 -B 1024 /dev/sdb1          # informando o tamanho do bloco
```

> ⚠️ `mke2fs -n` só **simula**. **Sem `-n`, o `mke2fs` recria o FS e apaga tudo.**

### `lost+found`

- Existe na **raiz de cada FS ext** (criado pelo `mke2fs`).
- Guarda o que o `e2fsck` recupera **sem nome** (inodes órfãos), nomeado pelo **número do inode**: `#12345`.
- Identificar: `file '#12345'`, `stat`, `head`; depois renomear com `mv`.
- Tem blocos **pré-alocados** para o `e2fsck` gravar mesmo com o FS cheio. **Não apague**; se apagou, o `e2fsck` ou `mklost+found` recria.
- Em XFS, o `xfs_repair` cria `lost+found` **só se necessário**.

## 7. Verificação na inicialização

### `/etc/fstab` — 6 campos

```
# dispositivo        ponto   tipo   opções    dump   pass
UUID=...             /       ext4   defaults   0      1
UUID=...             /dados  xfs    defaults   0      0
```

| 6º campo (`pass`) | Significado |
|---|---|
| **0** | **Não verifica** (XFS, Btrfs, tmpfs, NFS, swap) |
| **1** | Verifica **primeiro**; **só o `/`** |
| **2** | Verifica depois do raiz; demais FS |

Mesmo número em **discos diferentes** → verificação em **paralelo**. 5º campo (`dump`): `0` ignora no backup com `dump`.

### Quando a verificação roda no boot (se `pass ≠ 0`)

1. FS marcado como *not clean*; **ou**
2. **Contador de montagens** atingiu o máximo (`tune2fs -c`); **ou**
3. **Intervalo de tempo** expirou (`tune2fs -i`); **ou**
4. Verificação **forçada**.

Com **systemd**, quem executa é o `systemd-fsck@.service`. Se o `fsck -p` achar algo grave → **modo de emergência** (pede senha do root).

### Verificar o `/` (não dá para desmontar em execução)

| Método | Como |
|---|---|
| Forçar no próximo boot (systemd) | Parâmetros do kernel: `fsck.mode=force` (+ `fsck.repair=yes` ou `preen`) |
| Forçar no próximo boot (SysV legado) | `touch /forcefsck` ou `shutdown -rF now` |
| Modo de recuperação/resgate | Boot em *rescue/single* com `/` somente leitura |
| Live CD/USB | `fsck` no dispositivo do `/` desmontado |
| Remontar ro | `mount -o remount,ro /` e `e2fsck -fn` (só análise) |

Parâmetros: `fsck.mode=auto|force|skip` · `fsck.repair=preen|yes|no`.

## 8. `tune2fs`, `dumpe2fs` e `debugfs`

### `tune2fs` — ajusta/lista parâmetros de ext2/3/4

| Opção | Efeito |
|---|---|
| `-l` | **Lista** o superbloco |
| `-c N` | **Máximo de montagens** antes do `fsck` (`0` ou `-1` desativa) |
| `-C N` | Define o **contador atual** de montagens |
| `-i intervalo` | **Intervalo de tempo** entre verificações (`d`, `w`, `m`; `0` desativa) |
| `-e ação` | Comportamento em erro: `continue`, `remount-ro`, `panic` |
| `-m %` / `-r N` | Reserva do root em **percentual** / em **nº de blocos** (padrão 5%) |
| `-L rótulo` / `-U UUID` | Altera **label** / **UUID** |
| `-j` | **Adiciona journal** (ext2 → ext3) |
| `-O feature` | Liga/desliga features (`^has_journal` remove) |

```bash
sudo tune2fs -c 0 -i 0 /dev/sdb1         # desativa checagens periódicas
sudo tune2fs -c 30 -i 3m /dev/sdb1       # a cada 30 montagens ou 3 meses
sudo tune2fs -e remount-ro /dev/sdb1     # em erro, remonta somente leitura
sudo tune2fs -m 1 /dev/sdb1              # reserva 1% (volumes de dados grandes)
sudo tune2fs -j /dev/sdb1                # ext2 → ext3
```

Campos úteis do `tune2fs -l`: *Filesystem state*, *Errors behavior*, *Mount count*, *Maximum mount count*, *Last checked*, *Check interval*, *Reserved block count*.

**`errors=`:** `continue` (ignora) · `remount-ro` (**remonta somente leitura**, evita agravar) · `panic` (kernel panic, útil em clusters).
Sintoma clássico: aplicação reclama **"Read-only file system"** → o kernel detectou erro e remontou ro. Veja `dmesg` e rode o `fsck` com o FS desmontado.

### `dumpe2fs` — mostra superbloco e grupos (somente leitura)

| Opção | Efeito |
|---|---|
| (sem opção) | Superbloco **+ cada grupo de blocos** (inclui backups do superbloco) |
| `-h` | **Só o cabeçalho** (≈ `tune2fs -l`) |
| `-b` | Lista **blocos defeituosos** |

`dumpe2fs -h` e `tune2fs -l` **listam** o superbloco; **só o `tune2fs` altera**.

### `debugfs` — depurador interativo de ext2/3/4

- Abre **somente leitura** por padrão; **`-w`** abre para escrita (perigoso); `-R "comando"` executa um comando e sai.
- Comandos: `stat` (inode), `ls`, `ncheck inode` (inode → nome), `icheck bloco` (bloco → inode), `dump arq saída` (copia do FS), `lsdel`/`undel` (recuperar apagados, **só ext2**), `logdump` (journal), `quit`.
- Em **ext3/ext4**, a recuperação de apagados é praticamente inviável (ponteiros zerados). A melhor recuperação é o **backup**.

## 9. `mke2fs` (o que importa aqui)

`mkfs.ext4 /dev/sdb1` ≡ `mke2fs -t ext4 /dev/sdb1` ≡ `mkfs -t ext4 /dev/sdb1`

| Opção | Efeito |
|---|---|
| `-t tipo` | ext2, ext3 ou ext4 |
| `-j` | Com **journal** (ext3) |
| `-b tam` | **Tamanho do bloco** |
| `-i bytes` | **Bytes por inode**: **menor valor → mais inodes** |
| `-N num` | **Número exato** de inodes |
| `-m %` | % reservado ao root |
| `-L` / `-U` | Label / UUID |
| `-c` | Procura bad blocks antes de formatar |
| **`-n`** | **Dry-run**: não grava nada; mostra, inclusive, onde ficariam os **superblocos de backup** |

Muitos arquivos pequenos → `-i 4096` (mais inodes). Poucos arquivos gigantes → `-T largefile4` (menos inodes, mais espaço útil).

## 10. XFS

- Journaling só de **metadados**; após queda, o **log é reexecutado ao montar**.
- **`fsck.xfs` existe, mas não faz nada** → use **`pass = 0`** no fstab.
- Verificar/reparar: **`xfs_repair`** com o FS **desmontado**.
- Pode ser **aumentado** (`xfs_growfs`), **não reduzido**.

| Ferramenta | Função |
|---|---|
| **`xfs_repair`** | Verifica e repara (**desmontado**). `-n` só verifica; **`-L` zera o log** (último recurso) |
| **`xfs_db`** | Depurador (≈ `debugfs`); `-r` somente leitura |
| **`xfs_fsr`** | **Desfragmenta** (pode rodar montado) |
| **`xfs_info`** | Mostra a **geometria** (montado) |
| `xfs_admin` | Altera label (`-L`) e UUID (`-U`) |
| `xfs_growfs` | **Expande** o FS (montado) |
| `xfs_metadump` | Exporta metadados para análise |
| `xfs_freeze` | Congela/descongela I/O (`-f` / `-u`) |
| `xfs_check` | **Obsoleto** → use `xfs_repair -n` |

```bash
sudo umount /dados
sudo xfs_repair -n /dev/sdb1     # só verifica
sudo xfs_repair /dev/sdb1        # repara
```

**Log sujo:** o `xfs_repair` recusa e pede para reexecutar o log. Ordem correta:
1. **Montar e desmontar** (`mount` + `umount`) para reproduzir o log;
2. Rodar `xfs_repair` de novo;
3. **Só se não montar**: `xfs_repair -L` (zera o log, **pode perder as últimas alterações**).

## 11. Outros FS e como identificar o tipo

| Tipo | Verificar/reparar |
|---|---|
| ext2/3/4 | `fsck` / `e2fsck` |
| XFS | `xfs_repair` |
| Btrfs | `btrfs check` (desmontado; `--repair` é perigoso) · `btrfs scrub start` (montado, verifica checksums) |
| FAT/VFAT | `fsck.vfat` / `dosfsck` (`-n` só verifica, `-a` repara automático, `-r` interativo) |

- Btrfs: `df` engana → use `btrfs filesystem usage`. FAT não tem journal.
- **Identificar o tipo:** `lsblk -f` · `blkid /dev/sdb1` · `findmnt /dados` · `file -s /dev/sdb1`.

## 12. Sinais de problema físico

Corrupção pode ser **sintoma** de disco falhando; reparar o FS sem tratar a causa não resolve.

```bash
dmesg -T | grep -Ei 'error|ext4|xfs|i/o'
journalctl -k -p err
sudo smartctl -H /dev/sda        # saúde SMART (pacote smartmontools)
sudo smartctl -a /dev/sda        # atributos (setores realocados/pendentes crescentes = disco ruim)
sudo badblocks -sv /dev/sdb1     # leitura, não destrutivo
sudo badblocks -wsv /dev/sdb1    # ⚠ DESTRUTIVO (apaga dados)
```

Em ext, o mais prático é `e2fsck -c` (roda `badblocks` e registra os blocos ruins).
Alertas no log: `EXT4-fs error`, `I/O error, dev sdb`, `Metadata corruption detected`, `Remounting filesystem read-only`.

## 13. Fluxos práticos

**A — Verificar partição de dados (ext4)**

```bash
sudo fuser -vm /dados            # quem está usando?
sudo umount /dados
sudo e2fsck -fn /dev/sdb1        # avaliar
sudo e2fsck -fp /dev/sdb1        # reparar (se parar → e2fsck -f interativo)
sudo e2fsck -f /dev/sdb1; echo $?  # repetir até sair com 0
sudo mount /dados
ls -l /dados/lost+found          # revisar o recuperado
```

**B — Superbloco corrompido:** `dumpe2fs | grep -i superblock` (ou `mke2fs -n`) → `e2fsck -b 32768 /dev/sdb1` → montar.

**C — Raiz com problema:** GRUB (tecla `e`) → adicionar `fsck.mode=force fsck.repair=yes` → `Ctrl+X`; ou live USB → `e2fsck -f /dev/sda2`.

**D — "No space left on device":**

```
df -h  → blocos cheios?  → du -ahx / | sort -rh | head ; se df ≫ du → lsof +L1
df -i  → inodes cheios?  → achar o diretório com milhões de arquivos e limpar
```

**E — Servidor parou no *emergency mode* após queda:** senha do root → `journalctl -xb` → `e2fsck -f /dev/...` (avalie com `-n` antes de `-y`) → `reboot`.

**F — Nunca checar disco no boot:** `tune2fs -c 0 -i 0 /dev/sdX` (contrapartida: erros silenciosos; combine com monitoramento).

## 14. Pegadinhas de prova

1. **`fsck` em FS montado**: nunca em leitura/escrita.
2. **`-p`/`-a`** = automático seguro · **`-y`** = sim a tudo · **`-n`** = não altera nada · exclusivos entre si.
3. **Sem `-f`**, FS *clean* é **pulado**.
4. **`mke2fs -n`** = dry-run; sem `-n` **apaga tudo**.
5. **`df` ≠ `du`**: arquivo apagado e aberto, reserva de 5%, metadados.
6. **"No space left" com espaço livre** → `df -i`.
7. **Inode não guarda o nome.**
8. **`lost+found`**: itens nomeados `#inode`.
9. **XFS não usa `fsck`** → `xfs_repair` desmontado; **`-L`** só como último recurso, depois de tentar montar/desmontar.
10. **Backups do superbloco**: **8193** (bloco 1 KB) e **32768** (bloco 4 KB).
11. **`fstab` 6º campo**: `1` só `/`, `2` demais, `0` sem checagem.
12. **`tune2fs -c 0 -i 0`** desativa checagens periódicas; **`-c`** = montagens, **`-i`** = tempo.
13. **`tune2fs -l` ≈ `dumpe2fs -h`**; só o `tune2fs` altera.
14. **`debugfs`** abre em somente leitura; **`-w`** para escrever.
15. **`df -h` (1024) vs `df -H` (1000)**; **`du -s`** total, **`-x`** não cruza FS, **`-d N`** profundidade.
16. **Inodes em ext são fixos** na criação; XFS/Btrfs são dinâmicos.
17. **ext2 não tem journal**; ext3 = ext2 + journal.
18. **Journal não substitui o `fsck`** nem corrige defeito físico.

#### Ex.5
Observe a linha do /etc/fstab:

UUID=3f2a9c1e-7b4d-4c8a-9e21-5d6f0a1b2c3d  /dados  ext4  defaults  0  2

Qual afirmação sobre os dois últimos campos (0 e 2) está correta?

A) 0 desativa o backup pelo dump e 2 faz o fsck verificar o sistema de arquivos depois do raiz (/).  
B) 0 faz o fsck verificar este sistema primeiro e 2 faz o dump rodar duas vezes por semana.  
C) 0 e 2 são opções de montagem que definem leitura e escrita.  
D) 2 faz o fsck verificar este sistema antes do raiz (/).  
E) 0 indica que o sistema nunca será montado e 2 que será montado duas vezes.  

Resposta: A 
#### Ex.6

#### Ex.7

#### Ex.8

B) Apenas o sistema de arquivos raiz (/) deve ter pass igual a 1.

#### Ex.9
Digite o comando completo para definir o percentual de blocos reservados ao superusuário do ext4 em /dev/sdb1 como 2%.  

Resposta: tune2fs -m 2 /dev/sdb1  
#### Ex.10
Um servidor apresenta o erro “No space left on device” ao criar arquivos. O comando df -h mostra que o sistema de arquivos tem 40% de espaço livre. Qual comando ajuda a confirmar a causa mais provável do problema?

A) du -sh /  
B) df -i  
C) fsck -n /dev/sda1  
D) tune2fs -c 0 /dev/sda1  
E) df -T  

Resposta: B
