## 1. Objetivos oficiais e o que cai na prova

O LPI espera que você saiba:

- **Criar** links (hard e simbólicos).
- **Identificar** se um arquivo é hard link e/ou link simbólico.
- Entender a diferença entre **copiar** e **linkar** arquivos.
- Usar links para apoiar tarefas de administração do sistema.

**Arquivos, termos e utilitários citados no objetivo:**

| Item | Para que serve |
|------|----------------|
| `ln` | Cria links (hard por padrão, simbólico com `-s`) |
| `ls` | Lista arquivos; `-l` mostra tipo `l` e o destino; `-i` mostra inode |
| *hard link* | Outro nome para o **mesmo** inode |
| *soft link / symlink* | Arquivo especial que **guarda um caminho** para outro arquivo |

> 💡 Na prova, 80% das questões giram em torno de: **ordem dos argumentos do `ln`**, **diferenças de comportamento ao apagar/mover o original**, **limitações do hard link** (outra partição, diretórios) e **como identificar** cada tipo com `ls -l` / `ls -i`.

## 2. Pré-requisito: como o Linux guarda um arquivo (inodes)

Para entender links, você precisa separar duas coisas que no dia a dia parecem uma só: **o nome** e **o arquivo de verdade**.

```
 Diretório (/home/ana)                  Tabela de inodes                 Blocos de dados
┌─────────────────────────┐          ┌──────────────────────┐          ┌───────────────┐
│ nome        │  nº inode │          │ inode 131090         │          │               │
├─────────────┼───────────┤          │  • tipo / permissões │          │  "conteúdo    │
│ relatorio   │  131090 ──┼────────► │  • dono / grupo      │ ───────► │   do arquivo" │
│ ...         │           │          │  • tamanho           │          │               │
└─────────────────────────┘          │  • timestamps        │          └───────────────┘
                                     │  • contador de links │
                                     │  • ponteiros p/ dados│
                                     └──────────────────────┘
```

Pontos-chave:

- Um **diretório** é, na prática, uma tabela de pares **`nome → número do inode`**.
- O **inode** guarda *tudo* sobre o arquivo (dono, permissões, tamanho, datas, onde estão os dados) — **exceto o nome**.
- O inode possui um **contador de links** (*link count*): quantos nomes (entradas de diretório) apontam para ele.
- O número do inode é único **apenas dentro de um sistema de arquivos**. Dois arquivos em partições diferentes podem ter o mesmo número de inode sem relação nenhuma entre si.

### O que `rm` realmente faz

`rm` chama a operação **`unlink`**: remove **um nome** e decrementa o contador de links. Os dados só são liberados quando:

1. o contador chega a **0**, **e**
2. nenhum processo mantém o arquivo aberto.

Essa é a chave para entender tudo o que vem a seguir.

## 3. Hard links

### 3.1 Conceito

Um **hard link** é simplesmente **um segundo (terceiro, quarto…) nome para o mesmo inode**.

```
 relatorio.txt ──┐
                 ├──► inode 131090 ──► dados
 backup.txt   ───┘        (Links: 2)
```

- **Não existe "original" e "cópia".** Os dois nomes são perfeitamente equivalentes e indistinguíveis.
- Como são o **mesmo inode**, compartilham **tudo**: conteúdo, dono, grupo, permissões, tamanho e timestamps.
- Alterar o conteúdo, `chmod`, `chown` ou `touch` por qualquer um dos nomes reflete em todos.

### 3.2 Criando

```bash
ln ARQUIVO_EXISTENTE NOVO_NOME
#  └── origem (alvo) ─┘ └─ nome do link ─┘
```

```bash
$ echo "dados importantes" > relatorio.txt
$ ln relatorio.txt backup.txt
$ ls -li
131090 -rw-r--r-- 2 ana ana 18 out 22 10:00 backup.txt
131090 -rw-r--r-- 2 ana ana 18 out 22 10:00 relatorio.txt
  ↑                ↑
  mesmo inode      contador de links = 2
```

> 🧠 **Mnemônico da ordem dos argumentos:** `ln` segue a mesma lógica do `cp`: **`ln ORIGEM DESTINO`** — primeiro o que **já existe**, depois o **nome novo**.

### 3.3 Como identificar hard links

| Método | O que olhar |
|--------|-------------|
| `ls -l` | **Segunda coluna** (contador de links) maior que 1 num arquivo regular |
| `ls -i` | **Mesmo número de inode** em nomes diferentes |
| `stat arquivo` | Campo `Links:` e `Inode:` |
| `find . -samefile arquivo` | Lista todos os nomes que apontam para o mesmo inode |
| `find / -xdev -inum 131090` | Procura por número de inode (use `-xdev` pois inodes se repetem entre filesystems) |
| `find . -type f -links +1` | Arquivos regulares com mais de um nome |

```bash
$ stat relatorio.txt
  File: relatorio.txt
  Size: 18          Blocks: 8          IO Block: 4096   regular file
Device: 801h/2049d  Inode: 131090      Links: 2
Access: (0644/-rw-r--r--)  Uid: ( 1000/ ana)   Gid: ( 1000/ ana)
```

> ⚠️ O `ls -l` **não mostra** "esse é um hard link" nem aponta para onde. A única pista é o contador > 1. Para descobrir **os outros nomes**, use `find -samefile` ou `find -inum`.

### 3.4 Comportamento dos hard links

| Ação | Resultado |
|------|-----------|
| Apagar um dos nomes (`rm backup.txt`) | O outro continua intacto; contador cai para 1 |
| Apagar todos os nomes | Contador = 0 → dados liberados |
| **Mover/renomear** um dos nomes (mesmo filesystem) | Só muda a entrada de diretório; os outros nomes não são afetados |
| Editar o conteúdo por um nome | Aparece em todos |
| `chmod` / `chown` em um nome | Vale para todos (é o mesmo inode) |
| Espaço em disco | **Não duplica** — só uma cópia dos dados existe |

### 3.5 Limitações (cobradas na prova!)

1. **Não atravessa sistemas de arquivos.** O link e o arquivo precisam estar **na mesma partição/filesystem** (porque o inode só tem sentido dentro dele).
   ```
   ln: failed to create hard link '/mnt/dados/x' => '/home/ana/x': Invalid cross-device link
   ```
2. **Não é permitido para diretórios** (nem para o root), para evitar loops na árvore.
   ```
   ln: /etc: hard link not allowed for directory
   ```
3. O alvo **precisa existir** no momento da criação.

### 3.6 O caso especial dos diretórios

Os diretórios *têm* um contador de links, mas é o sistema quem gerencia:

- Diretório vazio: **Links: 2** → o nome dele no pai + o `.` dentro dele.
- Cada subdiretório criado **soma 1** (por causa do `..` do filho).

```bash
$ mkdir -p teste/{a,b,c}
$ ls -ld teste
drwxr-xr-x 5 ana ana 4096 out 22 10:05 teste     # 2 + 3 subdiretórios = 5
```

### 3.7 Armadilha: alguns editores "quebram" o hard link

Programas que salvam gravando um **arquivo novo e depois renomeando** (muitos editores, `sed -i`, etc.) criam **um novo inode**. O nome editado passa a apontar para o novo inode e o hard link deixa de existir.

```bash
$ ln a.txt b.txt
$ sed -i 's/x/y/' a.txt     # sed -i cria arquivo temporário e renomeia
$ ls -li a.txt b.txt         # inodes agora são DIFERENTES
```

## 4. Links simbólicos (symlinks / soft links)

### 4.1 Conceito

Um **link simbólico** é um **arquivo especial com inode próprio** cujo conteúdo é **um caminho (texto)** para outro arquivo ou diretório. Funciona como um "atalho" resolvido pelo kernel a cada acesso.

```
 atalho ──► inode 200 (tipo "l")  ── conteúdo: "/dados/relatorio.txt"
                                              │
                                              ▼ (kernel resolve o caminho)
            relatorio.txt ──► inode 131090 ──► dados
```

- Tem **inode diferente** do alvo.
- O **tamanho** do symlink = **número de caracteres do caminho** que ele guarda.
- Se o alvo for apagado/movido, o link **continua existindo**, mas fica **quebrado** (*dangling / broken link*).

### 4.2 Criando

```bash
ln -s ALVO NOME_DO_LINK
#     └ para onde aponta ┘ └ nome do atalho ┘
```

```bash
$ ln -s /etc/hosts meuhosts
$ ls -l meuhosts
lrwxrwxrwx 1 ana ana 10 out 22 10:10 meuhosts -> /etc/hosts
↑                    ↑                 ↑
tipo "l"             tamanho = 10      destino exibido após "->"
                     (len("/etc/hosts"))
```

Atalhos de uso do `ln -s`:

```bash
ln -s /etc/hosts .              # cria ./hosts  (nome = basename do alvo)
ln -s /var/log/nginx ~/logs     # link para um diretório
ln -s /opt/app-2.0 /opt/app     # "versão atual" apontando para a versão em uso
```

### 4.3 Caminho absoluto × relativo (a pegadinha clássica)

| Tipo | Exemplo | Quando usar |
|------|---------|-------------|
| **Absoluto** | `ln -s /srv/dados/arq /home/ana/arq` | Link que não deve depender de onde ele está |
| **Relativo** | `ln -s ../dados/arq /home/ana/arq` | Árvores que podem ser movidas/montadas em outro lugar (ex.: pacotes, chroot, containers) |

> 🔑 **Regra de ouro:** um alvo **relativo é interpretado a partir do diretório onde o LINK está**, e **não** do diretório onde você digitou o comando.

```bash
$ mkdir -p /tmp/a/b && echo oi > /tmp/a/arq
$ cd /tmp
$ ln -s arq a/b/link        # ERRADO: resolve para /tmp/a/b/arq (não existe)
$ cat a/b/link
cat: a/b/link: No such file or directory

$ ln -sf ../arq a/b/link    # CERTO: a partir de /tmp/a/b, "../arq" = /tmp/a/arq
$ cat a/b/link
oi
```

O GNU `ln` ajuda com **`-r` (`--relative`)**: você passa os caminhos normalmente e ele calcula o alvo relativo.

```bash
ln -sr /tmp/a/arq /tmp/a/b/link
```

### 4.4 Como identificar links simbólicos

| Método | Resultado |
|--------|-----------|
| `ls -l` | Primeiro caractere **`l`** e a seta `nome -> alvo` |
| `ls -F` | Sufixo `@` no nome (`link@`) |
| `file link` | `symbolic link to /caminho/alvo` (ou `broken symbolic link`) |
| `readlink link` | Mostra o texto guardado no link |
| `readlink -f link` / `realpath link` | Caminho **final canônico** (resolve toda a cadeia) |
| `find . -type l` | Lista todos os symlinks |
| `find . -xtype l` | Lista **só os symlinks quebrados** |
| `find . -lname '*padrão*'` | Symlinks cujo alvo casa com o padrão |
| `namei -l /caminho/link` | Mostra cada componente do caminho, incluindo permissões e expansão de links |

```bash
$ ls -l /etc/localtime
lrwxrwxrwx 1 root root 38 jan  3 2025 /etc/localtime -> /usr/share/zoneinfo/America/Sao_Paulo
```

### 4.5 Links quebrados (dangling)

```bash
$ ln -s /nao/existe quebrado
$ ls -l quebrado
lrwxrwxrwx 1 ana ana 11 out 22 10:12 quebrado -> /nao/existe   # (muitos terminais mostram em vermelho)
$ cat quebrado
cat: quebrado: No such file or directory
```

Observações:

- **É possível criar** um symlink para algo que não existe (diferente do hard link).
- Se o alvo for **recriado** no mesmo caminho, o link "volta a funcionar" sozinho.
- Cadeias circulares geram o erro `Too many levels of symbolic links` (o kernel Linux limita a ~40 níveis).

### 4.6 Links para diretórios

Symlinks **podem** apontar para diretórios (hard links não):

```bash
$ ln -s /var/www/html ~/site
$ cd ~/site          # o shell entra, mas "pwd" mostra o caminho lógico
$ pwd                # /home/ana/site
$ pwd -P             # /var/www/html   (caminho físico, sem links)
```

- `cd -P` segue o caminho físico; `cd -L` (padrão) mantém o caminho lógico.
- `ls -l link/` (com barra no final) lista o **conteúdo** do diretório apontado; `ls -ld link` mostra o próprio link.
- Para **remover** um symlink de diretório, use `rm link` (**sem barra no final**) — nunca `rm -rf link/`, que pode atuar sobre o conteúdo do alvo.

### 4.7 Permissões de um symlink

- O `ls -l` mostra sempre **`lrwxrwxrwx` (777)** — é cosmético.
- O acesso real é decidido pelas **permissões do alvo** (e dos diretórios do caminho).
- `chmod` em um symlink **altera o alvo** (no Linux).
- `chown` em um symlink também altera o alvo por padrão; use **`chown -h`** para alterar o dono **do próprio link**.
- Para **criar ou remover** o link, o que importa é a permissão de escrita no **diretório onde o link está** (e o *sticky bit*, se houver).

### 4.8 Alterando e substituindo links

Um symlink não é "editado": ele é **recriado**.

```bash
ln -sf novo_alvo meu_link       # -f: remove o link existente e cria de novo
```

⚠️ **Cuidado quando `meu_link` já aponta para um diretório:** o `ln` "entra" no diretório e cria o novo link **dentro dele**. Use **`-n`** (`--no-dereference`, ou `-T`) para tratar `meu_link` como arquivo normal e **substituí-lo**:

```bash
ln -s /opt/app-1.0 /opt/app          # app -> app-1.0
ln -sf /opt/app-2.0 /opt/app         # ERRADO: cria /opt/app-1.0/app-2.0 (dentro do dir)
ln -sfn /opt/app-2.0 /opt/app        # CERTO: app -> app-2.0
```

Esse padrão (`ln -sfn`) é a base de *deploys* tipo "release atual".

Para remover:

```bash
rm meu_link          # ou:  unlink meu_link
```

## 5. Comparativo: hard link × link simbólico

| Característica | Hard link | Link simbólico |
|----------------|-----------|----------------|
| Comando | `ln alvo link` | `ln -s alvo link` |
| Inode | **Mesmo** do alvo | **Próprio** (tipo `l`) |
| O que contém | Nada próprio (é só um nome) | O **caminho** (texto) do alvo |
| Atravessa filesystems/partições | ❌ Não | ✅ Sim |
| Pode apontar para diretórios | ❌ Não | ✅ Sim |
| Alvo precisa existir ao criar | ✅ Sim | ❌ Não (pode ficar quebrado) |
| Apagar o "original" | Link **continua funcionando** | Link **quebra** |
| Mover/renomear o "original" | Link **continua funcionando** | Link **quebra** (se o caminho guardado mudou) |
| Permissões / dono | Idênticos ao alvo (mesmo inode) | `lrwxrwxrwx`; vale o alvo |
| Tamanho em `ls -l` | Igual ao do arquivo | Nº de caracteres do caminho |
| Contador de links (2ª coluna) | Aumenta no alvo | **Não** aumenta no alvo |
| Distinguir "original" de "link" | Impossível | Fácil (`ls -l`, `readlink`) |
| Usa espaço extra | Praticamente nenhum | Mínimo (inode + caminho) |
| Pode apontar para outro symlink (cadeia) | — | ✅ Sim |

**Resumo mental:**

- Hard link = *"outro nome para a mesma coisa"*.
- Symlink = *"um bilhete dizendo onde a coisa está"*.

## 6. O comando `ln` em detalhe

### Sintaxe

```bash
ln [OPÇÕES] ALVO                    # cria link com o mesmo nome no diretório atual
ln [OPÇÕES] ALVO NOME_DO_LINK       # forma mais comum
ln [OPÇÕES] ALVO... DIRETÓRIO       # vários alvos dentro de um diretório
ln [OPÇÕES] -t DIRETÓRIO ALVO...    # idem, com o diretório explícito
```

> Se o último argumento for um **diretório existente**, o link é criado **dentro dele**, com o nome base do alvo.

### Opções principais

| Opção | Significado |
|-------|-------------|
| *(nenhuma)* | Cria **hard link** |
| `-s`, `--symbolic` | Cria **link simbólico** |
| `-f`, `--force` | Remove destinos já existentes sem perguntar |
| `-i`, `--interactive` | Pergunta antes de sobrescrever |
| `-n`, `--no-dereference` | Trata o destino que é symlink para diretório como arquivo comum (evita criar link "dentro" do diretório) |
| `-T`, `--no-target-directory` | Trata sempre o último argumento como nome do link, nunca como diretório |
| `-r`, `--relative` | Com `-s`, calcula o alvo **relativo** automaticamente |
| `-v`, `--verbose` | Mostra o que foi feito |
| `-b`, `--backup` | Faz backup do destino existente (sufixo `~`); controlável com `--backup=numbered` e `-S sufixo` |
| `-t DIR` | Diretório onde os links serão criados |
| `-L` / `-P` | Ao criar hard link de um alvo que é symlink: seguir (`-L`) ou linkar o próprio symlink (`-P`) |
| `-d`, `-F` | "Tentam" hard link de diretório (só para root; **falha** no Linux moderno) |

Comando relacionado: **`unlink arquivo`** remove exatamente um nome (equivale a `rm` de um único arquivo).

### Exemplos

```bash
ln dados.csv dados_hard.csv                 # hard link
ln -s /var/log/syslog ~/syslog              # symlink absoluto
ln -sv ../conf/app.conf app.conf            # symlink relativo, verboso
ln -sfn /srv/releases/2026-10-22 /srv/current
ln -s /bin/bash /usr/local/bin/sh_alt       # link para binário
ln -t /tmp/links a.txt b.txt c.txt          # vários hard links em /tmp/links
```

## 7. Ferramentas para identificar e investigar links

### `ls`

| Comando | Uso |
|---------|-----|
| `ls -l` | Tipo (`-`, `d`, `l`), contador de links, destino do symlink |
| `ls -li` | Inclui o número do inode |
| `ls -lL link` | **Segue** o link: mostra as informações do alvo |
| `ls -ld link` | Informações do link/diretório em si (sem listar conteúdo) |
| `ls -F` | `@` = symlink, `/` = diretório, `*` = executável |

### `stat`

```bash
stat arquivo            # inode, links, permissões, datas
stat -L link            # segue o symlink e mostra o alvo
stat -c '%i %h %N' *    # inode, contador de links e nome formatado (%N mostra o alvo do symlink)
```

### `readlink` / `realpath`

```bash
readlink /etc/localtime         # só o próximo nível: /usr/share/zoneinfo/America/Sao_Paulo
readlink -f /usr/bin/python     # resolve TODA a cadeia até o arquivo final (mesmo se o último não existir)
realpath /usr/bin/python        # equivalente moderno
```

### `file`

```bash
$ file /bin/sh
/bin/sh: symbolic link to dash
```

### `find`

```bash
find /etc -type l                   # todos os symlinks
find /etc -xtype l                  # symlinks QUEBRADOS
find /etc -type l -lname '/usr/*'   # symlinks cujo alvo começa com /usr/
find . -type f -links +1            # arquivos com mais de um hard link
find . -samefile arq.txt            # todos os nomes do mesmo inode
find / -xdev -inum 131090           # busca por inode (restrito a um filesystem)
find -L . -type l                   # método antigo para achar quebrados
```

### `namei`

```bash
$ namei -l /usr/bin/editor
f: /usr/bin/editor
dr-xr-xr-x root root /
drwxr-xr-x root root usr
drwxr-xr-x root root bin
lrwxrwxrwx root root editor -> /etc/alternatives/editor
  lrwxrwxrwx root root alternatives -> ...
```

Excelente para depurar "por que não consigo acessar isso?" — mostra permissões de **cada componente** do caminho e onde os links são expandidos.

## 8. Copiar × mover × apagar × arquivar: o que acontece com os links

### 8.1 Copiar vs. linkar (objetivo do exame)

| | **Cópia** (`cp`) | **Hard link** | **Symlink** |
|--|------------------|---------------|-------------|
| Inode | Novo | Mesmo | Novo (tipo link) |
| Dados duplicados | ✅ Sim | ❌ Não | ❌ Não |
| Alteração em um reflete no outro | ❌ Não | ✅ Sim | ✅ Sim (lê o alvo) |
| Ocupa espaço extra | Igual ao original | ~0 | ~0 |
| Sobrevive ao apagar o original | ✅ | ✅ | ❌ |

### 8.2 `cp` e links

Por padrão, o GNU `cp` **segue** symlinks quando **não** está em modo recursivo e **não segue** (copia o link em si) em modo recursivo (`-R`). Você controla isso explicitamente:

| Opção do `cp` | Efeito |
|---------------|--------|
| `-L`, `--dereference` | **Sempre segue** symlinks (copia o conteúdo do alvo) |
| `-P`, `--no-dereference` | **Nunca segue**; copia o próprio symlink |
| `-H` | Segue apenas symlinks informados na linha de comando |
| `-d` | Igual a `-P` + preserva hard links entre os arquivos copiados |
| `-a` | `-dR --preserve=all`: cópia fiel (links preservados como links) |
| `-l`, `--link` | **Cria hard links** em vez de copiar |
| `-s`, `--symbolic-link` | **Cria symlinks** em vez de copiar |

```bash
cp -al /dados /dados_snapshot    # "snapshot" instantâneo usando hard links (não duplica dados)
```

### 8.3 `mv`

- **Dentro do mesmo filesystem**: só renomeia a entrada de diretório; o inode (e os hard links) permanece.
- **Entre filesystems**: o `mv` copia e apaga a origem → o resultado é um **novo inode**, e o **vínculo de hard links com outros nomes se perde**.
- Mover um **symlink relativo** para outro diretório pode **quebrá-lo**, pois o caminho guardado passa a ser interpretado a partir de um novo local.

### 8.4 `rm`

- `rm link_simbolico` remove **apenas o link**; o alvo permanece.
- `rm alvo` **não** remove symlinks que apontam para ele → eles ficam quebrados.
- `rm hardlink` remove só aquele nome; os dados persistem enquanto restar algum.

### 8.5 `tar`, `rsync` e backups

| Ferramenta | Comportamento |
|------------|---------------|
| `tar` | Guarda **symlinks como links** e preserva hard links (o segundo nome vira referência ao primeiro). `-h` / `--dereference` armazena o conteúdo do alvo em vez do link |
| `rsync -a` | Preserva symlinks (`-l`), mas **não** hard links: use **`-H`** |
| `rsync -L` | Transforma symlinks nos arquivos que eles apontam |
| `rsync --link-dest=DIR` | Backups incrementais com hard links para arquivos inalterados |

## 9. Links na administração de sistemas (exemplos reais)

### Symlinks muito comuns

| Link | Aponta para | Motivo |
|------|-------------|--------|
| `/etc/localtime` | `/usr/share/zoneinfo/<Região/Cidade>` | Define o fuso horário do sistema |
| `/bin/sh` | `dash` (Debian/Ubuntu) ou `bash` (RHEL) | Shell padrão de scripts |
| `/usr/bin/editor` → `/etc/alternatives/editor` → `/usr/bin/vim.basic` | Sistema **alternatives** (`update-alternatives`) | Trocar o programa padrão sem alterar scripts |
| `/bin`, `/sbin`, `/lib` → `usr/bin`, `usr/sbin`, `usr/lib` | *Merged-/usr* em distros modernas | Unificação de diretórios |
| `libc.so.6` → `libc-2.xx.so` (em `/lib*`) | Versionamento de **bibliotecas compartilhadas** (soname); `ldconfig` cria/atualiza | Atualizar a lib sem recompilar programas |
| `/etc/rc?.d/S01serviço` → `../init.d/serviço` | **SysV init**: ordem de início/parada por runlevel | Habilitar/desabilitar serviços |
| `/etc/systemd/system/multi-user.target.wants/*.service` → `/usr/lib/systemd/system/*.service` | **systemd**: é exatamente o que `systemctl enable` cria | Habilitar unidades |
| `/etc/nginx/sites-enabled/site` → `../sites-available/site` | Habilitar/desabilitar sites do Nginx/Apache (`a2ensite`) | Ativar sem apagar a configuração |
| `/etc/mtab` → `../proc/self/mounts` | Lista de montagens sempre atual | Compatibilidade |
| `/dev/stdin` → `/proc/self/fd/0` | Descritores de arquivo | Redirecionamentos |
| `/var/run` → `/run` | Diretório de runtime em tmpfs | Compatibilidade FHS |
| `/etc/resolv.conf` → `/run/systemd/resolve/stub-resolv.conf` | DNS gerenciado pelo systemd-resolved | Configuração dinâmica |

### Padrões de uso

- **Versão corrente:** `ln -sfn /opt/app-2.0 /opt/app`
- **Facilitar acesso:** `ln -s /mnt/dados/projetos ~/projetos`
- **Compatibilidade:** manter o caminho antigo funcionando após reorganizar diretórios.
- **Habilitar/desabilitar configurações:** criar/remover o link (padrão *available/enabled*).
- **Mesmo binário, vários nomes (hard links):** utilitários como `gzip`/`gunzip`/`zcat` historicamente compartilham o mesmo inode e mudam de comportamento conforme `argv[0]`; `busybox` usa a mesma ideia.
- **Snapshots/backup econômico:** `cp -al` e `rsync --link-dest`.

## 10. Segurança: `protected_symlinks` e `protected_hardlinks`

Links em diretórios com escrita pública (como `/tmp`) já foram vetor de ataques (*symlink attacks*, onde um usuário mau cria um link que engana um programa privilegiado). O kernel tem duas proteções, controladas por `sysctl`:

| Parâmetro | Efeito quando `= 1` |
|-----------|---------------------|
| `fs.protected_symlinks` | Em diretórios **world-writable com sticky bit** (ex.: `/tmp`), um symlink só é seguido se o **dono do link** for quem está seguindo, ou o dono do diretório |
| `fs.protected_hardlinks` | Um usuário só pode criar hard link para arquivos que **ele possui** (ou sobre os quais tem acesso de leitura **e** escrita) |

```bash
sysctl fs.protected_symlinks fs.protected_hardlinks
```

(Detalhe de aprofundamento — o foco da prova é o comportamento básico dos links.)

## 11. Erros comuns e solução de problemas

| Mensagem / sintoma | Causa | Solução |
|--------------------|-------|---------|
| `Invalid cross-device link` | Hard link entre filesystems diferentes | Use `ln -s` ou mova para a mesma partição |
| `hard link not allowed for directory` | Hard link de diretório | Use `ln -s` |
| `failed to create symbolic link 'x': File exists` | Já existe algo com esse nome | Use `-f` (e `-n` se for symlink para diretório) |
| `No such file or directory` ao usar um symlink que "existe" | Link quebrado ou alvo relativo errado | `readlink link`, `ls -lL link`, `find -xtype l`; corrija com `ln -sf` |
| Link foi criado **dentro** de um diretório em vez de substituir o link | Falta de `-n`/`-T` | `ln -sfn alvo link` |
| `Too many levels of symbolic links` | Laço (A → B → A) | Corrija a cadeia com `readlink`/`namei` |
| Hard link "sumiu" depois de editar | Editor/`sed -i` criou novo inode | Edite com método que preserve o inode ou recrie o link |
| `Permission denied` mesmo com link 777 | Permissão do **alvo** ou de diretório do caminho | `namei -l caminho` |
| Cópia ocupou o dobro de espaço | Hard links foram "desfeitos" pelo `cp`/`rsync` | Use `cp -a`/`cp -d`, `rsync -aH` |

## 13. Resumo para a prova (cheat sheet e pegadinhas)

### Comandos essenciais

```bash
ln alvo link                 # hard link
ln -s alvo link              # link simbólico
ln -sf alvo link             # recria o symlink
ln -sfn alvo link            # recria o symlink de diretório sem entrar nele
ln -sr alvo link             # symlink com caminho relativo automático
ls -l                        # tipo 'l', destino (->), contador de links
ls -i                        # número do inode
stat arquivo                 # Inode + Links
readlink -f link             # caminho final resolvido
find . -type l               # todos os symlinks
find . -xtype l              # symlinks quebrados
find . -samefile arq         # todos os nomes do mesmo inode
unlink nome  |  rm nome      # remove um nome
```

### Pegadinhas clássicas

1. **Ordem:** `ln [-s] ALVO(existente) LINK(novo)` — igual ao `cp ORIGEM DESTINO`.
2. **`ln` sem `-s` = hard link.** Esquecer o `-s` é a causa nº 1 de erros.
3. **Hard link:** mesma partição, nunca diretório, sempre mesmo inode, apagar o "original" **não** quebra.
4. **Symlink:** pode cruzar partições, pode apontar para diretórios, tem inode próprio, apagar/mover o alvo **quebra**.
5. **Caminho relativo no symlink** é resolvido a partir do **diretório do link**, não do `pwd`.
6. A **2ª coluna do `ls -l`** é o contador de links (hard links); symlinks **não** aumentam esse contador do alvo.
7. **Tamanho do symlink** = comprimento do caminho guardado.
8. Permissões de symlink aparecem como **`rwxrwxrwx`** mas **não valem nada** — vale o alvo.
9. **`ls -l` de um hard link não "avisa"** que ele é hard link; só o contador > 1 e o inode igual denunciam.
10. Dois nomes hard link = **mesmo dono, mesmas permissões, mesmas datas**.
11. `mv` entre filesystems **cria novo inode** (copia + apaga) e perde o vínculo de hard links.
12. `cp -a` / `cp -d` preservam symlinks como links; `cp -L` copia o conteúdo do alvo; `cp -l` cria hard links; `cp -s` cria symlinks.
13. Para substituir um symlink que aponta para **diretório**: **`ln -sfn`** (ou `-T`).
14. Para achar **symlinks quebrados**: `find -xtype l`.
15. Diretórios têm contador de links = **2 + número de subdiretórios**.

### Mini-fixação (responda de cabeça)

| Pergunta | Resposta |
|----------|----------|
| Como criar um hard link de `a` chamado `b`? | `ln a b` |
| Como criar um symlink `b` apontando para `a`? | `ln -s a b` |
| Qual tipo sobrevive à exclusão do arquivo original? | Hard link |
| Qual tipo pode apontar para outra partição? | Symlink |
| Qual tipo pode apontar para diretório? | Symlink |
| Como saber se dois arquivos são o mesmo inode? | `ls -i` (ou `stat`, `find -samefile`) |
| Que letra aparece no primeiro caractere do `ls -l` de um symlink? | `l` |
| Que opção do `ls` segue o link e mostra o alvo? | `-L` (`ls -lL`) |
| Como localizar symlinks quebrados? | `find . -xtype l` |
| Qual opção do `cp` cria hard links em vez de copiar? | `-l` |
