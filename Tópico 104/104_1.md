## 1. Visão geral e objetivos do tópico

Segundo os objetivos oficiais do LPI (versão 5.0), você precisa saber:

- Gerenciar tabelas de partição **MBR** e **GPT**.
- Usar vários comandos **mkfs** para criar sistemas de arquivos como **ext2/ext3/ext4, XFS, VFAT e exFAT**.
- Ter conhecimento básico dos recursos do **Btrfs**, incluindo **sistemas de arquivos multi-dispositivo, compressão e subvolumes**.

**Arquivos, termos e utilitários citados no objetivo:**

| Item | Para que serve |
|---|---|
| `fdisk` | Particionador interativo (MBR e GPT) |
| `gdisk` | Particionador interativo focado em GPT |
| `parted` | Particionador que aplica as mudanças **imediatamente** |
| `mkfs` | Cria sistema de arquivos (front-end para `mkfs.*`) |
| `mkswap` | Prepara uma partição/arquivo como área de swap |

> **Fora do escopo deste tópico** (aparecem em outros): montar (`mount`, `/etc/fstab`) é 104.3 e 104.2 trata de manutenção (`fsck`, `tune2fs`, `xfs_repair`, `df`, `du`). Aqui o assunto é **criar**.

## 2. Conceitos fundamentais

### 2.1 Disco, partição e sistema de arquivos

São três camadas distintas. Muita gente confunde, e o exame cobra essa diferença.

```
┌─────────────────────────────────────────────┐
│ DISCO (dispositivo de bloco: /dev/sdb)      │
│  ┌───────────────────────────────────────┐  │
│  │ TABELA DE PARTIÇÕES (MBR ou GPT)      │  │
│  └───────────────────────────────────────┘  │
│  ┌──────────────┐ ┌──────────────┐ ┌─────┐  │
│  │ Partição 1   │ │ Partição 2   │ │ ... │  │
│  │ /dev/sdb1    │ │ /dev/sdb2    │ │     │  │
│  │ ┌──────────┐ │ │ ┌──────────┐ │ │     │  │
│  │ │ ext4     │ │ │ │ swap     │ │ │     │  │
│  │ └──────────┘ │ │ └──────────┘ │ │     │  │
│  └──────────────┘ └──────────────┘ └─────┘  │
└─────────────────────────────────────────────┘
```

| Camada | O que é | Ferramenta que cria |
|---|---|---|
| **Disco** | O dispositivo físico ou virtual inteiro | (hardware / hypervisor) |
| **Tabela de partições** | Estrutura no início do disco que diz *onde* cada partição começa e termina | `fdisk`, `gdisk`, `parted` |
| **Partição** | Faixa contígua de setores reservada | `fdisk`, `gdisk`, `parted` |
| **Sistema de arquivos** | Estrutura de dados *dentro* da partição (diretórios, inodes, journal) | `mkfs.*`, `mkswap` |

**Ideia-chave:** particionar **não** cria sistema de arquivos. Uma partição recém-criada é só um espaço vazio; você ainda precisa rodar `mkfs` nela para poder gravar arquivos.

### 2.2 Por que particionar?

- **Isolamento:** `/home` lotado não derruba `/` (raiz).
- **Sistemas de arquivos diferentes** no mesmo disco (ex.: XFS em `/var`, ext4 em `/`).
- **Múltiplos sistemas operacionais** (dual boot).
- **Swap** dedicada.
- **Segurança e desempenho:** opções de montagem específicas (`noexec`, `nosuid`) em `/tmp`, por exemplo.
- **Backup e manutenção** mais simples por partição.

### 2.3 Setor, bloco e alinhamento

- **Setor:** menor unidade endereçável do disco. Historicamente **512 bytes**; discos modernos têm setores físicos de **4096 bytes** (Advanced Format, "4Kn" ou 512e).
- **LBA (Logical Block Addressing):** endereçamento por número de setor (LBA 0 é o primeiro).
- **Bloco:** unidade de alocação do **sistema de arquivos** (ex.: 4 KiB no ext4). Não confundir com setor.
- **Alinhamento:** o início das partições deve cair em múltiplos do tamanho físico do setor (e de blocos de SSD/RAID). Por isso as ferramentas modernas começam a primeira partição no setor **2048** (= **1 MiB** com setores de 512 bytes). Partições desalinhadas causam perda de desempenho.

## 3. Nomenclatura de discos e partições

| Tipo de dispositivo | Disco | Partições | Observação |
|---|---|---|---|
| SATA / SAS / USB / SCSI | `/dev/sda`, `/dev/sdb`... | `/dev/sda1`, `/dev/sda2`... | Letra segue a ordem de detecção |
| NVMe | `/dev/nvme0n1` | `/dev/nvme0n1p1`, `/dev/nvme0n1p2` | Note o **`p`** antes do número |
| Virtio (VMs KVM) | `/dev/vda` | `/dev/vda1` | |
| MMC / SD | `/dev/mmcblk0` | `/dev/mmcblk0p1` | Também usa `p` |
| IDE antigo | `/dev/hda` | `/dev/hda1` | Obsoleto |
| Loop device | `/dev/loop0` | `/dev/loop0p1` | Usa `p` (com `losetup -P`) |

> **Regra prática:** se o nome do disco **termina em dígito** (`nvme0n1`, `mmcblk0`, `loop0`), a partição leva um `p` antes do número.

> **Cuidado:** a letra do disco (`sda`, `sdb`) **pode mudar** entre boots. Por isso, em `/etc/fstab` prefira `UUID=` ou `LABEL=` (assunto do 104.3).

## 4. Tabela de partição MBR

**MBR** = *Master Boot Record*, também chamada de tabela **DOS** ou **msdos**. É o esquema clássico, nascido nos anos 1980 com o PC/BIOS.

### 4.1 Estrutura dos 512 bytes do primeiro setor (LBA 0)

```
Offset   Tamanho   Conteúdo
-------  --------  --------------------------------------------
0        446 B     Código de boot (bootstrap, ex.: GRUB stage 1)
446      64 B      Tabela de partições: 4 entradas × 16 bytes
510      2 B       Assinatura de boot: 0x55 0xAA
-------  --------  --------------------------------------------
Total    512 B
```

Cada entrada de 16 bytes guarda: flag de **boot (ativa)**, **tipo** da partição (1 byte), **setor inicial** e **quantidade de setores** (campos de 32 bits).

### 4.2 Limitações do MBR

| Limitação | Valor | Por quê |
|---|---|---|
| **Tamanho máximo de disco/partição** | **2 TiB** (com setores de 512 B) | Endereçamento LBA de **32 bits**: 2³² × 512 B = 2 TiB |
| **Partições primárias** | No máximo **4** | Só há 4 entradas de 16 bytes |
| **Redundância** | Nenhuma | Uma única cópia no setor 0 |
| **Verificação de integridade** | Nenhuma | Sem checksum |

### 4.3 Primárias, estendida e lógicas

Para passar de 4 partições, usa-se o truque da **partição estendida**:

```
Disco MBR
├── Primária 1  (/dev/sda1)
├── Primária 2  (/dev/sda2)
├── Primária 3  (/dev/sda3)
└── Estendida   (/dev/sda4)   ← ocupa 1 das 4 entradas
      ├── Lógica 1 (/dev/sda5)
      ├── Lógica 2 (/dev/sda6)
      └── Lógica 3 (/dev/sda7)
```

Regras importantes:

- Máximo de **4 primárias**, **ou** 3 primárias + **1 estendida**.
- Só pode existir **uma partição estendida** por disco.
- A estendida é apenas um **contêiner**: **não** recebe sistema de arquivos; quem recebe são as **lógicas** dentro dela.
- A numeração das lógicas **sempre começa em 5** (`sda5`, `sda6`...), mesmo que você tenha menos de 4 primárias. Os números 1 a 4 são reservados às primárias/estendida.
- Cada lógica é descrita por um **EBR** (*Extended Boot Record*), encadeado dentro da estendida.

### 4.4 Tipos (IDs) de partição MBR mais cobrados

| ID (hex) | Significado |
|---|---|
| `82` | **Linux swap** |
| `83` | **Linux** (dados genéricos: ext4, xfs, btrfs...) |
| `8e` | **Linux LVM** |
| `fd` | **Linux RAID autodetect** |
| `05` / `0f` | **Estendida** (CHS / LBA) |
| `07` | **NTFS / HPFS / exFAT** |
| `0b` / `0c` | **FAT32** (CHS / LBA) |
| `ef` | **EFI System Partition (ESP)** |

> O ID de tipo é só uma **etiqueta**. Ele *não* cria nem determina o sistema de arquivos. Uma partição tipo `83` pode conter ext4, XFS ou Btrfs. O ID serve de dica para o SO e para ferramentas (ex.: `82` indica swap).

### 4.5 Flag "bootable"

No MBR, uma partição pode ser marcada como **ativa/bootable** (comando `a` no `fdisk`). Algumas BIOS/bootloaders genéricos usam essa flag para decidir de qual partição continuar o boot. O GRUB não depende dela, mas sistemas Windows e BIOS antigas sim.

## 5. Tabela de partição GPT

**GPT** = *GUID Partition Table*, parte do padrão **UEFI**. Usa **LBA de 64 bits**, tem **cópia de segurança** e **checksums**.

### 5.1 Layout de um disco GPT

```
LBA 0          Protective MBR   (MBR "falso" que cobre o disco todo, tipo ee)
LBA 1          Cabeçalho GPT primário
LBA 2–33       Tabela de entradas de partição primária
                (padrão: 128 entradas × 128 bytes = 16 KiB = 32 setores)
LBA 34 ...     ← ÁREA UTILIZÁVEL: onde ficam as partições →
...
LBA -33 a -2   Tabela de entradas de partição (CÓPIA de backup)
LBA -1         Cabeçalho GPT de backup (último setor do disco)
```

Pontos a gravar:

- **Protective MBR (LBA 0):** contém uma única partição do tipo **`ee`** que ocupa o disco inteiro. Serve para que ferramentas antigas, que só entendem MBR, **não vejam o disco como vazio** e não o sobrescrevam por engano.
- **Cabeçalho primário (LBA 1)** e **cabeçalho de backup (último LBA do disco)**: guardam GUID do disco, localização das tabelas, e **CRC32** para detectar corrupção.
- **Redundância:** se a tabela primária corromper, a de backup permite recuperação (o `gdisk` tem modo recovery para isso).
- **Identificação:** cada disco e cada partição têm um **GUID** próprio (o **PARTUUID**), além do **GUID de tipo** e de um **nome** opcional (até 36 caracteres UTF-16).

### 5.2 Capacidades

| Característica | Valor |
|---|---|
| Endereçamento | **64 bits** de LBA |
| Tamanho máximo | ~**9,4 ZB** com setores de 512 B (2⁶⁴ × 512 B); na prática, limitado pelo SO/hardware |
| Partições | **128** por padrão (pode ser aumentado) |
| Tipos de partição | Sem primária/estendida/lógica: **todas são iguais** |

### 5.3 Códigos de tipo GPT no `gdisk` (4 dígitos hex)

O `gdisk` usa códigos que são o ID MBR com `00` anexado (quando existe equivalente):

| Código gdisk | Significado |
|---|---|
| `8300` | **Linux filesystem** |
| `8200` | **Linux swap** |
| `8e00` | **Linux LVM** |
| `fd00` | **Linux RAID** |
| `ef00` | **EFI System Partition (ESP)**: normalmente FAT32 |
| `ef02` | **BIOS boot partition**: necessária para GRUB em BIOS + GPT (sem sistema de arquivos) |
| `0700` | **Microsoft basic data** (NTFS, FAT32, exFAT) |

### 5.4 BIOS + GPT e UEFI + GPT

| Firmware | Disco GPT precisa de... |
|---|---|
| **UEFI** | Uma **ESP** (`ef00`, FAT32, ~100–550 MiB, montada em `/boot/efi`) |
| **BIOS (legacy)** | Uma **BIOS boot partition** (`ef02`, ~1 MiB, sem filesystem) para guardar o *core.img* do GRUB |

## 6. MBR × GPT: comparação

| Aspecto | **MBR (DOS)** | **GPT** |
|---|---|---|
| Padrão | BIOS clássico | UEFI (funciona também com BIOS) |
| Tamanho máx. | **2 TiB** | ~**9,4 ZB** |
| Partições | 4 primárias (ou 3 + estendida/lógicas) | **128** (padrão), todas equivalentes |
| Cópia de segurança | **Não** | **Sim** (início e fim do disco) |
| Checksum | **Não** | **Sim** (CRC32) |
| Identificação | Tipo de 1 byte, sem ID único | **GUIDs** (disco e partição) + nomes |
| Numeração das lógicas | Começa em **5** | Não existem lógicas |
| Ferramentas | `fdisk`, `parted`, `cfdisk` | `gdisk`, `fdisk` (moderno), `parted` |
| ID de swap / Linux | `82` / `83` | `8200` / `8300` |

**Quando usar cada um?**

- **GPT** é a escolha padrão atual (discos >2 TiB, UEFI, mais robustez).
- **MBR** ainda aparece em BIOS legado, VMs antigas e mídia removível por compatibilidade.

## 7. Inspecionando discos antes de mexer

> **Regra de ouro:** antes de particionar, **confirme qual é o disco certo**. Particionar o disco errado destrói dados.

### 7.1 `lsblk`: visão em árvore

```bash
lsblk
lsblk -f              # mostra FSTYPE, LABEL, UUID e ponto de montagem
lsblk -o NAME,SIZE,TYPE,FSTYPE,PTTYPE,MOUNTPOINT
```

Exemplo:

```text
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda      8:0    0   50G  0 disk
├─sda1   8:1    0  512M  0 part /boot/efi
├─sda2   8:2    0   45G  0 part /
└─sda3   8:3    0  4.5G  0 part [SWAP]
sdb      8:16   0  100G  0 disk
```

A coluna `PTTYPE` mostra o tipo de tabela (`gpt` ou `dos`).

### 7.2 `fdisk -l`: tabela de partições

```bash
fdisk -l                 # todos os discos (precisa de root)
fdisk -l /dev/sdb        # só um disco
```

Mostra "Disklabel type: **gpt**" ou "**dos**", tamanho em setores, e cada partição com `Start`, `End`, `Sectors`, `Size`, `Type`.

### 7.3 `blkid` e `file -s`: identificar conteúdo

```bash
blkid /dev/sdb1             # UUID, LABEL, TYPE (filesystem)
file -s /dev/sdb1           # lê o início do dispositivo e descreve o conteúdo
wipefs /dev/sdb             # lista assinaturas (sem apagar)
```

### 7.4 Outros arquivos úteis

```bash
cat /proc/partitions        # partições conhecidas pelo kernel
ls -l /dev/disk/by-uuid/    # links por UUID
ls -l /dev/disk/by-id/      # links por modelo/serial
ls -l /dev/disk/by-partuuid # PARTUUID (GPT)
```

## 8. fdisk

O **`fdisk`** é o particionador mais cobrado no exame. É **interativo** e trabalha em uma **cópia em memória**: nada é gravado no disco até você usar **`w`**. Se errar, use **`q`** para sair sem salvar.

> Versões modernas (util-linux ≥ 2.23) suportam **MBR e GPT**. As antigas só MBR.

### 8.1 Abrindo

```bash
sudo fdisk /dev/sdb
```

### 8.2 Comandos do menu (mais importantes)

| Tecla | Ação |
|---|---|
| `m` | **Ajuda** (lista de comandos) |
| `p` | **Imprime** a tabela de partições atual |
| `n` | **Nova** partição |
| `d` | **Apaga** (*delete*) partição |
| `t` | Altera o **tipo** da partição |
| `l` | **Lista** os tipos conhecidos |
| `a` | Liga/desliga a flag **bootable** (só MBR) |
| `o` | Cria **nova tabela DOS (MBR)** vazia |
| `g` | Cria **nova tabela GPT** vazia |
| `F` | Mostra **espaço livre** não particionado |
| `i` | Informações de uma partição |
| `v` | **Verifica** a tabela |
| `u` | Alterna unidade (setores/cilindros) |
| `x` | Modo **expert** |
| `w` | **Grava** e sai (*write*) |
| `q` | **Sai sem gravar** (*quit*) |

### 8.3 Exemplo completo: criar tabela GPT e duas partições

```text
$ sudo fdisk /dev/sdb

Command (m for help): g
Created a new GPT disklabel (GUID: 6B0D...).

Command (m for help): n
Partition number (1-128, default 1): 1
First sector (2048-209715166, default 2048): <Enter>
Last sector, +/-sectors or +/-size{K,M,G,T,P}: +20G

Created a new partition 1 of type 'Linux filesystem' and of size 20 GiB.

Command (m for help): n
Partition number (2-128, default 2): 2
First sector (...): <Enter>
Last sector, +/-sectors or +/-size{K,M,G,T,P}: +4G

Command (m for help): t
Partition number (1,2, default 2): 2
Partition type or alias (type L to list all): 19      # ou o alias "swap"
Changed type of partition 'Linux filesystem' to 'Linux swap'.

Command (m for help): p
...
Command (m for help): w
The partition table has been altered.
Calling ioctl() to re-read partition table.
Syncing disks.
```

### 8.4 Detalhes que caem na prova

- **Primeiro setor padrão = 2048** (alinhamento de 1 MiB). Aceite o padrão apertando Enter.
- No **último setor** use `+20G`, `+512M` etc. (o `+` significa "a partir do primeiro setor"). Sem unidade, o número é em **setores**.
- Numa tabela **DOS**, o `n` pergunta **`p` primary / `e` extended** (e `l` logical, quando já existe estendida). Em **GPT** essa pergunta **não existe**.
- `o` = **o**ld/DOS (MBR). `g` = **g**PT. Ambos **apagam** a tabela atual **em memória** (e valem de verdade ao `w`).
- O `fdisk` **não cria** o sistema de arquivos.
- Ao mudar o tipo com `t`, em **DOS** você informa o **hex** (`82`, `83`, `8e`...); em **GPT** informa o **número da lista** ou o **alias** (`swap`, `linux`, `uefi`, `lvm`).
- Após `w`, o `fdisk` pede ao kernel para reler a tabela; se o disco estiver em uso, isso pode falhar (veja a [seção 11](#11-fazendo-o-kernel-reler-a-tabela-de-partições)).

### 8.5 Modo não interativo (scriptável)

```bash
# Alimenta o fdisk por stdin (cada linha = uma resposta do menu)
printf 'g\nn\n1\n\n+1G\nw\n' | sudo fdisk /dev/sdb
```

Para scripts sérios, prefira `sfdisk` (MBR/GPT) ou `sgdisk` (GPT).

## 9. gdisk e sgdisk

O **`gdisk`** (*GPT fdisk*) é feito para **GPT**. A interface lembra a do `fdisk`.

```bash
sudo gdisk /dev/sdb
```

### 9.1 Comandos do menu

| Tecla | Ação |
|---|---|
| `?` | Ajuda |
| `p` | Imprime a tabela |
| `n` | Nova partição |
| `d` | Apaga partição |
| `t` | Altera o tipo (código de 4 dígitos hex) |
| `L` | Lista os códigos de tipo |
| `c` | Altera o **nome** da partição |
| `i` | Detalhes da partição (GUIDs) |
| `o` | Cria **nova GPT vazia** |
| `v` | **Verifica** a integridade do disco |
| `r` | Menu de **recuperação/transformação** (`r`) |
| `x` | Menu **expert** |
| `s` | **Ordena** (*sort*) as partições |
| `b` | **Backup** da tabela para arquivo |
| `l` | Carrega backup |
| `w` | **Grava** e sai |
| `q` | Sai **sem gravar** |

### 9.2 Exemplo

```text
Command (? for help): o            # nova GPT
Proceed? (Y/N): y

Command (? for help): n
Partition number (1-128, default 1): <Enter>
First sector (34-..., default = 2048) or {+-}size{KMGTP}: <Enter>
Last sector (... default = ...) or {+-}size{KMGTP}: +10G
Current type is 8300 (Linux filesystem)
Hex code or GUID (L to show codes, Enter = 8300): <Enter>

Command (? for help): n
...
Hex code or GUID: 8200                # swap

Command (? for help): w
```

### 9.3 Conversão de MBR para GPT (sem perder dados)

O `gdisk` **lê MBR** e, ao gravar, **converte para GPT em memória**:

```text
$ sudo gdisk /dev/sdb
Found valid MBR and GPT. Which do you want to use?   (ou)
Partition table scan:
  MBR: MBR only
  BSD: not present
  APM: not present
  GPT: not present
...
Command (? for help): w
```

> **Atenção:** a conversão pode exigir criar uma **BIOS boot partition** (`ef02`) ou ESP para o boot continuar funcionando, e é recomendável **backup antes**.

### 9.4 Recuperação (`r`)

No menu `r` você consegue, por exemplo:

- `b`: usar o **cabeçalho de backup**
- `c`: carregar a **tabela de partições de backup**
- `d`: usar o cabeçalho principal; `e`: carregar a tabela principal
- `f`: **carregar o MBR e construir uma GPT nova a partir dele**
- `g`: **converter GPT em MBR** e sair
- `h`: criar um **MBR híbrido** (**evite**: frágil e desencorajado)
- `m`: voltar ao menu principal

### 9.5 `sgdisk`: o `gdisk` para scripts

```bash
sudo sgdisk -p /dev/sdb                          # imprime
sudo sgdisk -Z /dev/sdb                          # zap: destrói GPT e MBR
sudo sgdisk -o /dev/sdb                          # nova GPT vazia
sudo sgdisk -n 1:0:+1G -t 1:8300 /dev/sdb        # partição 1, início padrão, 1G, tipo Linux
sudo sgdisk -n 2:0:0   -t 2:8200 /dev/sdb        # partição 2, até o fim do disco, swap
sudo sgdisk -c 1:"dados" /dev/sdb                # define o nome
sudo sgdisk -d 2 /dev/sdb                        # apaga a partição 2
```

Sintaxe do `-n`: `número:início:fim`, onde **`0` significa "padrão"** (início = primeiro setor livre; fim = último disponível).

## 10. parted

O **`parted`** trabalha com **MBR (msdos)**, **GPT** e outros rótulos. A diferença crucial:

> ⚠️ **O `parted` aplica as mudanças IMEDIATAMENTE** ao disco, a cada comando. **Não existe `w` para gravar** e não há "desfazer". Seja cuidadoso.

### 10.1 Modo interativo

```bash
sudo parted /dev/sdb
(parted) print
(parted) mklabel gpt
(parted) mkpart dados ext4 1MiB 20GiB
(parted) mkpart swap linux-swap 20GiB 24GiB
(parted) print
(parted) quit
```

### 10.2 Comandos principais

| Comando | Ação |
|---|---|
| `print` (ou `p`) | Mostra a tabela (`print free`: inclui espaço livre; `print all`: todos os discos) |
| `select /dev/sdc` | Troca o disco |
| `mklabel gpt` / `mklabel msdos` | Cria nova tabela (**apaga a anterior**) |
| `mkpart` | Cria partição |
| `rm N` | Remove a partição N |
| `resizepart N FIM` | Redimensiona o fim da partição N |
| `name N nome` | Dá nome (só **GPT**) |
| `set N flag on\|off` | Liga/desliga flags (`boot`, `esp`, `swap`, `lvm`, `raid`...) |
| `unit MiB` | Muda a unidade de exibição |
| `align-check optimal N` | Verifica o alinhamento da partição N |
| `quit` (ou `q`) | Sai |

### 10.3 Sintaxe do `mkpart`

```text
# GPT:   mkpart NOME   [FS-TYPE] INÍCIO FIM
# MSDOS: mkpart TIPO   [FS-TYPE] INÍCIO FIM       (TIPO = primary | logical | extended)

(parted) mkpart primary ext4 1MiB 20GiB     # msdos
(parted) mkpart dados   ext4 1MiB 20GiB     # gpt (o "dados" é o nome)
(parted) mkpart primary ext4 20GiB 100%     # até o fim do disco
```

> **Pegadinha clássica:** o `FS-TYPE` do `mkpart` é só uma **dica** para definir o ID/tipo da partição. O `parted` **NÃO cria o sistema de arquivos**. Você ainda precisa do `mkfs`.

### 10.4 Modo script (não interativo)

```bash
sudo parted -s /dev/sdb mklabel gpt \
     mkpart primary ext4 1MiB 20GiB \
     mkpart primary linux-swap 20GiB 24GiB \
     set 2 swap on \
     print
```

`-s` (*script*) suprime perguntas/confirmações.

### 10.5 Unidades

`parted` aceita `s` (setores), `B`, `kB`, `MB`, `GB` (base **10**), e `KiB`, `MiB`, `GiB`, `TiB` (base **2**), além de `%`. Para alinhamento correto, use **`MiB`/`GiB`** e comece em **`1MiB`**.

### 10.6 Quando o `parted` é indispensável

- Tem suporte nativo a **redimensionar** (`resizepart`).
- Muito usado em **scripts/automação** (Kickstart, cloud-init, Ansible).
- Trabalha com **discos >2 TiB** em GPT sem mudar de ferramenta.

## 11. Fazendo o kernel reler a tabela de partições

Depois de alterar partições, o kernel precisa saber das mudanças. Se o disco **tem partições montadas/em uso**, ele **não** relê automaticamente.

```bash
sudo partprobe /dev/sdb         # pede ao kernel para reler a tabela
sudo partx -u /dev/sdb          # atualiza as partições (alternativa)
sudo udevadm settle             # espera o udev terminar de criar os nós em /dev
sudo blockdev --rereadpt /dev/sdb   # outra forma de forçar a releitura
```

Se nada funcionar porque o disco está em uso: **desmonte** as partições (`umount`) ou **reinicie**.

Confirme com:

```bash
lsblk /dev/sdb
cat /proc/partitions
```

## 12. Criando sistemas de arquivos: mkfs

### 12.1 O comando `mkfs`

`mkfs` é apenas um **front-end** que chama o utilitário específico `mkfs.<tipo>`:

```bash
mkfs -t ext4 /dev/sdb1      # é equivalente a:  mkfs.ext4 /dev/sdb1
mkfs.ext4 /dev/sdb1
mke2fs -t ext4 /dev/sdb1    # mkfs.ext4 é link/atalho para mke2fs -t ext4
```

Veja os `mkfs.*` instalados:

```bash
ls /sbin/mkfs*
# mkfs  mkfs.bfs  mkfs.btrfs  mkfs.cramfs  mkfs.exfat  mkfs.ext2  mkfs.ext3
# mkfs.ext4  mkfs.fat  mkfs.minix  mkfs.msdos  mkfs.vfat  mkfs.xfs ...
```

> **Atenção:** `mkfs` **destrói** o conteúdo anterior da partição. Se o dispositivo já tiver filesystem, a maioria dos utilitários **pergunta/avisa** (ou exige `-f`).

### 12.2 Opções comuns

| Opção | Efeito | Observação |
|---|---|---|
| `-t TIPO` | Escolhe o tipo (no `mkfs` genérico) | `mkfs -t xfs` |
| `-L RÓTULO` | Define o **label** | Limites: ext **16**, xfs **12**, vfat **11** (em vfat é `-n`) |
| `-U UUID` | Define um UUID específico | ext4/xfs (xfs: `-m uuid=`) |
| `-f` | **Força** a criação (xfs, btrfs) | Sobrescreve fs existente |
| `-b TAM` | Tamanho do bloco | `-b 4096` em ext; `-b size=4096` em xfs |
| `-n` (vfat) | Rótulo | Em `mkfs.vfat`, `-n` = nome/label |

Depois de criar, confira:

```bash
blkid /dev/sdb1
lsblk -f /dev/sdb
```

## 13. ext2, ext3 e ext4

Família **ext** ("*extended filesystem*"): o padrão histórico no Linux.

### 13.1 Evolução

| FS | Journal | Extents | Tamanho máx. do FS | Tamanho máx. de arquivo | Notas |
|---|---|---|---|---|---|
| **ext2** | ❌ | ❌ (blocos indiretos) | 16 TiB* | 2 TiB* | Simples, sem journal; bom para `/boot` pequeno ou mídias flash |
| **ext3** | ✅ | ❌ | 16–32 TiB* | 2 TiB* | = ext2 **+ journal**; retrocompatível |
| **ext4** | ✅ | ✅ | **1 EiB** (teórico) | **16 TiB** | Extents, alocação atrasada, checksums no journal, `fsck` rápido |

\* Os limites de ext2/ext3 dependem do tamanho de bloco; os valores acima são com bloco de 4 KiB, e valem como ordem de grandeza.

**O que é journal?** Um registro (log) das operações pendentes. Após queda de energia, o sistema **reaplica ou descarta** o que estava em andamento, evitando um `fsck` demorado.

**O que são extents?** Em vez de listar bloco por bloco, o arquivo é descrito por **faixas contíguas** (início + comprimento). Menos metadados, melhor desempenho em arquivos grandes e menos fragmentação.

### 13.2 Criando

```bash
sudo mkfs.ext2 /dev/sdb1
sudo mkfs.ext3 /dev/sdb1
sudo mkfs.ext4 /dev/sdb1
sudo mkfs.ext4 -L dados /dev/sdb1                 # com label
sudo mkfs -t ext4 -L dados /dev/sdb1              # idem
```

### 13.3 Opções úteis (`mke2fs`/`mkfs.ext4`)

| Opção | Função |
|---|---|
| `-L rótulo` | Label (até 16 caracteres) |
| `-b tamanho` | Tamanho do **bloco**: 1024, 2048 ou 4096 |
| `-m %` | **% de blocos reservados** para o root (padrão **5%**). Em discos de dados grandes, `-m 1` ou `-m 0` libera espaço |
| `-N n` | Número de **inodes** |
| `-i bytes` | **bytes por inode** (razão de inodes). Menor valor = mais inodes |
| `-j` | Cria **journal** (ext3). Com `mke2fs`, `-j` equivale a ext3 |
| `-O recurso` | Liga/desliga recursos (`-O ^has_journal` remove o journal) |
| `-T tipo` | Perfil de uso em `/etc/mke2fs.conf` (`small`, `news`, `largefile`...) |
| `-U uuid` | UUID específico |
| `-E opções` | Opções estendidas (`lazy_itable_init`, `stride`, `stripe_width`) |
| `-n` | **Simulação**: mostra o que faria, sem gravar |

Exemplo combinado:

```bash
sudo mkfs.ext4 -L backup -m 1 -b 4096 -i 16384 /dev/sdb1
```

> **Inodes:** cada arquivo/diretório consome 1 inode. É possível **ficar sem inodes** com espaço sobrando (muitos arquivos pequenos). Os inodes são definidos **na criação** do ext*, e não crescem depois; confira com `df -i`.

### 13.4 Ferramentas relacionadas (veja o tópico 104.2)

`tune2fs` (ajustar parâmetros), `e2label` (label), `dumpe2fs` (detalhes), `resize2fs` (redimensionar), `e2fsck`/`fsck.ext4` (verificar).

## 14. XFS

Sistema de arquivos **journaling de alto desempenho**, de 64 bits, criado pela SGI. É o **padrão do RHEL/CentOS/Rocky/Alma** e excelente com **arquivos grandes** e paralelismo.

### 14.1 Características

- Escala até **8 EiB** de sistema de arquivos.
- **Journal** de metadados.
- **Alocação por extents** e alocação atrasada.
- **Pode crescer online, mas NÃO pode ser reduzido.**
- Ótimo para volumes grandes, bancos de dados, mídia.
- Inodes alocados **dinamicamente** (menos risco de "acabar inodes").

### 14.2 Criando

```bash
sudo mkfs.xfs /dev/sdb1
sudo mkfs.xfs -L dados /dev/sdb1            # label (máx. 12 caracteres)
sudo mkfs.xfs -f /dev/sdb1                  # FORÇA: sobrescreve filesystem existente
sudo mkfs.xfs -b size=4096 /dev/sdb1        # tamanho do bloco
sudo mkfs.xfs -m uuid=<UUID> /dev/sdb1      # UUID específico
```

> **`-f` é a opção mais lembrada do `mkfs.xfs`:** sem ela, o comando **recusa** criar em uma partição que já tenha um sistema de arquivos.

### 14.3 Utilitários XFS

| Comando | Função |
|---|---|
| `xfs_info /ponto` | Mostra a geometria do FS (ponto de montagem **ou** dispositivo) |
| `xfs_growfs /ponto` | **Aumenta** o FS montado |
| `xfs_repair /dev/...` | **Repara** (**desmontado**) |
| `xfs_admin -L rótulo /dev/...` | Altera label/UUID |
| `xfs_db` | Depurador |
| `xfs_dump` / `xfs_restore` | Backup/restore |
| `xfs_freeze` | Congela o FS (para snapshots) |

> O `fsck.xfs` **não repara nada** (existe só por compatibilidade no boot). Quem repara é o **`xfs_repair`**.

## 15. VFAT (FAT32) e exFAT

Sistemas de arquivos da Microsoft, usados por **portabilidade** (pen drives, cartões SD, **ESP** do UEFI).

### 15.1 FAT (VFAT)

- **VFAT** = FAT com suporte a **nomes longos** (LFN).
- Variantes: **FAT12**, **FAT16**, **FAT32**.
- **Não tem** permissões Unix, donos, links simbólicos nem journal.
- **FAT32:** arquivo máximo de **4 GiB − 1 byte**.
- É o formato exigido pela **ESP** (EFI System Partition).

```bash
sudo mkfs.vfat /dev/sdb1                  # escolhe FAT12/16/32 conforme o tamanho
sudo mkfs.vfat -F 32 /dev/sdb1            # força FAT32  (-F 12 | 16 | 32)
sudo mkfs.vfat -F 32 -n PENDRIVE /dev/sdb1   # -n define o rótulo (máx. 11 caracteres)
sudo mkfs.fat -F 32 /dev/sdb1             # mkfs.fat = mkfs.vfat = mkfs.msdos (mesmo pacote dosfstools)
```

> O pacote é **`dosfstools`**. Rótulo: **`-n`**, não `-L`.

### 15.2 exFAT

- Criado para **mídia flash** (SDXC, pen drives grandes).
- **Sem o limite de 4 GiB** por arquivo.
- Suporta volumes e arquivos **muito grandes** (limites teóricos de ZiB/EiB).
- Também **sem permissões Unix**; compatível com Windows e macOS.
- Suporte nativo no kernel Linux a partir da versão **5.7**; antes, via FUSE (`exfat-fuse`).

```bash
sudo mkfs.exfat /dev/sdb1
sudo mkfs.exfat -L CARTAO /dev/sdb1       # rótulo com -L
```

Pacotes: **`exfatprogs`** (moderno) ou `exfat-utils` (antigo).

### 15.3 Tipos de partição para FAT/exFAT

| Esquema | FAT32 | exFAT |
|---|---|---|
| MBR | `0b` ou `0c` | `07` |
| GPT | `0700` (Microsoft basic data) | `0700` |
| ESP (UEFI) | `ef00` (FAT32) | n/a |

## 16. Btrfs

**Btrfs** ("*B-tree FS*") é um sistema de arquivos **moderno, copy-on-write (CoW)**, com recursos que antes exigiam LVM + RAID + ferramentas de backup. O LPI exige conhecimento **básico**: **multi-dispositivo, compressão e subvolumes**.

### 16.1 Principais recursos

| Recurso | Descrição |
|---|---|
| **Copy-on-Write** | Dados modificados são gravados em **novo local**; o original só é liberado depois. Mais segurança e base para snapshots |
| **Subvolumes** | "Árvores" de arquivos independentes **dentro do mesmo FS**; podem ser montadas separadamente |
| **Snapshots** | Cópia **instantânea** e leve de um subvolume (compartilha blocos até serem modificados) |
| **Checksums** | Dados **e** metadados têm checksum (detecta corrupção silenciosa) |
| **Multi-dispositivo** | Um FS pode usar **vários discos**, com perfis de RAID nativos |
| **Compressão** | Transparente (`zlib`, `lzo`, `zstd`) |
| **Crescer/reduzir online** | Pode **aumentar e diminuir** com o FS montado |
| **Send/receive** | Replicação incremental de snapshots |
| **Scrub / balance** | Verificação de integridade / redistribuição de dados |

### 16.2 Criando

```bash
sudo mkfs.btrfs /dev/sdb1
sudo mkfs.btrfs -L dados /dev/sdb1               # label
sudo mkfs.btrfs -f /dev/sdb1                     # força sobrescrita
```

### 16.3 Multi-dispositivo e perfis (RAID)

Um **único** Btrfs pode abranger **vários dispositivos**. Você escolhe o **perfil** de dados (`-d`) e de metadados (`-m`):

| Perfil | Comportamento |
|---|---|
| `single` | Sem redundância; usa os discos como espaço somado |
| `dup` | Duas cópias **no mesmo disco** (padrão para metadados em disco único) |
| `raid0` | *Striping* (desempenho, sem redundância) |
| `raid1` | **Espelhamento** (2 cópias em discos diferentes) |
| `raid10` | Striping + espelhamento |
| `raid5` / `raid6` | Paridade (considerados **experimentais/ressalvas conhecidas**) |

```bash
# Criar já com 2 discos, em espelhamento
sudo mkfs.btrfs -L pool -d raid1 -m raid1 /dev/sdb /dev/sdc

# Mostrar os dispositivos do FS
sudo btrfs filesystem show

# Adicionar um disco a um FS montado e redistribuir
sudo btrfs device add /dev/sdd /mnt/pool
sudo btrfs balance start /mnt/pool

# Remover um disco
sudo btrfs device remove /dev/sdd /mnt/pool
```

> Montar um Btrfs multi-disco: basta apontar **qualquer** dos dispositivos membros (`mount /dev/sdb /mnt/pool`).

### 16.4 Subvolumes e snapshots

```bash
sudo mount /dev/sdb1 /mnt

# Criar subvolumes
sudo btrfs subvolume create /mnt/@
sudo btrfs subvolume create /mnt/@home

# Listar
sudo btrfs subvolume list /mnt

# Snapshot (gravável) e snapshot somente leitura (-r)
sudo btrfs subvolume snapshot /mnt/@home /mnt/@home-snap
sudo btrfs subvolume snapshot -r /mnt/@home /mnt/@home-ro

# Apagar
sudo btrfs subvolume delete /mnt/@home-snap
```

Montando um subvolume específico:

```bash
sudo mount -o subvol=@home /dev/sdb1 /home
sudo mount -o subvolid=256 /dev/sdb1 /home        # pelo ID
```

> Um **subvolume** *não é* uma partição nem um LVM: é um **diretório especial** com raiz própria, que compartilha o espaço do FS e pode ser montado/snapshotado separadamente.

### 16.5 Compressão

Ativada por **opção de montagem**:

```bash
sudo mount -o compress=zstd /dev/sdb1 /mnt
sudo mount -o compress=zlib /dev/sdb1 /mnt
sudo mount -o compress=lzo  /dev/sdb1 /mnt
sudo mount -o compress-force=zstd /dev/sdb1 /mnt   # comprime mesmo o que parece incomprimível
```

Em `/etc/fstab`:

```text
UUID=xxxx-xxxx  /dados  btrfs  compress=zstd,subvol=@dados  0 0
```

Comprimir arquivos já existentes:

```bash
sudo btrfs filesystem defragment -r -v -czstd /mnt/dados
```

### 16.6 Comandos de manutenção essenciais

| Comando | Função |
|---|---|
| `btrfs filesystem show` | Lista FS Btrfs e dispositivos |
| `btrfs filesystem df /ponto` | Uso por tipo (data/metadata/system) |
| `btrfs filesystem usage /ponto` | Visão detalhada de uso |
| `btrfs filesystem resize +10G /ponto` | Aumenta (ou `-10G`, reduz); `max` ocupa tudo |
| `btrfs scrub start /ponto` | Verifica checksums e repara (com redundância) |
| `btrfs balance start /ponto` | Redistribui blocos entre os dispositivos |
| `btrfs check /dev/...` | Verifica (**desmontado**; `--repair` com cautela) |
| `btrfs send` / `btrfs receive` | Envia/recebe snapshots |

> No Btrfs, `df` pode **enganar** (espaço de dados/metadados é alocado em *chunks*). Use `btrfs filesystem df/usage`.

## 18. Swap: mkswap, swapon e swapoff

A **swap** é espaço em disco usado como extensão da memória RAM (e para **hibernação**). **Não** usa `mkfs`: usa **`mkswap`**.

### 18.1 Swap em partição

```bash
# 1) Criar a partição com tipo swap (82 em MBR / 8200 em GPT) usando fdisk/gdisk/parted
# 2) Preparar a área de swap
sudo mkswap /dev/sdb2
sudo mkswap -L minhaswap /dev/sdb2          # com label

# 3) Ativar
sudo swapon /dev/sdb2

# 4) Conferir
swapon --show          # ou:  swapon -s   /  cat /proc/swaps
free -h

# 5) Desativar
sudo swapoff /dev/sdb2
```

### 18.2 Swap em arquivo

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048   # 2 GiB
# alternativa:  sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile                             # só root deve ler
sudo mkswap /swapfile
sudo swapon /swapfile
```

> Em **Btrfs**, um arquivo de swap exige cuidados (sem CoW/compressão, via `chattr +C` ou `btrfs filesystem mkswapfile`). Em XFS/ext4 o método acima funciona normalmente.

### 18.3 Tornar permanente (`/etc/fstab`)

```text
UUID=a1b2c3d4-...   none   swap   sw   0 0
/swapfile           none   swap   sw   0 0
```

### 18.4 Comandos úteis

| Comando | Função |
|---|---|
| `mkswap DEV` | Cria a **assinatura de swap** |
| `swapon DEV` / `swapon -a` | Ativa um dispositivo / **todos** do `/etc/fstab` |
| `swapoff DEV` / `swapoff -a` | Desativa um / todos |
| `swapon --show` | Lista swaps ativas |
| `cat /proc/swaps` | Idem, pelo kernel |
| `free -h` | Memória e swap |

## 19. Fluxo completo: do disco vazio ao uso

Cenário: novo disco `/dev/sdb` de 100 GiB. Queremos uma partição de 20 GiB em **ext4**, uma de 4 GiB de **swap** e o restante em **XFS**.

```bash
# 0) Identificar o disco certo
lsblk
sudo fdisk -l /dev/sdb

# 1) Criar tabela GPT e partições (script do sgdisk)
sudo sgdisk -Z /dev/sdb
sudo sgdisk -n 1:0:+20G -t 1:8300 -c 1:"dados-ext4" /dev/sdb
sudo sgdisk -n 2:0:+4G  -t 2:8200 -c 2:"swap"       /dev/sdb
sudo sgdisk -n 3:0:0    -t 3:8300 -c 3:"dados-xfs"  /dev/sdb

# 2) Avisar o kernel
sudo partprobe /dev/sdb
lsblk /dev/sdb

# 3) Criar os sistemas de arquivos / swap
sudo mkfs.ext4 -L dados  /dev/sdb1
sudo mkswap    -L swapx  /dev/sdb2
sudo mkfs.xfs  -L grande /dev/sdb3

# 4) Conferir UUIDs
sudo blkid /dev/sdb1 /dev/sdb2 /dev/sdb3

# 5) Montar e ativar (detalhes no 104.3)
sudo mkdir -p /dados /grande
sudo mount /dev/sdb1 /dados
sudo mount /dev/sdb3 /grande
sudo swapon /dev/sdb2

# 6) Tornar permanente: adicionar entradas com UUID em /etc/fstab
```

## 20. Laboratório seguro com loop device

Não tem disco sobrando? Treine com um **arquivo** que finge ser um disco. **Zero risco** para seu sistema.

```bash
# 1) Cria um "disco" de 1 GiB (esparso)
truncate -s 1G ~/disco.img

# 2) Associa a um loop device, lendo partições (-P) e mostrando o nome (--show)
sudo losetup -fP --show ~/disco.img
# saída, por exemplo:  /dev/loop0

# 3) Particiona normalmente
sudo fdisk /dev/loop0         # g, n, +300M, n, +300M, n, Enter, w
lsblk /dev/loop0              # loop0p1, loop0p2, loop0p3

# 4) Cria sistemas de arquivos diferentes
sudo mkfs.ext4  /dev/loop0p1
sudo mkfs.xfs   /dev/loop0p2
sudo mkfs.btrfs /dev/loop0p3
lsblk -f /dev/loop0

# 5) Monte e explore
sudo mkdir -p /mnt/{a,b,c}
sudo mount /dev/loop0p1 /mnt/a
sudo mount /dev/loop0p2 /mnt/b
sudo mount /dev/loop0p3 /mnt/c

# 6) Limpeza
sudo umount /mnt/{a,b,c}
sudo losetup -d /dev/loop0
rm ~/disco.img
```

**Desafios sugeridos para fixar:**

1. Refaça com **MBR** (`o` no fdisk) e crie 3 primárias + 1 estendida com 2 lógicas. Observe a numeração (`5`, `6`).
2. Converta o disco MBR para GPT com `gdisk` e compare o `fdisk -l` antes e depois.
3. Crie um Btrfs **raid1** com dois arquivos `.img` em dois loop devices e monte com `compress=zstd`.
4. Aumente o XFS com `xfs_growfs` após estender o arquivo (`truncate -s +500M`), `losetup -c` e `parted resizepart`.

## 21. Armadilhas e pontos mais cobrados no exame

### Particionamento

- [ ] **MBR:** 4 primárias; estendida é contêiner; lógicas começam em **5**; limite de **2 TiB**.
- [ ] **GPT:** 128 partições padrão; **sem** primária/estendida/lógica; **cópia de backup** no fim do disco; **protective MBR** (tipo `ee`).
- [ ] `fdisk`: grava só com **`w`**; `q` descarta; `g` = GPT, `o` = DOS.
- [ ] `parted`: **aplica imediatamente**, sem `w`; o *fs-type* do `mkpart` **não cria** filesystem.
- [ ] `gdisk`: códigos de **4 dígitos** (`8300`, `8200`, `ef00`, `ef02`).
- [ ] IDs MBR: `82` swap, `83` Linux, `8e` LVM, `fd` RAID, `05`/`0f` estendida, `ef` ESP.
- [ ] Particionar **não** cria filesystem: falta o `mkfs`.
- [ ] Alinhamento: início em **2048** (1 MiB).
- [ ] NVMe/MMC/loop: partições com **`p`** (`nvme0n1p1`).
- [ ] Após alterar com disco em uso: `partprobe`/`partx`/reboot.

### Sistemas de arquivos

- [ ] **ext2** sem journal; **ext3** = ext2 + journal; **ext4** = extents + journal + até 1 EiB.
- [ ] **XFS** só **cresce** (`xfs_growfs`), **nunca reduz**; `mkfs.xfs -f` para forçar; repara com `xfs_repair`.
- [ ] **VFAT**: arquivo máx. **4 GiB**, sem permissões; label com **`-n`**; `-F 32`.
- [ ] **exFAT**: sem limite de 4 GiB, para mídia flash; pacote `exfatprogs`.
- [ ] **Btrfs**: CoW, **subvolumes**, **snapshots**, compressão (`compress=zstd|zlib|lzo` na **montagem**), multi-dispositivo com `-d`/`-m`.
- [ ] `mkfs.ext4 -m 1`: reduz os blocos reservados (padrão 5%).
- [ ] Inodes do ext* são fixos na criação; XFS aloca dinamicamente.

### Swap

- [ ] `mkswap` → `swapon`; **não** use `mkfs` para swap.
- [ ] Tipo da partição: `82` (MBR) / `8200` (GPT).
- [ ] Arquivo de swap: `chmod 600`.

## 22. Cola rápida (cheat sheet)

```bash
# ---------- INSPECIONAR ----------
lsblk -f                         # árvore + FS + UUID
fdisk -l /dev/sdb                # tabela de partições
blkid /dev/sdb1                  # UUID, LABEL, TYPE
cat /proc/partitions

# ---------- PARTICIONAR ----------
fdisk /dev/sdb                   # m ajuda | g GPT | o DOS | n | d | t | p | w | q
gdisk /dev/sdb                   # ? ajuda | o | n | d | t | p | w | q
parted /dev/sdb                  # mklabel | mkpart | rm | print (SEM "gravar")
sgdisk -n 1:0:+1G -t 1:8300 /dev/sdb
partprobe /dev/sdb               # relê a tabela

# ---------- CRIAR SISTEMA DE ARQUIVOS ----------
mkfs.ext4  -L rotulo /dev/sdb1
mkfs.xfs   -f -L rotulo /dev/sdb1
mkfs.vfat  -F 32 -n ROTULO /dev/sdb1
mkfs.exfat -L rotulo /dev/sdb1
mkfs.btrfs -L rotulo /dev/sdb1
mkfs -t ext4 /dev/sdb1           # forma genérica

# ---------- SWAP ----------
mkswap /dev/sdb2 && swapon /dev/sdb2
swapon --show ; swapoff /dev/sdb2

# ---------- BTRFS ----------
btrfs subvolume create /mnt/@home
btrfs subvolume snapshot -r /mnt/@home /mnt/@home-snap
mount -o compress=zstd,subvol=@home /dev/sdb1 /home
btrfs device add /dev/sdc /mnt && btrfs balance start /mnt
```

### Tabela-resumo final

| Preciso... | Use |
|---|---|
| Criar tabela GPT | `fdisk` → `g` · `gdisk` → `o` · `parted` → `mklabel gpt` |
| Criar tabela MBR | `fdisk` → `o` · `parted` → `mklabel msdos` |
| Nova partição | `n` (fdisk/gdisk) · `mkpart` (parted) |
| Mudar o tipo | `t` (fdisk/gdisk) · `set N flag on` (parted) |
| Gravar | `w` (fdisk/gdisk) · **automático** (parted) |
| Descartar | `q` (fdisk/gdisk) · **impossível** (parted) |
| Criar ext4 / XFS / FAT32 / exFAT / Btrfs | `mkfs.ext4` / `mkfs.xfs` / `mkfs.vfat -F 32` / `mkfs.exfat` / `mkfs.btrfs` |
| Preparar swap | `mkswap` + `swapon` |
