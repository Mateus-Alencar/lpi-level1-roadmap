## 1. Objetivos e áreas-chave do exame

Segundo o objetivo oficial da LPI, você deve ser capaz de:

- Entender a **localização correta dos arquivos** na hierarquia do sistema de arquivos.
- Saber o que é o **FHS** e a finalidade de cada diretório de primeiro nível.
- Diferenciar **arquivos temporários e de dados variáveis** de arquivos estáticos.
- **Encontrar arquivos e comandos** no sistema.

**Arquivos, termos e utilitários que você precisa dominar:**

| Item | Para que serve |
|---|---|
| `find` | Busca em tempo real, percorrendo diretórios, com muitos filtros |
| `locate` | Busca rápida em um banco de dados pré-indexado |
| `updatedb` | Atualiza o banco de dados usado pelo `locate` |
| `whereis` | Localiza binário, código-fonte e man page de um comando |
| `which` | Mostra qual executável seria rodado (procura no `$PATH`) |
| `type` | Diz *o que é* um comando (alias, builtin, função, arquivo) |
| `/etc/updatedb.conf` | Configuração do `updatedb` |
| `$PATH` | Variável com a lista de diretórios de executáveis |

## 2. FHS – Filesystem Hierarchy Standard

O **FHS** é um padrão (mantido pela Linux Foundation) que define **quais diretórios existem na raiz `/` e o que deve ficar em cada um**. Graças a ele, você sabe que a configuração do sistema está em `/etc` seja numa Debian, Red Hat ou SUSE.

### 2.1 Os dois eixos de classificação

O FHS organiza os arquivos em quatro categorias, cruzando duas perguntas:

|  | **Compartilhável** (pode ser usado por outras máquinas via rede) | **Não compartilhável** (específico da máquina) |
|---|---|---|
| **Estático** (não muda sem intervenção do admin) | `/usr`, `/opt` | `/etc`, `/boot` |
| **Variável** (muda durante a operação normal) | `/var/mail`, `/var/spool/news` | `/var/run`, `/var/lock` |

**Por que isso importa?** Imagine montar `/usr` como somente leitura, ou até compartilhá-lo via NFS entre várias máquinas, porque ele é **estático**. Já `/var` precisa ser **gravável**, pois muda o tempo todo.

### 2.2 Visão geral da árvore

```text
/
├── bin      → comandos essenciais (todos os usuários)
├── boot     → kernel, initrd, bootloader
├── dev      → arquivos de dispositivo
├── etc      → configuração do sistema
├── home     → diretórios dos usuários
├── lib      → bibliotecas essenciais e módulos do kernel
├── media    → pontos de montagem de mídia removível
├── mnt      → montagem temporária manual
├── opt      → software opcional de terceiros
├── proc     → pseudo-FS: processos e kernel
├── root     → home do usuário root
├── run      → dados de runtime desde o boot
├── sbin     → binários essenciais de administração
├── srv      → dados de serviços (web, ftp)
├── sys      → pseudo-FS: dispositivos e drivers
├── tmp      → arquivos temporários
├── usr      → programas e dados compartilháveis (estático)
└── var      → dados variáveis (logs, filas, caches)
```

## 3. Os diretórios em detalhe

### `/bin` e `/sbin`
- **`/bin`**: comandos essenciais, necessários **mesmo em modo monousuário** e usáveis por qualquer usuário. Ex.: `ls`, `cp`, `mv`, `cat`, `bash`.
- **`/sbin`**: binários essenciais de **administração**, normalmente para o root. Ex.: `fdisk`, `fsck`, `mkfs`, `reboot`, `ip`.

> Em distros modernas (Debian 10+, Fedora, RHEL 7+, Ubuntu), `/bin`, `/sbin` e `/lib` são **links simbólicos** para `/usr/bin`, `/usr/sbin` e `/usr/lib`. É o chamado *merged-/usr*. Confira com `ls -ld /bin`.

### `/boot`
Arquivos necessários para a **inicialização**: kernel (`vmlinuz-*`), `initrd`/`initramfs`, e arquivos do GRUB (`/boot/grub` ou `/boot/grub2`). Em sistemas UEFI, a ESP costuma ser montada em `/boot/efi`.

### `/dev`
Arquivos de dispositivo (blocos e caracteres): `/dev/sda`, `/dev/tty`, `/dev/null`, `/dev/zero`, `/dev/random`. Gerenciado dinamicamente pelo **udev**.

### `/etc`
**Configuração do sistema**, específica da máquina e em geral em texto puro. Ex.: `/etc/passwd`, `/etc/fstab`, `/etc/hosts`, `/etc/ssh/sshd_config`. **Não deve conter binários.**

### `/home`
Diretório pessoal dos usuários comuns (`/home/maria`).

### `/lib`, `/lib64`, `/lib32`
Bibliotecas compartilhadas necessárias aos binários de `/bin` e `/sbin`, além dos **módulos do kernel** em `/lib/modules/$(uname -r)/`.

### `/media` e `/mnt`
- **`/media`**: montagem **automática** de mídias removíveis (pendrive, CD). Ex.: `/media/usuario/PENDRIVE`.
- **`/mnt`**: ponto de montagem **temporário, manual**, usado pelo administrador.

### `/opt`
Pacotes de software **opcionais e autocontidos**, normalmente de terceiros (Google Chrome, algumas ferramentas comerciais). Cada pacote costuma ficar em `/opt/<pacote>`.

### `/proc`
**Pseudo-sistema de arquivos** gerado pelo kernel na memória. Mostra processos (`/proc/1234/`) e informações do kernel (`/proc/cpuinfo`, `/proc/meminfo`, `/proc/mounts`). Parâmetros ajustáveis em `/proc/sys`.

### `/root`
Diretório pessoal do **usuário root**. Fica separado de `/home` para que o root consiga logar mesmo se `/home` estiver em outra partição que falhou.

### `/run`
Dados voláteis de **runtime desde o último boot**: PID files, sockets, locks. Fica em `tmpfs` (memória) e é limpo a cada reinicialização. Substituiu `/var/run` e `/var/lock` (que hoje costumam ser links para `/run`).

### `/srv`
Dados servidos pelo próprio sistema: `/srv/www`, `/srv/ftp`.

### `/sys`
**Pseudo-sistema de arquivos (sysfs)** que expõe dispositivos, drivers e estrutura do hardware conforme o kernel os enxerga.

### `/tmp`
Arquivos **temporários**, graváveis por todos (com **sticky bit**: `drwxrwxrwt`). Pode ser limpo na reinicialização ou por rotinas (`systemd-tmpfiles`).

### `/usr`
Segunda grande hierarquia, **estática e compartilhável**. Contém a maior parte do software e dos dados somente leitura:

| Subdiretório | Conteúdo |
|---|---|
| `/usr/bin` | A maioria dos comandos de usuário |
| `/usr/sbin` | Comandos de administração não essenciais ao boot |
| `/usr/lib` | Bibliotecas do software em `/usr/bin` e `/usr/sbin` |
| `/usr/share` | Dados independentes de arquitetura (man pages, docs, ícones, locales) |
| `/usr/include` | Arquivos de cabeçalho C (`.h`) |
| `/usr/src` | Código-fonte (ex.: fontes do kernel) |
| `/usr/local` | Software instalado **localmente pelo admin** (ver seção 10) |

### `/var`
Dados **variáveis**:

| Subdiretório | Conteúdo |
|---|---|
| `/var/log` | Logs do sistema (`/var/log/syslog`, `messages`, `auth.log`) |
| `/var/spool` | Filas (impressão, e-mail, cron) |
| `/var/mail` | Caixas de correio locais |
| `/var/cache` | Caches de aplicações (ex.: pacotes baixados) |
| `/var/lib` | Estado persistente de programas (bancos de dados, dpkg/rpm) |
| `/var/tmp` | Temporários que **persistem entre reinicializações** |
| `/var/www` | Comum para sites (convenção de algumas distros) |

## 4. Distinções que caem na prova

### 4.1 `/tmp` × `/var/tmp`

| | `/tmp` | `/var/tmp` |
|---|---|---|
| Persiste após reboot? | **Não necessariamente** (pode ser limpo) | **Sim**, deve ser preservado |
| Uso | Temporários de curta duração | Temporários que precisam sobreviver |

### 4.2 `/bin` × `/usr/bin` e `/sbin` × `/usr/sbin`

- `/bin` e `/sbin`: o que é necessário para **inicializar e reparar** o sistema (antes de `/usr` estar montado).
- `/usr/bin` e `/usr/sbin`: **todo o resto**.

### 4.3 `/media` × `/mnt`
Automático e para mídia removível (`/media`) × manual e temporário (`/mnt`).

### 4.4 `/proc` × `/sys`
`/proc`: processos + informações gerais do kernel. `/sys`: modelo de **dispositivos e drivers**. Ambos são **virtuais** (não ocupam disco).

### 4.5 `/etc` × `/usr/local/etc` × `/opt`
Configuração do **sistema/distribuição** × configuração de software instalado localmente × software de terceiros autocontido.

### 4.6 Partições que o FHS permite (e o admin separa) como filesystem próprio
`/boot`, `/home`, `/var`, `/tmp`, `/usr`, `/opt`. Já **`/etc`, `/bin`, `/sbin`, `/lib` e `/dev` devem estar no mesmo filesystem da raiz `/`**, pois são necessários para o boot e para montar os demais.

> **Dica de prova:** `/var` costuma ser separado para que logs descontrolados não encham a raiz; `/home` para preservar dados do usuário numa reinstalação.

## 5. Comandos para localizar arquivos

Há duas famílias de busca:

- **Busca em tempo real:** `find` (lê o disco agora; lento, mas sempre atual e muito flexível).
- **Busca indexada:** `locate` (consulta um banco de dados; muito rápido, mas pode estar desatualizado).
- **Busca de comandos:** `which`, `type`, `whereis`.

## 6. `find` em profundidade

**Sintaxe:**
```bash
find [onde procurar] [critérios] [ação]
```

### 6.1 Critérios mais cobrados

| Opção | Significado | Exemplo |
|---|---|---|
| `-name` | Nome (diferencia maiúsc./minúsc.) | `find /etc -name "*.conf"` |
| `-iname` | Nome, **ignorando** caixa | `find . -iname "readme*"` |
| `-type` | Tipo: `f` arquivo, `d` diretório, `l` link, `b`/`c` dispositivos, `s` socket, `p` pipe | `find /dev -type b` |
| `-user` / `-group` | Dono / grupo | `find /home -user maria` |
| `-perm` | Permissões | veja abaixo |
| `-size` | Tamanho | `find / -size +100M` |
| `-mtime` | Modificado há N **dias** | `find . -mtime -7` |
| `-atime` | Acessado há N dias | `find . -atime +30` |
| `-ctime` | **Metadados** alterados há N dias | `find . -ctime -1` |
| `-mmin` / `-amin` / `-cmin` | Igual, mas em **minutos** | `find . -mmin -30` |
| `-newer ARQ` | Mais novo que ARQ | `find . -newer ref.txt` |
| `-empty` | Arquivos/diretórios vazios | `find . -empty` |
| `-maxdepth N` / `-mindepth N` | Limita profundidade | `find . -maxdepth 1` |

### 6.2 Sinais `+`, `-` e número puro (pegadinha clássica)

Para `-mtime`, `-size`, `-perm` etc.:

| Notação | Significado |
|---|---|
| `+7` | **mais de** 7 |
| `-7` | **menos de** 7 |
| `7` | **exatamente** 7 |

```bash
find . -mtime +7     # modificado há MAIS de 7 dias
find . -mtime -7     # modificado nos ÚLTIMOS 7 dias
find . -mtime 7      # modificado exatamente há 7 dias
```

### 6.3 Unidades de `-size`

| Sufixo | Unidade |
|---|---|
| `c` | bytes |
| `k` | KiB |
| `M` | MiB |
| `G` | GiB |
| `b` | blocos de 512 bytes (**padrão** se omitir o sufixo) |

```bash
find / -size +100M          # maior que 100 MiB
find / -size -10k           # menor que 10 KiB
find . -size 0              # tamanho zero
```

### 6.4 `-perm`: três formas

```bash
find . -perm 644     # permissões EXATAMENTE 644
find . -perm -644    # TODAS estas permissões (no mínimo 644)
find . -perm /644    # QUALQUER um destes bits (/ ou +)

find . -perm 6000    # SUID e SGID
```

Procurando arquivos com **SUID** e **SGID** (muito comum em auditoria):

```bash
find / -perm -4000 -type f 2>/dev/null     # SUID
find / -perm -2000 -type f 2>/dev/null     # SGID
find / -perm -u=s -type f 2>/dev/null      # SUID (notação simbólica)
find / -perm -1000 -type d 2>/dev/null     # sticky bit
```

### 6.5 Operadores lógicos

```bash
find . -name "*.log" -o -name "*.txt"          # OU
find . -type f ! -name "*.bak"                 # NÃO (nega)
find . -type f -name "*.sh" -user root         # E (implícito)
find . \( -name "*.jpg" -o -name "*.png" \) -size +1M
```

### 6.6 Ações

| Ação | O que faz |
|---|---|
| `-print` | Imprime o caminho (padrão) |
| `-ls` | Lista em formato longo |
| `-delete` | **Apaga** o que encontrou (cuidado!) |
| `-exec CMD {} \;` | Executa CMD **uma vez por arquivo** |
| `-exec CMD {} +` | Executa CMD **agrupando** vários arquivos |
| `-ok CMD {} \;` | Como `-exec`, mas **pede confirmação** |

```bash
# Mudar permissão de todos os .sh
find . -name "*.sh" -exec chmod +x {} \;

# Pedir confirmação antes de remover
find /tmp -name "*.tmp" -ok rm {} \;

# Versão eficiente (um único rm com vários arquivos)
find /tmp -name "*.tmp" -exec rm {} +

# Alternativa com xargs (tratando espaços nos nomes)
find . -name "*.log" -print0 | xargs -0 gzip
```

> `{}` é substituído pelo nome do arquivo encontrado; `\;` (ou `';'`) encerra o `-exec`.

### 6.7 Silenciando erros de permissão

Ao buscar a partir de `/` como usuário comum, surgem muitos "Permission denied":

```bash
find / -name "sshd_config" 2>/dev/null
```

## 7. `locate`, `updatedb` e `updatedb.conf`

### 7.1 Como funciona

O `locate` **não varre o disco**: consulta um **banco de dados** (geralmente `/var/lib/mlocate/mlocate.db`, ou `/var/lib/plocate/plocate.db` no `plocate`) que é montado pelo **`updatedb`**.

```bash
locate sshd_config
locate -i readme          # ignora maiúsculas/minúsculas
locate -c "*.conf"        # só conta as ocorrências
locate -n 5 passwd        # limita a 5 resultados
locate -e arquivo         # só mostra arquivos que ainda existem
```

### 7.2 Atualizando o banco

```bash
sudo updatedb
```

Normalmente executado **diariamente via cron/systemd timer**. Consequências diretas:

- Arquivo **criado hoje** pode **não aparecer** no `locate` até o próximo `updatedb`.
- Arquivo **apagado** ainda pode aparecer (a menos que use `-e`).

### 7.3 `/etc/updatedb.conf`

Controla **o que NÃO indexar**:

```conf
PRUNE_BIND_MOUNTS="yes"
PRUNEFS="NFS nfs nfs4 proc sysfs tmpfs devpts iso9660 ..."
PRUNENAMES=".git .bzr .hg .svn"
PRUNEPATHS="/tmp /var/spool /media /home/.ecryptfs"
```

| Variável | Função |
|---|---|
| `PRUNEFS` | Tipos de sistemas de arquivos a ignorar |
| `PRUNENAMES` | Nomes de diretórios a ignorar |
| `PRUNEPATHS` | Caminhos a ignorar |
| `PRUNE_BIND_MOUNTS` | Ignora bind mounts |

> Por isso `locate` normalmente **não acha nada em `/tmp`** ou em mídias removíveis.

### 7.4 `locate` × `find`

| | `find` | `locate` |
|---|---|---|
| Velocidade | Lenta | Muito rápida |
| Atualidade | Sempre atual | Depende do `updatedb` |
| Critérios | Nome, dono, perm., tamanho, datas… | **Só o nome/caminho** |
| Executar ações | Sim (`-exec`) | Não |

## 8. `which`, `type`, `whereis`

### 8.1 `which`
Mostra o **caminho do executável** que seria executado, procurando nos diretórios do `$PATH`, na ordem.

```bash
which ls
which -a python3     # mostra TODAS as ocorrências no PATH
```

Limitação: **não enxerga** aliases, funções nem builtins do shell (em muitas distros).

### 8.2 `type`
É um **builtin do bash** que informa **como o shell interpretará** o comando.

```bash
type cd        # cd is a shell builtin
type ll        # ll is aliased to `ls -l'
type ls        # ls is /usr/bin/ls   (ou aliased to ...)
type -a echo   # mostra todas as formas (builtin + arquivo)
type -t cd     # só o tipo: alias | keyword | function | builtin | file
```

### 8.3 `whereis`
Localiza **binário**, **código-fonte** e **man page** de um comando, em locais padrão (não só no `$PATH`).

```bash
$ whereis ls
ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz
```

| Opção | Efeito |
|---|---|
| `-b` | Somente binários |
| `-m` | Somente manuais |
| `-s` | Somente fontes |

### 8.4 A variável `$PATH`

```bash
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin:/sbin
```

- Os diretórios são separados por `:`.
- O shell busca **da esquerda para a direita** e usa o **primeiro** encontrado.
- Por segurança, **evite** colocar `.` (diretório atual) no PATH.

```bash
export PATH=$PATH:/opt/meuapp/bin       # adiciona ao final
export PATH=/opt/meuapp/bin:$PATH       # adiciona ao início (prioridade)
```

## 9. Comparativo geral dos comandos

| Comando | Procura onde? | Tipo de resultado | Vê alias/builtin? | Precisa de índice? |
|---|---|---|---|---|
| `find` | Árvore de diretórios indicada | Qualquer arquivo | Não | Não |
| `locate` | Banco de dados | Qualquer arquivo (só por nome) | Não | **Sim** (`updatedb`) |
| `which` | `$PATH` | Executável | Geralmente não | Não |
| `type` | Contexto do shell | Alias, builtin, função, arquivo | **Sim** | Não |
| `whereis` | Locais padrão | Binário + fonte + man | Não | Não |

## 10. `/usr/local`, `/opt` e software de terceiros

### `/usr/local`
Destinado ao software que **o administrador instala por conta própria** (compilado do código-fonte, scripts locais), **sem interferir** no gerenciador de pacotes. Espelha a estrutura de `/usr`:

```text
/usr/local/bin   /usr/local/sbin   /usr/local/lib
/usr/local/etc   /usr/local/share  /usr/local/src
```

Um `./configure && make && make install` usa, por padrão, o prefixo `/usr/local`.

### `/opt`
Para pacotes **autocontidos** (binários, bibliotecas e configs juntos num único diretório), geralmente de fornecedores externos.

| | `/usr/local` | `/opt` |
|---|---|---|
| Estrutura | Espalhada em `bin`, `lib`, `etc`… | Tudo dentro de `/opt/<pacote>` |
| Típico de | Software compilado pelo admin | Software comercial/terceiros |

## 11. Cenários práticos

**Cenário 1 – Onde está a configuração do SSH?**
```bash
find /etc -name "sshd_config"
locate sshd_config
```

**Cenário 2 – Arquivos de log com mais de 100 MiB**
```bash
find /var/log -type f -size +100M -ls
```

**Cenário 3 – Arquivos alterados nas últimas 24 horas em `/etc`**
```bash
find /etc -type f -mtime -1
```

**Cenário 4 – Auditoria de binários SUID**
```bash
find / -perm -4000 -type f 2>/dev/null
```

**Cenário 5 – Apagar `.tmp` com mais de 30 dias em `/var/tmp`**
```bash
find /var/tmp -type f -name "*.tmp" -mtime +30 -delete
```

**Cenário 6 – Diretórios vazios**
```bash
find /srv -type d -empty
```

**Cenário 7 – `locate` não acha um arquivo recém-criado**
```bash
sudo updatedb
locate meuarquivo
```

**Cenário 8 – O comando `python` abre uma versão inesperada**
```bash
type -a python
which -a python
echo $PATH
```

**Cenário 9 – Achar a man page e o binário de um comando**
```bash
whereis nginx
```

**Cenário 10 – Comprimir logs encontrados, lidando com espaços nos nomes**
```bash
find /var/log -name "*.log" -print0 | xargs -0 gzip
```

## 12. Armadilhas comuns

1. **`-mtime +7` não é "7 dias ou mais"**: é **estritamente mais de 7** (o valor é arredondado para baixo em dias inteiros).
2. **`-size +100M`** arredonda **para cima** em unidades de 1M; use `c` para precisão em bytes.
3. **`locate` desatualizado**: arquivos novos/removidos só refletem após `updatedb`.
4. **`locate` ignora `/tmp` e mídias** por causa do `updatedb.conf`.
5. **`which` ≠ `type`**: `which` só olha o `$PATH`; `type` considera alias, função e builtin.
6. **`-name` é case-sensitive**; use `-iname`.
7. **Aspas no `-name`**: `find . -name *.txt` pode ter o glob expandido pelo shell *antes* do `find`. Use `"*.txt"`.
8. **`-delete` antes dos filtros** pode apagar tudo; coloque `-delete` por **último**.
9. **`/run` × `/var/run`**: o moderno é `/run`; `/var/run` é só um link.
10. **`/etc`, `/bin`, `/sbin`, `/lib`, `/dev` não podem estar em partição separada** da raiz.
11. **`/tmp` × `/var/tmp`**: só `/var/tmp` garante persistência entre boots.
12. **`/mnt` × `/media`**: manual × automático.

## 13. Cheat sheet final

```bash
# FHS rápido
/etc        → configuração
/var/log    → logs
/boot       → kernel e bootloader
/dev        → dispositivos
/proc /sys  → pseudo-FS (kernel/hardware)
/home /root → homes
/usr/local  → software do admin
/opt        → software de terceiros
/tmp        → temp (pode sumir)  |  /var/tmp → temp (persiste)
/media      → mídia automática   |  /mnt → montagem manual

# Busca
find /caminho -name "x"              # por nome
find / -type f -size +100M           # por tamanho
find . -mtime -7                     # alterado nos últimos 7 dias
find / -perm -4000                   # SUID
find . -name "*.sh" -exec chmod +x {} \;
locate -i nome                       # rápido (usa índice)
sudo updatedb                        # atualiza o índice
which -a cmd                         # onde no PATH
type -a cmd                          # alias/builtin/arquivo
whereis cmd                          # bin + man + fonte
```

```bash
$ whereis -b python3
python3: /usr/bin/python3 /usr/local/bin/python3
$ echo $PATH
/usr/bin:/bin:/usr/local/bin:/usr/sbin
```  

Qual alternativa explica corretamente a situação e indica a forma de verificar todas as resoluções possíveis do nome (incluindo aliases e funções) na ordem em que o shell as considera?
