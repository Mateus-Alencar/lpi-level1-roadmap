# 101.3 Alternar runlevels/boot targets, desligar e reiniciar o sistema  

## 1. systemd

### 1.1 Target padrão e consulta

| Comando | O que faz |
| :--- | :--- |
| `systemctl get-default` | Mostra o target padrão de boot |
| `systemctl set-default multi-user.target` | Define o target padrão |
| `systemctl list-units` | Lista unidades **carregadas** (ativas por padrão) |
| `systemctl list-units --all` | Lista também as inativas |
| `systemctl list-units --type=target` | Filtra por tipo (service, target, socket, timer...) |
| `systemctl list-unit-files` | Lista **arquivos** de unidade e seu estado (enabled, disabled, masked, static) |
| `systemctl list-dependencies <unidade>` | Mostra a árvore de dependências |
| `systemctl is-active <unidade>` | Diz se está rodando agora |
| `systemctl is-enabled <unidade>` | Diz se inicia no boot |
| `systemctl is-failed <unidade>` | Diz se a unidade falhou |

> **Atenção:** `is-active` (rodando agora) e `is-enabled` (inicia no boot) são independentes. Um serviço pode estar *enabled* e *inactive*.

### 1.2 Ações sobre serviços

| Comando | O que faz |
| :--- | :--- |
| `systemctl reload <svc>` | Pede ao serviço que releia a configuração, **sem reiniciar** o processo |
| `systemctl restart <svc>` | Para e inicia de novo |
| `systemctl enable --now <svc>` | Habilita no boot **e** inicia agora |
| `systemctl disable --now <svc>` | Desabilita no boot **e** para agora |
| `systemctl mask <svc>` | Impede qualquer início (cria link para `/dev/null`) |
| `systemctl unmask <svc>` | Remove o bloqueio |
| `systemctl daemon-reload` | Relê os arquivos de unidade após editá-los |

**`disable` x `mask`:**
- `disable` só remove o início automático no boot. O serviço ainda pode ser iniciado manualmente ou por dependência.
- `mask` bloqueia totalmente. Nem manualmente nem por dependência a unidade sobe.

### 1.3 Desligar e reiniciar via systemctl

| Comando | Efeito |
| :--- | :--- |
| `systemctl poweroff` | Desliga |
| `systemctl reboot` | Reinicia |
| `systemctl halt` | Para o sistema (CPU parada, pode não cortar a energia) |
| `systemctl suspend` | Suspende para a memória RAM |
| `systemctl hibernate` | Hiberna para o disco |

### 1.4 Diretórios das unidades e precedência

Do **maior** para o **menor** precedência:

| Ordem | Diretório | Uso |
| :---: | :--- | :--- |
| 1 | `/etc/systemd/system/` | Configurações do administrador (vencem todas) |
| 2 | `/run/systemd/system/` | Unidades geradas em tempo de execução (somem no reboot) |
| 3 | `/lib/systemd/system/` ou `/usr/lib/systemd/system/` | Unidades instaladas pelos pacotes |

- O `default.target` é um **link simbólico** em `/etc/systemd/system/default.target`, apontando para o target padrão.
- Para sobrescrever parte de uma unidade sem copiar o arquivo inteiro: `systemctl edit <unidade>` (cria um *drop-in* em `/etc/systemd/system/<unidade>.d/override.conf`).

## 2. Mudar o target/runlevel NO BOOT (cai bastante)

Útil para recuperar sistema (senha de root perdida, serviço travando o boot).

### 2.1 No GRUB

1. Na tela do GRUB, selecione a entrada e aperte **`e`** (editar).
2. Vá até a linha que começa com `linux` (ou `linux16` / `linuxefi`).
3. Adicione no **final** da linha o parâmetro desejado.
4. Boot com **Ctrl+X** (ou F10). A alteração vale **só para este boot**.

### 2.2 Parâmetros

| Parâmetro | Resultado |
| :--- | :--- |
| `systemd.unit=rescue.target` | Boot em modo de resgate |
| `systemd.unit=emergency.target` | Boot em modo de emergência |
| `systemd.unit=multi-user.target` | Modo texto multiusuário |
| `systemd.unit=graphical.target` | Modo gráfico |
| `single`, `s`, `S` ou `1` | Single-user (compatibilidade SysV) |
| `emergency` | Atalho para o emergency.target |
| `3` ou `5` | Número do runlevel (compatibilidade SysV) |

> **Dica de prova:** o parâmetro é passado à **linha do kernel**, não ao `/etc/inittab` nem ao `systemctl`.

## 3. SysVinit

### 3.1 Descobrir e trocar o runlevel

| Comando | Função |
| :--- | :--- |
| `runlevel` | Mostra runlevel **anterior** e **atual** (ex: `N 5`) |
| `who -r` | Também mostra o runlevel atual |
| `init 3` | Muda para o runlevel 3 |
| `telinit 3` | Idem (`telinit` é um link para o `init`) |
| `init 0` | Desliga |
| `init 6` | Reinicia |
| `telinit q` (ou `Q`) | Manda o init **reler** o `/etc/inittab` |
| `telinit u` | Re-executa o próprio init |

> A saída `N 5` significa: **N** = não há runlevel anterior (acabou de dar boot), **5** = runlevel atual.

### 3.2 Formato do `/etc/inittab`

```
id:runlevels:ação:processo
```

| Campo | Significado |
| :--- | :--- |
| `id` | Identificador único da linha (1 a 4 caracteres) |
| `runlevels` | Runlevels em que a linha vale (ex: `2345`) |
| `ação` | Como o init trata o processo |
| `processo` | Comando a executar |

**Ações principais:**

| Ação | Comportamento |
| :--- | :--- |
| `initdefault` | Define o **runlevel padrão** (campo `processo` fica vazio) |
| `sysinit` | Executada durante o boot, antes de qualquer runlevel |
| `wait` | Executa e **espera terminar** ao entrar no runlevel |
| `once` | Executa uma vez, sem esperar |
| `respawn` | **Reinicia** o processo se ele terminar (ex: `getty`) |
| `ctrlaltdel` | Executada ao pressionar Ctrl+Alt+Del |
| `powerfail` | Executada quando há falha de energia |

**Exemplos:**

```
id:3:initdefault:
l3:3:wait:/etc/rc.d/rc 3
1:2345:respawn:/sbin/mingetty tty1
ca::ctrlaltdel:/sbin/shutdown -r now
```

## 4. Desligamento e reinício (comandos tradicionais)

### 4.1 Opções do `shutdown`

```
shutdown [opções] [horário] [mensagem]
```

| Opção | Efeito |
| :--- | :--- |
| `-h` | Desliga (halt/poweroff, conforme o sistema) |
| `-H` | Para (halt) sem necessariamente cortar a energia |
| `-P` | Desliga cortando a energia (poweroff) |
| `-r` | Reinicia |
| `-k` | **Só envia o aviso**, não desliga de fato |
| `-c` | Cancela um desligamento agendado |
| `--no-wall` | Não envia a mensagem aos usuários |

**Formatos de horário:**

| Formato | Significado |
| :--- | :--- |
| `now` | Imediatamente |
| `+m` | Daqui a *m* minutos (ex: `+15`) |
| `hh:mm` | Horário exato, 24h (ex: `23:30`) |

**Exemplos:**

```bash
shutdown -h now
shutdown -r +10 "Reinício para atualização"
shutdown -h 23:30
shutdown -k +5 "Teste de aviso"   # só avisa
shutdown -c                        # cancela
```

### 4.2 Sem opções

- Em sistemas SysV antigos, `shutdown` sem `-h` ou `-r` levava ao **single-user**.
- Em sistemas atuais com systemd, o padrão costuma ser **desligar** (poweroff).
- Na prova, sempre use `-h` ou `-r` explicitamente nos exemplos.

### 4.3 `/etc/nologin`

- Quando faltam **menos de 5 minutos** para o desligamento, o sistema cria o arquivo `/etc/nologin`.
- Enquanto ele existir, **usuários comuns não conseguem logar** (root ainda consegue).
- É removido ao cancelar (`shutdown -c`) ou no reboot.

### 4.4 Comandos diretos

| Comando | Efeito |
| :--- | :--- |
| `halt` | Para o sistema |
| `poweroff` (ou `halt -p`) | Desliga e corta a energia |
| `reboot` | Reinicia |

> Em sistemas com systemd, `halt`, `poweroff` e `reboot` são **links simbólicos para o `systemctl`**.

### 4.5 `wall`

```bash
wall "O sistema será reiniciado em 5 minutos"
```

Envia a mensagem para o terminal de todos os usuários logados.

## 5. Upstart

| Comando | Função |
| :--- | :--- |
| `initctl list` | Lista todos os jobs e seus estados |
| `initctl start <job>` | Inicia um job |
| `initctl stop <job>` | Para um job |
| `initctl restart <job>` | Reinicia um job |
| `initctl status <job>` | Mostra o estado do job |
| `initctl reload-configuration` | Relê os arquivos em `/etc/init/` |
| `initctl emit <evento>` | Dispara um evento manualmente |

- **Runlevel padrão** no Upstart: variável `DEFAULT_RUNLEVEL` em `/etc/init/rc-sysinit.conf`.
- Arquivos `.conf` em `/etc/init/` definem os jobs, com linhas como `start on runlevel [2345]` e `stop on runlevel [!2345]`.
- Para desativar um job sem apagar o `.conf`, use um arquivo `.override` com a palavra `manual`.
- O Upstart é **transicional** e mantém compatibilidade com scripts SysV, sem ser total.

## 6. Terminar processos corretamente


### 6.1 Sinais

| Número | Nome | Efeito |
| :---: | :--- | :--- |
| 1 | `SIGHUP` | Hangup. Muitos daemons **releem a configuração** |
| 2 | `SIGINT` | Interrupção (Ctrl+C) |
| 9 | `SIGKILL` | Mata **à força**. Não pode ser ignorado nem tratado |
| 15 | `SIGTERM` | Pedido de término **educado** (padrão do `kill`) |
| 18 | `SIGCONT` | Retoma um processo parado |
| 19 | `SIGSTOP` | Pausa o processo (não pode ser ignorado) |
| 20 | `SIGTSTP` | Pausa pelo terminal (Ctrl+Z) |

> **Boa prática:** tente primeiro `SIGTERM` (15) para o processo encerrar limpo. Use `SIGKILL` (9) apenas se ele não responder.

### 6.2 Comandos

| Comando | Como seleciona | Exemplo |
| :--- | :--- | :--- |
| `kill` | Por **PID** | `kill -15 1234` ou `kill -SIGTERM 1234` |
| `killall` | Pelo **nome exato** do processo | `killall nginx` |
| `pkill` | Por **padrão** de nome ou outros critérios | `pkill -u joao firefox` |
| `pgrep` | Só **lista** os PIDs (não mata) | `pgrep -l ssh` |

```bash
kill -l              # lista todos os sinais
kill 1234            # envia SIGTERM (15) por padrão
kill -9 1234         # SIGKILL
kill -HUP 1234       # SIGHUP, releitura de configuração
killall -9 nginx
pkill -f "python app.py"
```

## 7. Pegadinhas frequentes

1. **`systemctl reload` x `restart`:** `reload` não derruba o processo, `restart` derruba.
2. **`enable` não inicia o serviço agora.** Use `enable --now` ou `start`.
3. **`disable` não impede início manual.** Só `mask` impede.
4. **Runlevel 2 no Debian/Ubuntu** é multiusuário **com rede**. Nos Red Hat clássicos, é sem rede.
5. **Runlevel 4** é "não usado" por padrão.
6. **`/etc/init.d/`** (scripts SysV) é diferente de **`/etc/init/`** (jobs do Upstart).
7. **Links em `rcX.d`:** prefixo `K` = parar, `S` = iniciar. Os números definem a ordem.
8. **`shutdown -k`** só avisa, não desliga.
9. **`telinit q`** relê o `/etc/inittab`, não muda de runlevel.
10. **Parâmetros de boot** vão na linha do **kernel** no GRUB e valem só para aquele boot.

## 9. Cola rápida

```bash
# =========================================================
# systemd
# Arquivos principais:
#   /lib/systemd/system/         (ou /usr/lib/systemd/system/) unidades instaladas por pacotes
#   /etc/systemd/system/         unidades e overrides do administrador (maior prioridade)
#   /run/systemd/system/         unidades geradas em tempo de execução (somem no reboot)
#   /etc/systemd/system/default.target   link simbólico para o target padrão
#   /etc/systemd/system/<target>.wants/  links criados pelo "systemctl enable"
#   /etc/systemd/system/<unidade>.d/override.conf  drop-in criado por "systemctl edit"
# Prioridade: /etc > /run > /lib
# =========================================================
systemctl get-default                # mostra o target padrão de boot
systemctl set-default multi-user.target   # define o target padrão (vale a partir do próximo boot)
systemctl isolate rescue.target      # muda para o target agora (temporário, só nesta sessão)
systemctl enable --now sshd          # habilita no boot E inicia agora
systemctl mask <svc>                 # bloqueia qualquer início (link para /dev/null)
systemctl daemon-reload              # relê os arquivos de unidade após editá-los

# =========================================================
# SysVinit
# Arquivos principais:
#   /etc/inittab        runlevel padrão (initdefault) e processos do init
#   /etc/init.d/        scripts reais dos serviços (start|stop|restart|status)
#   /etc/rc0.d ... /etc/rc6.d/   links simbólicos para os scripts (S = start, K = kill, 00-99 = ordem)
#   /etc/rc.d/ (famílias Red Hat) pode conter o init.d e os rcX.d
# Formato do inittab: id:runlevels:ação:processo
# =========================================================
runlevel          # mostra runlevel anterior e atual (ex: N 5, onde N = sem anterior)
who -r            # também mostra o runlevel atual
init 3 / telinit 3   # muda para o runlevel 3 agora (init 0 desliga, init 6 reinicia)
telinit q         # manda o init reler o /etc/inittab (não muda de runlevel)

# =========================================================
# Desligar/reiniciar
# Arquivo relacionado:
#   /etc/nologin    criado nos últimos 5 min do shutdown; bloqueia login de usuários comuns
# =========================================================
shutdown -h now                  # desliga imediatamente
shutdown -r +10 "mensagem"       # reinicia em 10 minutos e avisa os usuários logados
shutdown -c                      # cancela um desligamento agendado
halt / poweroff / reboot         # para o sistema / desliga cortando energia / reinicia
                                 # (com systemd são links simbólicos para o systemctl)

# =========================================================
# Upstart
# Arquivos principais:
#   /etc/init/*.conf                  definição dos jobs (não confundir com /etc/init.d/)
#   /etc/init/*.override              sobrescreve um job (ex: "manual" desativa o início)
#   /etc/init/rc-sysinit.conf         variável DEFAULT_RUNLEVEL (runlevel padrão)
# Compatível com os scripts do SysV (/etc/init.d/ e rcX.d)
# =========================================================
initctl list                     # lista todos os jobs e seus estados
initctl reload-configuration     # relê os arquivos de /etc/init/

# =========================================================
# Processos
# Sinais: 1 = SIGHUP (relê configuração), 9 = SIGKILL (à força), 15 = SIGTERM (padrão, educado)
# =========================================================
kill -15 PID                     # pede o término do processo de forma limpa (SIGTERM)
kill -9 PID                      # mata à força, sem chance de tratar o sinal (SIGKILL)
killall nome                     # envia sinal a todos os processos com esse nome exato
pkill -u usuario padrao          # envia sinal aos processos do usuário cujo nome casa com o padrão
```

## Exercícios

#### Ex.1  
Um administrador de sistemas instalou o servidor web Apache e deseja criar uma configuração customizada para o arquivo de unidade apache2.service. Para garantir que as alterações feitas manualmente pelo administrador não sejam sobrescritas durante as futuras atualizações de pacotes do sistema operacional, em qual diretório o arquivo customizado ou o seu override deve ser armazenado?  
A) /usr/lib/systemd/system/  
B) /etc/systemd/system/  
C) /run/systemd/system/  
D) /etc/init/  
E) /etc/init.d/  

Alternativa B  
O diretório `/etc/systemd/system/` possui a prioridade máxima no systemd e é reservado estritamente para as configurações locais criadas pelo administrador. Arquivos colocados aqui nunca são sobrescritos por gerenciadores de pacotes (como `apt` ou `yum`).

#### Ex.2  
Ao habilitar um serviço para iniciar automaticamente durante o boot em uma distribuição Linux moderna que utiliza o systemd através do comando systemctl enable service_name, o gerenciador cria um link simbólico apontando para o arquivo de unidade original.  
Informe o caminho absoluto do diretório principal de configuração mantido pelo administrador onde esse link simbólico (ou os arquivos locais criados pelo usuário) será gerado. (Forneça apenas o caminho completo do diretório).  
Resposta: `/etc/systemd/system/`  
Explicação:
Quando você executa o comando systemctl enable, o systemd cria pastas com a extensão .wants (ex: multi-user.target.wants) e coloca os links simbólicos diretamente dentro do diretório de configurações locais, que é o `/etc/systemd/system/`  

#### Ex.3  
Um administrador precisa alterar permanentemente o comportamento de inicialização de um servidor Linux que utiliza o systemd. Atualmente, o sistema inicializa direto na interface gráfica (antigo Runlevel 5), mas o objetivo é que, a partir do próximo boot, ele carregue por padrão apenas em modo texto multiusuário (antigo Runlevel 3).  
Qual comando nativo do systemd realiza essa alteração de forma persistente?  
A) systemctl isolate multi-user.target  
B) systemctl set-default multi-user.target  
C) telinit 3D) systemctl default graphical.target  
E) init 3  

Alternativa: B  

O comando `systemctl isolate multi-user.target` altera o estado do sistema imediatamente na sessão atual (em tempo de execução). Porém, o enunciado pediu para alterar o comportamento de forma permanente/persistente para o próximo boot.
- Mudança agora (temporária) → isolate  
- Mudança para o próximo boot (permanente) → set-default  

#### Ex. 4
Em um sistema SysVinit, o diretório `/etc/rc3.d/` contém os links `S08iptables`, `S20postfix`, `S55sshd` e `K15httpd`. Quais afirmações são corretas? (Escolha DUAS.)  
A) `S08iptables` é executado antes de `S20postfix` ao entrar no runlevel 3.  
B) `K15httpd` inicia o serviço `httpd` ao entrar no runlevel 3.  
C) Os links com prefixo `S` recebem o argumento `start` e os com prefixo `K` recebem o argumento `stop`.  
D) Os números nos nomes não influenciam a ordem de execução, apenas identificam o serviço.  
E) Os arquivos de `/etc/rc3.d/` são os scripts reais dos serviços.  

Resposta: A C  
> Explicação: O número define a ordem: valores menores executam primeiro. O prefixo `K` (Kill) interrompe o serviço e o `S` (Start) o inicia, e o script de `/etc/init.d/` recebe o argumento correspondente. Os arquivos em `rcX.d` são apenas links simbólicos.

#### Ex. 5
Sobre `rescue.target` e `emergency.target` no systemd, quais afirmações são corretas? (Escolha DUAS.)  
A) O `emergency.target` monta apenas o sistema de arquivos raiz (`/`), em modo somente leitura.  
B) O `rescue.target` monta os sistemas de arquivos locais e inicia apenas serviços básicos.  
C) O `emergency.target` inicia os serviços de rede.  
D) O `rescue.target` é equivalente ao runlevel 5.  
E) O `emergency.target` desliga o sistema.  

Resposta: A B

#### Questão 6  
Questão aberta: um servidor systemd está em modo gráfico. O administrador quer passar para o modo texto multiusuário **agora** e também garantir que o sistema inicie em modo texto **nos próximos boots**. Quais dois comandos ele deve executar?   

Resposta:  
`systemctl isolate multi-user.target` (muda o estado atual, de forma temporária)  
`systemctl set-default multi-user.target` (altera o `default.target`, valendo a partir do próximo boot)
