# 101.3 Alternar runlevels/boot targets, desligar e reiniciar o sistema

Os gerenciadores de serviços controlam como o Linux inicializa, gerencia processos em segundo plano (**daemons**) e desliga o sistema.

---

## 1. O que são Serviços do Sistema

* **Definição:** Processos que rodam em segundo plano (**daemons**) sem interação direta do usuário na tela. (ex: `sshd`, `httpd`, `cron`).
* **Papel:** Fornecer funcionalidades contínuas ao sistema (como servidores web, acesso remoto SSH, agendamento de tarefas e gerenciamento de rede).

---

## 2. Entendendo os Runlevels (Níveis de Execução)

Os **runlevels** representam o estado operacional de um sistema operacional baseado em Unix/Linux. Cada nível define quais serviços e daemons devem ser iniciados ou finalizados automaticamente.

### Tabela de Equivalência de Estados

| Runlevel | Nome / Estado Clássico | Mapeamento no systemd |
| :--- | :--- | :--- |
| **0** | Desligamento (Halt) | `poweroff.target` |
| **1 / S** | Modo de usuário único (Single-user / Resgate) | `rescue.target` |
| **2** | Modo multiusuário sem rede (Debian/Ubuntu usam com rede) | `multi-user.target` |
| **3** | Modo multiusuário em texto com rede (Padrão servidores) | `multi-user.target` |
| **4** | Não utilizado / Customizável pelo usuário | `multi-user.target` |
| **5** | Modo multiusuário gráfico (Padrão Desktops) | `graphical.target` |
| **6** | Reinicialização (Reboot) | `reboot.target` |

## 3. Tabela Comparativa de Comandos

| Ação no Serviço | SysVinit | systemd | Upstart |

| **Interromper** | `service nginx stop` | `systemctl stop nginx` | `stop nginx` |

## 4. SysVinit (Abordagem Tradicional e Sequencial)

O SysVinit é baseado puramente em runlevels. O comportamento e os serviços do sistema são totalmente ditados por eles, executados em uma ordem numérica rígida através de scripts shell sequenciais.

* **`/etc/inittab`:** Arquivo principal de configuração. Define o runlevel padrão (`id:3:initdefault:`) e quais processos o `init` deve gerar.
* **`init`:** O primeiro processo do sistema (PID = 1), pai de todos os outros processos.
* **`telinit`:** Comando utilizado pelo administrador para alterar o runlevel do sistema em tempo de execução (ex: `telinit 3`).

### Estrutura de Scripts e Links Simbólicos do SysVinit

#### O Diretório `/etc/init.d/`
* Contém os scripts shell originais de inicialização, parada e controle de todos os serviços instalados no sistema.
* Cada script aceita argumentos padrão como `start`, `stop`, `restart` e `status`.

#### Os Diretórios `rcX.d`
Para cada runlevel, existe um diretório correspondente localizado em `/etc/rc0.d/`, `/etc/rc1.d/`, `/etc/rc2.d/`, etc. 

* Esses diretórios **não contêm scripts reais**, apenas **links simbólicos** que apontam para os scripts originais dentro de `/etc/init.d/`.
* A nomenclatura desses links segue um padrão estrito que determina a ordem de execução:

$$\text{[Prefixo S ou K]} + \text{[Número de 00 a 99]} + \text{[Nome do Serviço]}$$

* **Prefixo K (Kill):** Indica que o serviço deve ser **interrompido** ao entrar neste runlevel.
* **Prefixo S (Start):** Indica que o serviço deve ser **iniciado** ao entrar neste runlevel.
* **Numeração (00-99):** Define a prioridade e ordem de execução. Números menores (ex: `S10`) executam antes de números maiores (ex: `S90`).

*Exemplo prático:* O link `/etc/rc3.d/S20ssh` aponta para `/etc/init.d/ssh`. Ele indica que, ao entrar no modo texto com rede (Runlevel 3), o serviço SSH deve ser iniciado com prioridade 20.

## 5. systemd (Padrão Moderno e Paralelo)

Substituiu o SysVinit na maioria das distribuições modernas. Substituiu os runlevels pelo conceito de **Targets** (alvos `.target`) e foca na inicialização paralela usando **Units** (unidades). Ele mantém mapeamento e compatibilidade retroativa com os runlevels clássicos e com os scripts do `/etc/init.d/`.

* **`systemctl`:** O comando central de gerenciamento.
* **/etc/systemd/system**: Armazena as unidades criadas pelo administrador do sistema e os links simbólicos gerados pelo comando `systemctl enable`  
* **Sintaxe padrão:** `systemctl [ação] [unidade/serviço]` (ex: `systemctl status sshd`).
* **Gerenciamento de Targets (Estados do Sistema):**
  * Alterar para modo texto (antigo runlevel 3): `systemctl isolate multi-user.target`
  * Alterar para modo gráfico (antigo runlevel 5): `systemctl isolate graphical.target`
  * Definir o alvo padrão de boot: `systemctl set-default multi-user.target`
* O systemd monitora processos usando **cgroups** do Linux, garantindo que ao parar um determinado serviço, todos os processos que tenham sido iniciados por ele sejam finalizados.

**Exemplo de exeução**: Quando você executa `systemctl enable sshd`, o systemd cria um link simbólico dentro de `/etc/systemd/system/multi-user.target.wants/` apontando para o arquivo original em `/lib/systemd/system/sshd.service`  


| Comando Completo | Target do Systemd | Descrição / Objetivo | Equivalente SysVinit |
| :--- | :--- | :--- | :--- |
| `systemctl isolate graphical.target` | `graphical.target` | Inicia a interface gráfica completa com suporte a rede e múltiplos usuários. | Runlevel 5 |
| `systemctl isolate multi-user.target` | `multi-user.target` | Modo de texto padrão para múltiplos usuários com rede ativa, sem interface gráfica. | Runlevel 3 |
| `systemctl isolate rescue.target` | `rescue.target` | Modo de socorro básico. Monta sistemas de arquivos e inicia um shell de root (pede senha). | Runlevel 1 / Single |
| `systemctl isolate emergency.target` | `emergency.target` | Modo de emergência mais cru. Monta o root como leitura e não inicia serviços de rede. | - |
| `systemctl isolate poweroff.target` | `poweroff.target` | Desliga o sistema completamente. | Runlevel 0 |
| `systemctl isolate reboot.target` | `reboot.target` | Reinicia a máquina. | Runlevel 6 |

## 6. Upstart (Transição Baseada em Eventos)

Criado pela Ubuntu para resolver a lentidão do SysVinit, o Upstart funciona de forma transicional. Ele substituiu a lógica pura de runlevels por **eventos** de hardware e software de forma assíncrona (ex: "placa de rede conectada"), mas **mantém compatibilidade total** com os comandos do SysVinit e com os diretórios `rcX.d`.

* **`/etc/init/`:** Diretório que armazena os arquivos de configuração de tarefas e serviços (arquivos `.conf`). *Não confundir com o antigo `/etc/init.d/`*.
* **`initctl`:** Utilitário principal de controle do Upstart.
* **Comandos nativos:** Permite atalhos diretos no terminal como `start`, `stop`, `restart` e `status` (comandos independentes que interagem com o Upstart).

---

## 7. Gerenciamento do Sistema e Desligamento

Comandos tradicionais e universais usados para interromper o hardware e gerenciar o estado da máquina de forma segura.

* **`shutdown`:** Desliga ou reinicia o sistema, notificando os usuários conectados e impedindo novos logins.
  * Desligar imediatamente: `shutdown -h now`
  * Reiniciar imediatamente: `shutdown -r now`
  * Agendar o desligamento com uma mensagem de aviso: `shutdown +10 "Manutenção no servidor"`
  * Cancelar um desligamento agendado: `shutdown -c`
* **`wall`:** Abreviação de *write all*. Envia uma mensagem de texto diretamente para o terminal (TTY) de **todos os usuários** logados no momento (ex: `wall "O sistema será reiniciado em 5 minutos"`).


## Exercícios

#### Ex.1  
Um administrador de sistemas instalou o servidor web Apache e deseja criar uma configuração customizada para o arquivo de unidade apache2.service. Para garantir que as alterações feitas manualmente pelo administrador não sejam sobrescritas durante as futuras atualizações de pacotes do sistema operacional, em qual diretório o arquivo customizado ou o seu override deve ser armazenado?  
A) /usr/lib/systemd/system/  
B) /etc/systemd/system/  
C) /run/systemd/system/  
D) /etc/init/  
E) /etc/init.d/  

Alternativa B  
O diretório `/etc/systemd/system/` possui a prioridade máxima no systemd e é reservado estritamente para as configurações locais criadas pelo administrador. Arquivos colocados aqui nunca são sobrescritos por gerenciadores de pacotes (como `apt` ou `yum`).

#### Ex.2  
Ao habilitar um serviço para iniciar automaticamente durante o boot em uma distribuição Linux moderna que utiliza o systemd através do comando systemctl enable service_name, o gerenciador cria um link simbólico apontando para o arquivo de unidade original.  
Informe o caminho absoluto do diretório principal de configuração mantido pelo administrador onde esse link simbólico (ou os arquivos locais criados pelo usuário) será gerado. (Forneça apenas o caminho completo do diretório).  
Resposta: `/etc/systemd/system/`  
Explicação:
Quando você executa o comando systemctl enable, o systemd cria pastas com a extensão .wants (ex: multi-user.target.wants) e coloca os links simbólicos diretamente dentro do diretório de configurações locais, que é o `/etc/systemd/system/`  

#### Ex.3  
Um administrador precisa alterar permanentemente o comportamento de inicialização de um servidor Linux que utiliza o systemd. Atualmente, o sistema inicializa direto na interface gráfica (antigo Runlevel 5), mas o objetivo é que, a partir do próximo boot, ele carregue por padrão apenas em modo texto multiusuário (antigo Runlevel 3).  
Qual comando nativo do systemd realiza essa alteração de forma persistente?  
A) systemctl isolate multi-user.target  
B) systemctl set-default multi-user.target  
C) telinit 3D) systemctl default graphical.target  
E) init 3  

Alternativa: B  

O comando `systemctl isolate multi-user.target` altera o estado do sistema imediatamente na sessão atual (em tempo de execução). Porém, o enunciado pediu para alterar o comportamento de forma permanente/persistente para o próximo boot.
- Mudança agora (temporária) → isolate  
- Mudança para o próximo boot (permanente) → set-default
