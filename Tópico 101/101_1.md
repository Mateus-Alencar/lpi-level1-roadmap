# 101.1 Determinar e configurar as definições de hardware

## Conceitos  

**Kernel**: núcleo central do sistema operacional Linux. Atua como ponte entre o hardware e os softwares/aplicativos.

Principais funções:
- Gerenciamento de processos
- Gerenciamento da memória RAM
- Gerenciamento de dispositivos de hardware
- Gerenciamento do sistema de arquivos
- Comunicação entre hardware e software

> [!NOTE]
> O kernel executa em **kernel space**, enquanto os programas do usuário executam em **user space**. Essa separação evita que um erro em um programa comum derrube o sistema inteiro.

**Driver**: software que permite ao kernel controlar um dispositivo de hardware. No Linux, a maioria dos drivers é implementada como **módulos do kernel**, embora alguns venham compilados diretamente dentro do kernel (built-in).

**Módulo**: componente carregável do kernel (arquivo `.ko`) que adiciona funcionalidades sem necessidade de recompilar ou reiniciar o sistema.

Vantagens:
- Economia de memória (só carrega o que é usado)
- Inicialização mais rápida
- Suporte dinâmico a novos dispositivos

> [!NOTE]
> A maioria dos drivers no Linux é módulo. Os desenvolvedores transformam os drivers em módulos, que só entram na memória quando o hardware correspondente é detectado/plugado.

**Daemons (serviços)**: programas executados em segundo plano (background) que realizam tarefas automatizadas ou fornecem funcionalidades sem intervenção do usuário. Não possuem interface gráfica e, geralmente, iniciam automaticamente com o sistema.

### Dispositivos coldplug x hotplug

| Tipo | Definição | Exemplos |
|---|---|---|
| **Coldplug** | Dispositivos que só são detectados durante o boot/inicialização do sistema; não suportam conexão/remoção "a quente". | CPU, RAM, placa-mãe, placas PCI internas mais antigas |
| **Hotplug** | Dispositivos que podem ser conectados/removidos com o sistema ligado, e são detectados dinamicamente pelo kernel + udev. | USB, SATA (com hot-swap), PCMCIA, Thunderbolt |

> [!NOTE]
> É o **udev** quem trata os eventos de hotplug, criando/removendo os arquivos correspondentes em `/dev` em tempo real.

### BIOS x UEFI

| BIOS | UEFI |
|---|---|
| Mais antigo, 16 bits | Mais moderno, 32/64 bits |
| MBR (limite de 4 partições primárias, discos até 2TB) | GPT (suporta discos maiores e mais partições) |
| Boot mais lento | Suporta **Secure Boot** e boot mais rápido |
| Interface em modo texto | Interface gráfica, suporte a mouse |

- Configurações de hardware embutido (placa de som, rede, portas seriais/USB) geralmente são habilitadas/desabilitadas via **BIOS/UEFI Setup** (tecla `Del`, `F2`, `F10`, `F12` dependendo do fabricante).
- No Linux, também é possível consultar/alterar parâmetros em tempo de execução via `/sys` ou ferramentas específicas (ex.: `setpci`).

> [!NOTE]  
> MBR e GPT são formatos de particionamento, é a estrutura que fica gravada no começo do disco dizendo onde cada partição começa e termina. Quem irá realizar o gerenciamento das partições são o `fdisk` ou o `gdisk`   

### Recursos de hardware (endereçamento)

- **IRQ (Interrupt Request)**: canal usado por um dispositivo para "avisar" a CPU que precisa de atenção. Cada dispositivo tradicionalmente usa uma linha de IRQ (0–15 em sistemas antigos; hoje virtualizado via APIC).
- **DMA (Direct Memory Access)**: permite que um dispositivo transfira dados diretamente para a RAM sem passar pela CPU, liberando-a para outras tarefas.
- **Portas de I/O (endereços de E/S)**: faixas de endereço usadas para comunicação entre CPU e dispositivo.
- **Endereço de memória (memory-mapped I/O)**: região de memória reservada para comunicação com o dispositivo.

Esses recursos podem ser consultados em `/proc/interrupts`, `/proc/ioports`, `/proc/dma` (ver tabela abaixo).

### Dispositivos de bloco x caractere

- **Dispositivos de bloco**: armazenamento em massa, leitura/escrita em blocos de dados (discos, partições, pendrives). Ex.: `/dev/sda`, `/dev/nvme0n1`.
- **Dispositivos de caractere**: transmitem dados byte a byte, sem buffer de blocos (teclado, mouse, portas seriais). Ex.: `/dev/tty`, `/dev/random`.

> [!TIP]
> Em `ls -l /dev`, a primeira letra da permissão indica o tipo: `b` = bloco, `c` = caractere.

**sysfs (`/sys`)**: sistema de arquivos virtual que exporta a árvore de dispositivos e drivers do kernel para o user-space (informações sobre hardware detectado, atributos, etc.).

**udev**: gerencia dinamicamente os arquivos em `/dev`, criando/removendo nós de dispositivo conforme eventos de hardware (plug/unplug).

**D-Bus**: barramento de mensagens (IPC) usado para comunicação entre processos e para propagar eventos de hardware/sistema entre aplicações (ex.: um gerenciador de arquivos sendo avisado quando um pendrive é conectado).

### Fluxo de carregamento de um módulo

```
Hardware conectado
        ↓
Kernel detecta o dispositivo
        ↓
udev recebe o evento (via kernel uevent)
        ↓
udev consulta banco de módulos (modules.alias) e aciona modprobe
        ↓
modprobe carrega o módulo necessário (e dependências)
        ↓
Driver controla o dispositivo
        ↓
udev cria o(s) nó(s) em /dev
```

> [!NOTE]
> Quando um dispositivo é detectado, o kernel gera um "uevent"; o udev recebe esse evento e solicita ao `modprobe` o carregamento automático do módulo (e de suas dependências) correspondente, além de criar o arquivo de dispositivo em `/dev`.

## Comandos

| Comando | Função | Opções mais importantes | Exemplo |
|---------|--------|--------------------------|---------|
| `lsmod` | Lista os módulos do kernel atualmente carregados (lê `/proc/modules`). | Sem opções relevantes. | `lsmod` |
| `modinfo` | Exibe informações sobre um módulo (autor, licença, descrição, parâmetros, dependências etc.). | `-p` (parâmetros), `-F <campo>` (mostra só um campo: `author`, `license`, `description`, `depends`, `filename`), `-k <versão>` (consulta módulos de outro kernel). | `modinfo e1000e`<br>`modinfo -p snd_hda_intel` |
| `modprobe` | Carrega módulos resolvendo automaticamente as dependências. Também remove módulos. | `-r` (remove), `-a` (carrega vários), `-v` (verboso), `-n` (simula, dry-run). | `modprobe e1000e`<br>`modprobe -r e1000e` |
| `insmod` | Carrega um módulo `.ko` diretamente, **sem** resolver dependências. | Sem opções importantes. | `insmod ./meu_driver.ko` |
| `rmmod` | Remove um módulo carregado, sem resolver dependências. | `-f` (força remoção), `-v` (verboso). | `rmmod e1000e` |
| `depmod` | Gera/atualiza o arquivo de dependências entre módulos (`modules.dep`). | `-a` (todos os módulos). | `depmod -a` |
| `lspci` | Lista dispositivos conectados ao barramento PCI/PCIe. | `-k` (driver em uso e módulos disponíveis), `-v`/`-vv` (detalhes), `-nn` (IDs numéricos do fabricante/dispositivo). | `lspci`<br>`lspci -k` |
| `lsusb` | Lista dispositivos conectados às portas USB. | `-t` (árvore de barramentos), `-v` (detalhes), `-d <VID:PID>` (filtra por fabricante/dispositivo). | `lsusb`<br>`lsusb -t` |
| `lsblk` | Lista dispositivos de bloco (HDs, SSDs, NVMe, partições, pendrives). | `-f` (+ sistema de arquivos), `-o` (colunas personalizadas), `-a` (inclui vazios), `-p` (caminho completo). | `lsblk`<br>`lsblk -f` |
| `lshw` | Mostra informações detalhadas de todo o hardware da máquina. | `-short` (resumo em tabela), `-class <classe>` (filtra por tipo, ex. `network`, `disk`). | `lshw -short` |
| `dmesg` | Exibe mensagens do buffer do kernel, incluindo detecção de hardware no boot. | `-H` (formato legível), `-w` (acompanha em tempo real, watch), `-T` (timestamps legíveis). | `dmesg \| grep -i usb` |
| `udevadm` | Interage com o sistema udev (consulta e dispara eventos). | `monitor` (observa eventos em tempo real), `info` (mostra atributos de um dispositivo), `trigger` (reenvia eventos). | `udevadm monitor`<br>`udevadm info -a -n /dev/sda` |
| `hwinfo` | Ferramenta (nem sempre pré-instalada) que detalha o hardware por categoria. | `--short` (resumo). | `hwinfo --short` |

## Pastas e Arquivos

| Caminho | Função |
|---|---|
| `/dev` | Arquivos que representam dispositivos de hardware. Criados dinamicamente pelo `udev`. |
| `/proc` | Sistema de arquivos virtual (**procfs**) com informações do kernel e dos processos. |
| `/sys` | Sistema de arquivos virtual (**sysfs**) que representa a árvore de dispositivos do kernel. |
| `/proc/cpuinfo` | Informações da CPU. |
| `/proc/meminfo` | Informações da memória RAM. |
| `/proc/modules` | Lista dos módulos carregados. |
| `/proc/interrupts` | IRQs em uso. |
| `/proc/ioports` | Portas de Entrada/Saída registradas. |
| `/proc/dma` | Canais DMA utilizados. |
| `/proc/bus/usb/` ou `/sys/bus/usb/` | Informações sobre barramento USB (varia conforme o sistema). |
| `/etc/modprobe.conf` | Arquivo antigo de configuração do `modprobe` (algumas distros ainda possuem). |
| `/etc/modprobe.d/` | Diretório atual para configuração persistente dos módulos do kernel (blacklist, opções, aliases). |
| `/etc/modules-load.d/` | Define módulos a serem carregados automaticamente no boot (systemd). |
| `/lib/modules/<versão-do-kernel>/` | Local onde ficam armazenados os módulos (`.ko`) do kernel. |

>[!NOTE]  
> IRQs -> Requisição de interrupção

## Exercícios de Revisão

1. Qual é a diferença entre um dispositivo **coldplug** e um **hotplug**? Dê um exemplo de cada.  
**Resposta**: O coldplug só detecta dispositivos durante o boot, o hotplug consegue detectar dispositivos dinamicamente  

2. Qual comando você usaria para descobrir qual driver está sendo usado por uma placa de rede PCI?  
**Resposta**: lspci

3. Qual comando lista os módulos atualmente carregados no kernel, e qual arquivo em `/proc` ele lê?  
**Resposta**: É o comando lsmod, realizando a leitura do arquivo: `/proc/modules`  

4. Qual a diferença prática entre `modprobe` e `insmod`?  
**Resposta**: O `modprobe` resolve dependências automaticamente, enquanto o `insmod` carrega apenas o módulo `.ko` diretamente, sem resolver dependências  

5. Você quer remover o módulo `e1000e` do kernel de forma segura (com resolução de dependências). Qual comando usar?
**Resposta**: Comando `modprobe -r e1000e`  

6. Onde você consultaria, no /proc, os canais de IRQ atualmente em uso?
**Resposta**: Caminho: `/proc/interrupts`  

7. O que é o `udev` e qual sua relação com o `/dev`?
**Resposta**: É o subsistema que gerencia dinamicamente os arquivo de dispositovs em `/dev`, criando e removendo conforme eventos do hardware  

8. Qual comando mostra, em tempo real, os eventos gerados quando você conecta um pendrive USB?
**Resposta**: Comando `udevadm monitor`  

9. Qual é a diferença entre um dispositivo de bloco e um dispositivo de caractere? Dê um exemplo de cada.
**Resposta**: Dispositivos de bloc lê e escreve em blocos, como buffer (ex: `/dev/sda`); dispositivos de caractere transmite byte a byte, sem buffer de blocos (ex: `/dev/tty`)  

10. Qual arquivo/diretório é usado para configurar de forma persistente opções e blacklist de módulos do kernel?
**Resposta**: `/etc/modprobe.d/`
