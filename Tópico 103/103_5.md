# Tópico 103.5 — Criar, monitorar e finalizar processos

**Peso: 4** · Exame 101

**Comandos e arquivos-chave:** `&`, `bg`, `fg`, `jobs`, `kill`, `killall`, `pkill`, `pgrep`, `nohup`, `ps`, `top`, `free`, `uptime`, `watch`, `screen`, `tmux`, `nice`, `renice`, `/proc`.

---

## 1. Conceitos fundamentais

- **Programa** é um arquivo executável em disco. 
- **Processo** é uma instância desse programa em execução, com seu próprio espaço de memória e recursos.

| Conceito | Significado |
| --- | --- |
| **PID** | Identificador único do processo |
| **PPID** | PID do processo pai (quem o criou) |
| **UID/EUID** | Usuário dono / usuário efetivo do processo |
| **PGID** | ID do grupo de processos (um pipeline forma um grupo) |
| **SID** | ID da sessão (um login/terminal) |
| **TTY** | Terminal de controle (`?` = sem terminal, como daemons) |

### Como processos nascem

1. O pai chama **fork()**, criando uma cópia de si mesmo com novo PID.
2. O filho chama **exec()**, substituindo-se pelo novo programa.
3. O pai pode esperar (**wait**) o filho terminar.

O primeiro processo do sistema é o **PID 1** (`init` ou `systemd`), ancestral de todos. Se um pai morre antes do filho, o filho é "adotado" pelo PID 1.

### Estados de um processo (coluna STAT)

| Código | Estado | Explicação |
| --- | --- | --- |
| **R** | Running | Executando ou na fila para executar |
| **S** | Sleeping | Dormindo, esperando evento (interrompível) |
| **D** | Uninterruptible sleep | Esperando I/O; **não aceita sinais** (nem SIGKILL) |
| **T** | Stopped | Parado (SIGSTOP/Ctrl+Z) ou em debug |
| **Z** | Zombie | Terminou, mas o pai ainda não leu seu status |

Modificadores extras: `<` alta prioridade, `N` baixa prioridade, `s` líder de sessão, `l` multithread, `+` foreground no terminal.

> **Zumbi não se mata com kill** — ele já está morto. A solução é fazer o pai chamar wait (ou matar/reiniciar o pai, fazendo o init adotar e limpar o zumbi).

## 2. Primeiro e segundo plano (jobs)

Um **job** é um processo (ou pipeline) controlado pelo shell atual. Jobs são locais àquela sessão do shell.

```bash
sleep 300 &        # inicia direto em segundo plano
# [1] 4821         # [número do job] PID
```

| Ação | Como |
| --- | --- |
| Iniciar em background | `comando &` |
| Suspender o job em foreground | **Ctrl+Z** (envia SIGTSTP) |
| Interromper o job em foreground | **Ctrl+C** (envia SIGINT) |
| Listar jobs | `jobs` (`-l` mostra PIDs, `-p` só PIDs) |
| Continuar em background | `bg %1` |
| Trazer para foreground | `fg %1` |

### Especificadores de job

- `%1` → job número 1
- `%%` ou `%+` → job atual (o último manipulado)
- `%-` → job anterior
- `%nome` → job cujo comando começa com *nome*
- `%?texto` → job cujo comando contém *texto*

### Exemplo completo

```bash
$ sleep 500
^Z
[1]+  Stopped                 sleep 500
$ bg %1
[1]+ sleep 500 &
$ jobs
[1]+  Running                 sleep 500 &
$ fg %1          # volta ao foreground
$ kill %1        # kill também aceita %job
```

**Observação:** processo em background ainda escreve no terminal. Para evitar, redirecione: `comando > saida.log 2>&1 &`.

## 3. Sobreviver ao logout

Ao fechar o terminal, o shell envia **SIGHUP** a seus filhos, e eles morrem. Soluções:

### nohup

Executa o comando ignorando SIGHUP.

```bash
nohup ./script.sh &
```

- Se a saída padrão for um terminal, é redirecionada para `nohup.out` (no diretório atual, ou em `$HOME` se não for possível gravar).
- Redirecione para controlar: `nohup ./script.sh > log.txt 2>&1 &`

### Alternativas (cobradas no exame)

- **disown**: `disown %1` remove o job da tabela do shell (não receberá SIGHUP). Com `-h`, apenas marca para não enviar SIGHUP.
- **screen** e **tmux**: multiplexadores de terminal. A sessão continua rodando no servidor mesmo desconectado, e você pode reanexar depois.

### screen

```bash
screen                 # nova sessão
screen -S nome         # sessão nomeada
# Ctrl+a d             # desanexar (detach)
screen -ls             # listar sessões
screen -r nome         # reanexar
```

Atalhos (prefixo **Ctrl+a**): `c` nova janela, `n`/`p` próxima/anterior, `"` lista janelas, `d` detach, `k` mata janela.

### tmux

```bash
tmux                   # nova sessão
tmux new -s nome       # sessão nomeada
# Ctrl+b d             # desanexar
tmux ls                # listar
tmux attach -t nome    # reanexar (a / attach-session)
tmux kill-session -t nome
```

Atalhos (prefixo **Ctrl+b**): `c` nova janela, `n`/`p` navegar, `%` divide na vertical, `"` divide na horizontal, `d` detach, `[` modo de rolagem.

## 4. Monitorando processos

### 4.1 ps — foto instantânea

O `ps` mostra um retrato **no momento da execução**. Aceita três estilos de opções:

| Estilo | Exemplo | Origem |
| --- | --- | --- |
| UNIX (com `-`) | `ps -ef` | System V |
| BSD (sem `-`) | `ps aux` | BSD |
| GNU (com `--`) | `ps --forest` | GNU |

```bash
ps                 # apenas processos do terminal atual
ps -e              # todos os processos (= ps -A)
ps -ef             # formato completo (UID PID PPID C STIME TTY TIME CMD)
ps aux             # todos, com usuário, %CPU, %MEM, STAT
ps -u usuario      # processos de um usuário
ps -C nginx        # por nome do comando
ps -p 1234         # por PID
ps --forest        # árvore pai/filho (ou: ps -ejH)
ps -o pid,ppid,user,%cpu,%mem,cmd   # colunas personalizadas
ps aux --sort=-%mem | head          # ordena por memória (decrescente)
```

**Colunas de `ps aux`:** `USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND`

- **VSZ**: memória virtual total (KB) · **RSS**: memória física residente (KB)

**Colunas de `ps -ef`:** `UID PID PPID C STIME TTY TIME CMD` (C = uso de CPU).

> **Dica de prova:** `--sort=campo` ordena crescente; `--sort=-campo` decrescente.

### 4.2 pgrep — achar PIDs por nome

```bash
pgrep sshd              # PIDs que casam com "sshd"
pgrep -l sshd           # PID + nome
pgrep -u root sshd      # filtrando por usuário
pgrep -a -f "python app" # mostra linha de comando completa; -f casa com a linha inteira
```

### 4.3 top — monitoramento em tempo real

```bash
top            # atualiza a cada 3 s por padrão
top -d 1       # intervalo de 1 segundo
top -p 123,456 # só esses PIDs
top -u user    # só um usuário
top -b -n 1    # modo batch (para scripts), 1 iteração
```

**Cabeçalho do top:**

- Linha 1: hora, **uptime**, usuários, **load average** (1, 5 e 15 min)
- Tasks: total, running, sleeping, stopped, zombie
- `%Cpu(s)`: **us** (usuário), **sy** (kernel), **ni** (nice), **id** (ocioso), **wa** (espera I/O), **hi/si** (interrupções), **st** (roubado por VM)
- Memória e Swap: total, free, used, buff/cache

**Colunas:** `PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND` (`PR` = prioridade do kernel, `NI` = valor nice, `S` = estado)

**Teclas interativas do top:**

| Tecla | Função |
| --- | --- |
| `k` | Matar processo (pede PID e sinal) |
| `r` | Renice (alterar prioridade) |
| `M` | Ordenar por memória |
| `P` | Ordenar por CPU |
| `N` | Ordenar por PID |
| `T` | Ordenar por tempo de CPU |
| `R` | Inverter ordenação |
| `u` | Filtrar por usuário |
| `1` | Mostrar cada CPU separadamente |
| `h` ou `?` | Ajuda |
| `q` | Sair |
| `d` / `s` | Alterar intervalo de atualização |
| `W` | Salvar configuração em `~/.toprc` |

### 4.4 Load average e uptime

```bash
uptime
# 14:02:11 up 12 days, 3:41, 2 users, load average: 0.52, 0.80, 1.05
```

O load average é a média de processos **prontos para executar ou aguardando I/O** nos últimos 1, 5 e 15 minutos. Regra prática: em uma máquina com **N núcleos**, load constantemente acima de N indica saturação. Tendência (1 min > 15 min) indica carga crescente.

### 4.5 free — memória

```bash
free         # em KiB
free -h      # legível (Gi, Mi)
free -m      # em MiB
free -s 2    # repete a cada 2 segundos
free -t      # linha de total
```

Colunas: `total used free shared buff/cache available`. A coluna **available** é a estimativa real de memória utilizável por novos programas (inclui cache liberável). Não se assuste com `free` baixo: o Linux usa RAM livre como cache.

### 4.6 watch — repetir um comando

```bash
watch -n 2 free -h       # a cada 2s (padrão: 2s)
watch -d 'ps aux | wc -l' # -d destaca diferenças
```

### 4.7 /proc — o sistema de arquivos virtual

Cada processo tem um diretório `/proc/<PID>/`:

| Arquivo | Conteúdo |
| --- | --- |
| `cmdline` | Linha de comando original |
| `status` | Estado, PID, PPID, UID, memória |
| `environ` | Variáveis de ambiente |
| `cwd` | Link para o diretório de trabalho |
| `exe` | Link para o executável |
| `fd/` | Descritores de arquivo abertos |
| `maps` | Mapeamento de memória |

Arquivos globais: `/proc/loadavg`, `/proc/meminfo`, `/proc/cpuinfo`, `/proc/uptime`. É dali que `ps`, `top` e `free` obtêm seus dados. `/proc/self` aponta para o próprio processo que o lê.

## 5. Sinais e finalização de processos

Um **sinal** é uma notificação assíncrona enviada a um processo. O processo pode tratá-lo, ignorá-lo, ou sofrer a ação padrão.

| Nº | Nome | Ação padrão / uso | Capturável? |
| --- | --- | --- | --- |
| **1** | **SIGHUP** | Terminal fechou; muitos daemons **recarregam a configuração** | Sim |
| **2** | **SIGINT** | Interrupção (Ctrl+C) | Sim |
| **3** | SIGQUIT | Encerra + core dump (Ctrl+\\) | Sim |
| **9** | **SIGKILL** | Morte imediata, forçada pelo kernel | **Não** |
| **15** | **SIGTERM** | Pedido educado de término (**padrão do kill**) | Sim |
| **18** | **SIGCONT** | Continua processo parado | Sim |
| **19** | **SIGSTOP** | Pausa o processo | **Não** |
| **20** | SIGTSTP | Pausa pelo terminal (Ctrl+Z) | Sim |

> **Memorize:** 1 = HUP · 2 = INT · 9 = KILL · 15 = TERM · 18 = CONT · 19 = STOP. KILL e STOP **não podem** ser capturados nem ignorados.

### kill

Apesar do nome, `kill` apenas **envia sinais** (padrão: SIGTERM).

```bash
kill 1234             # SIGTERM (15)
kill -15 1234         # idem
kill -SIGTERM 1234    # idem
kill -TERM 1234       # idem
kill -9 1234          # SIGKILL
kill -s HUP 1234      # outra sintaxe
kill -1 1234          # recarregar configuração do daemon
kill -l               # lista todos os sinais
kill %2               # age sobre o job 2
kill -9 -1234         # PID negativo = grupo de processos 1234
```

**Boa prática:** tente primeiro SIGTERM (permite limpeza de arquivos temporários e conexões); use SIGKILL só se o processo não responder. Usuários comuns só podem sinalizar seus próprios processos; root, qualquer um.

### killall e pkill — por nome

```bash
killall nginx              # SIGTERM em todos os processos chamados nginx
killall -9 firefox         # SIGKILL
killall -u usuario         # todos os processos do usuário (cuidado!)
killall -i nome            # pede confirmação
pkill sshd                 # casa por padrão (regex) no nome
pkill -9 -u maria          # SIGKILL em todos de maria
pkill -f "python app.py"   # casa com a linha de comando completa
pkill -t pts/2             # processos de um terminal
pkill -P 1234              # filhos do PID 1234
```

`pkill` e `pgrep` compartilham as mesmas opções de seleção, e por isso `pgrep` é ótimo para **testar antes** de usar `pkill`.

### Fluxo seguro de finalização

```bash
pgrep -l -f "meuapp"   # 1. confirmar quem será afetado
kill PID               # 2. SIGTERM
sleep 5; ps -p PID     # 3. verificar se terminou
kill -9 PID            # 4. último recurso
```

## 6. Prioridade de processos: nice e renice

O escalonador distribui CPU conforme a prioridade. O **valor nice** vai de **-20** (maior prioridade) a **+19** (menor). O padrão é **0**. "Quanto mais *legal* (nice) o processo, menos CPU ele disputa."

```bash
nice -n 10 ./backup.sh     # inicia com nice 10
nice ./backup.sh           # sem -n: nice +10 por padrão
nice -n -5 ./critico.sh    # negativo: só root
renice 5 -p 1234           # altera processo em execução
renice -n 10 -p 1234       # sintaxe equivalente
renice 5 -u maria          # todos de um usuário
renice 5 -g 100            # todos de um grupo
```

**Regras importantes:**

- Usuário comum só pode **aumentar** o nice (diminuir a prioridade) de seus processos; **nunca reduzi-lo** de volta.
- Apenas **root** pode usar valores negativos.
- O nice aparece como **NI** no `top` e `ps -l`. `PR` no top ≈ 20 + NI.
- Em `ps`, use `-o pid,ni,cmd` para ver o nice.

## 8. Pegadinhas frequentes na prova

1. `kill` sem opção envia **SIGTERM (15)**, não SIGKILL.
2. **SIGKILL e SIGSTOP** não podem ser capturados.
3. **Zumbis** (Z) não são removidos com kill.
4. Estado **D** ignora sinais até o I/O terminar.
5. `nohup` grava em `nohup.out` quando a saída é um terminal.
6. `nice` sem argumento soma **+10**; só root usa valores negativos.
7. `ps aux` (BSD, sem hífen) ≠ `ps -aux` (mistura estilos; evite).
8. `top` ordena por CPU por padrão; `M` ordena por memória.
9. Jobs (`jobs`, `fg`, `bg`) são **por shell**, não globais; `ps` é global.
10. Ctrl+Z **suspende** (não finaliza); o job continua na lista como *Stopped*.
11. `killall` no **Solaris** mata *todos* os processos; no Linux, por nome. Na prova, considere o comportamento do Linux.
12. `free` usa **KiB** por padrão; `-h` para humano.

Um administrador executa o comando `kill 2345` sem informar nenhuma opção de sinal. Qual sinal é enviado ao processo?

Resposta: SIGTERM (15)
#### Ex.2  
Você iniciou `sleep 600` em primeiro plano e pressionou Ctrl+Z. O job aparece como [1]+ Stopped. Qual comando faz esse job voltar a executar em segundo plano?

Resposta: fg %1
#### Ex.3

b) O processo está bloqueado em I/O; é preciso aguardar o disco  
c) O processo já terminou, mas o pai não leu seu status de saída; o pai deve fazer isso ou ser encerrado  
d) O processo ignora SIGKILL; use SIGSTOP e depois SIGCONT  

Resposta: C
