# Tópico 103.4 — Fluxos, pipes e redirecionamentos

## 1. Os três fluxos padrão (streams)

Todo processo Linux nasce com três canais abertos, identificados por **descritores de arquivo (file descriptors, FD)**:

| FD | Nome | Sigla | Padrão | Dispositivo |
| --- | --- | --- | --- | --- |
| 0 | Entrada padrão | stdin | teclado | `/dev/stdin` |
| 1 | Saída padrão | stdout | terminal | `/dev/stdout` |
| 2 | Saída de erro padrão | stderr | terminal | `/dev/stderr` |

Pontos-chave:

- stdout e stderr aparecem **ambos no terminal**, mas são canais **separados**. Um `>` comum só captura o stdout.
- Mensagens de erro vão para o stderr; resultados normais vão para o stdout.
- Os FDs também existem em `/proc/<PID>/fd/`.

## 2. Redirecionamento de saída

| Operador | Efeito |
| --- | --- |
| `>` | Redireciona stdout para arquivo, **sobrescrevendo** (cria se não existir) |
| `>>` | Redireciona stdout para arquivo, **anexando** ao final |
| `1>` / `1>>` | Idêntico a `>` / `>>` (o `1` é implícito) |
| `2>` | Redireciona stderr para arquivo (sobrescreve) |
| `2>>` | Redireciona stderr para arquivo (anexa) |
| `&>` | stdout **e** stderr para o mesmo arquivo (sobrescreve) — Bash |
| `&>>` | stdout e stderr para o mesmo arquivo (anexa) — Bash 4+ |
| `>&2` | Envia stdout para onde o stderr aponta |
| `2>&1` | Envia stderr para onde o stdout aponta |
| `>\|` | Força sobrescrita mesmo com `noclobber` ativo |

```bash
ls /etc > lista.txt              # sobrescreve
ls /home >> lista.txt            # acrescenta
ls /inexistente 2> erros.txt     # só o erro vai ao arquivo
ls /etc /inexistente > ok.txt 2> erro.txt   # separa os dois
ls /etc /inexistente > tudo.txt 2>&1        # junta os dois
ls /etc /inexistente &> tudo.txt            # atalho Bash
```

### ⚠️ A ordem importa (pegadinha clássica)

Os redirecionamentos são processados **da esquerda para a direita**.

```bash
comando > arquivo 2>&1    # CORRETO: stdout -> arquivo; depois stderr -> onde stdout está (arquivo)
comando 2>&1 > arquivo    # ERRADO: stderr -> terminal (onde stdout estava); depois stdout -> arquivo
```

No segundo caso, os erros continuam no terminal.

### `/dev/null` e `/dev/zero`

- `/dev/null`: "buraco negro". Tudo que é escrito nele é descartado; leitura devolve EOF.
- `comando 2> /dev/null` — silencia erros.
- `comando > /dev/null 2>&1` — silencia tudo.
- `> arquivo` (sem comando) ou `: > arquivo` — **zera** o arquivo.

### `noclobber`

```bash
set -o noclobber     # impede que '>' sobrescreva arquivos existentes
echo oi > a.txt      # erro se a.txt já existir
echo oi >| a.txt     # força a sobrescrita
set +o noclobber     # desativa
```

## 3. Redirecionamento de entrada

| Operador | Nome | Efeito |
| --- | --- | --- |
| `<` | Entrada | O arquivo vira o stdin do comando |
| `<<DELIM` | Here-document | Texto digitado até a linha `DELIM` vira o stdin |
| `<<< "texto"` | Here-string | A string vira o stdin (Bash) |

```bash
sort < nomes.txt                 # equivalente a: sort nomes.txt
wc -l < /etc/passwd              # imprime só o número (sem nome de arquivo)

cat << EOF > config.txt
linha 1
linha 2
EOF

grep root <<< "root:x:0:0"
```

- `<<-DELIM` remove **tabs** iniciais (permite indentar o here-doc).
- Com `<<'EOF'` (aspas no delimitador) não há expansão de variáveis dentro do bloco.

## 4. Pipes (`|`)

O pipe liga o **stdout** de um comando ao **stdin** do próximo. Os processos rodam **em paralelo**, e os dados passam por um buffer em memória (sem arquivo temporário).

```bash
cat /etc/passwd | cut -d: -f1 | sort | head -5
ps aux | grep sshd | wc -l
ls -l | sort -k5 -n -r | head
```

Detalhes importantes:

- O pipe **só transporta stdout**. Para incluir stderr: `cmd1 2>&1 | cmd2` ou `cmd1 |& cmd2` (Bash).
- O código de saída de um pipeline é o do **último** comando. Use `set -o pipefail` para propagar falhas, e `${PIPESTATUS[@]}` para ver o código de cada etapa.
- Nem todo comando lê stdin. `ls | rm` **não** funciona: `rm` ignora stdin. Para isso existe o `xargs`.
- Pipe anônimo (`|`) vs. **pipe nomeado (FIFO)**, criado com `mkfifo nome` — existe como arquivo no disco e serve para comunicação entre processos independentes.

## 5. `tee` — dividir a saída

Lê o stdin e escreve **no stdout e em arquivo(s)** ao mesmo tempo (como uma conexão em "T").

```bash
ls -l | tee lista.txt            # mostra na tela e grava
ls -l | tee -a lista.txt         # -a: anexa em vez de sobrescrever
ls | tee a.txt b.txt | wc -l     # vários arquivos + continua o pipeline
echo "porta 22" | sudo tee /etc/exemplo.conf > /dev/null
```

| Opção | Efeito |
| --- | --- |
| `-a` | Anexa (append) |
| `-i` | Ignora SIGINT |

💡 **Truque com sudo:** `sudo echo x > /etc/arq` falha, pois o redirecionamento é feito pelo *seu* shell, não pelo sudo. Use `echo x | sudo tee /etc/arq`.

## 6. `xargs` — transformar stdin em argumentos

Lê itens do stdin e os passa como **argumentos** ao comando indicado (padrão: `echo`).

```bash
find /tmp -name "*.log" | xargs rm
echo "a b c" | xargs mkdir
cat lista.txt | xargs -n 1 echo         # 1 argumento por execução
find . -name "*.txt" | xargs -I {} cp {} /backup/
find . -name "*.txt" -print0 | xargs -0 rm   # seguro p/ espaços
```

| Opção | Efeito |
| --- | --- |
| `-n N` | No máximo N argumentos por execução |
| `-I {}` | Define marcador de substituição (uma execução por item) |
| `-0` | Itens separados por byte nulo (par com `find -print0`) |
| `-p` | Pergunta antes de cada execução |
| `-t` | Exibe o comando antes de executar |
| `-r` | Não executa se a entrada for vazia (GNU) |
| `-d` | Define o delimitador |
| `-P N` | Executa até N processos em paralelo |

Alternativas ao xargs:

```bash
find . -name "*.log" -exec rm {} \;    # um processo por arquivo
find . -name "*.log" -exec rm {} +     # agrupa (como xargs)
```

## 7. Substituição de comandos

Injeta a **saída** de um comando dentro de outro:

```bash
echo "Hoje é $(date +%A)"
ls -l $(which bash)
echo "Kernel: `uname -r`"      # sintaxe antiga (crases)
```

`$( )` é preferível: aceita aninhamento e é mais legível.

```
teclado ──► [ stdin 0 ]──► PROCESSO ──► [ stdout 1 ] ──► terminal
                              │
                              └────────► [ stderr 2 ] ──► terminal

cmd1 ──stdout──| pipe |──stdin──► cmd2
cmd  ──stdout──► tee ──► arquivo  (e continua no stdout)
```

## 9. Cola rápida para a prova

| Quero... | Use |
| --- | --- |
| Gravar stdout, apagando o arquivo | `cmd > f` |
| Gravar stdout, acrescentando | `cmd >> f` |
| Gravar só erros | `cmd 2> f` |
| Gravar tudo no mesmo arquivo | `cmd > f 2>&1` ou `cmd &> f` |
| Descartar erros | `cmd 2> /dev/null` |
| Usar arquivo como entrada | `cmd < f` |
| Encadear comandos | `cmd1 \| cmd2` |
| Pipe incluindo stderr | `cmd1 2>&1 \| cmd2` |
| Tela **e** arquivo | `cmd \| tee f` |
| Tela e arquivo (append) | `cmd \| tee -a f` |
| Saída virar argumentos | `cmd1 \| xargs cmd2` |
| Esvaziar arquivo | `> f` |
| Texto inline como entrada | `cmd << EOF` |

## 10. Armadilhas frequentes

1. `cmd 2>&1 > f` ≠ `cmd > f 2>&1` (a ordem muda o resultado).
2. `>` sobrescreve **sem avisar**; `cat f > f` deixa o arquivo vazio.
3. `sort arq > arq` destrói o arquivo (o shell o zera antes do sort ler). Use `sort -o arq arq` ou um arquivo temporário.
4. O pipe só leva stdout; erros continuam na tela.
5. `ls | rm` não funciona; use `xargs` ou `-exec`.
6. `xargs` sem `-0` quebra com nomes contendo espaços.
7. `tee` sem `-a` sobrescreve o arquivo.
8. `sudo cmd > arquivo` — o redirecionamento não roda como root.
9. `wc -l arq` mostra o nome; `wc -l < arq` mostra só o número.

#### Ex.1  
Considere o comando executado no Bash, em um sistema onde o diretório /inexistente não existe:  
```bash
ls /etc /inexistente 2>&1 > resultado.txt
```
Qual é o resultado dessa linha de comando?  
a) A saída padrão e a saída de erro são gravadas em resultado.txt.  
b) A saída padrão é gravada em resultado.txt e a mensagem de erro é exibida no terminal.  
c) A saída de erro é gravada em resultado.txt e a listagem de /etc é exibida no terminal.  
d) Tanto a saída padrão quanto a saída de erro são exibidas no terminal, e resultado.txt fica vazio.  
e) O Bash retorna erro de sintaxe, pois os operadores não podem ser combinados.  

Resposta: B  
No segundo descrito > resultado.txt só a saída 1 é redirecionada, e passa a apontar para o arquivo, a saída 2 continua apontando para o terminal (1)
#### Ex.2  
Um administrador precisa executar dmesg, exibir a saída na tela e acrescentar essa mesma saída ao final do arquivo boot.log, sem apagar o conteúdo existente. Qual comando atende ao requisito?  

a) dmesg | tee boot.log  
b) dmesg | tee -a boot.log  
c) dmesg | tee >> boot.log  
d) dmesg > boot.log | tee  
e) dmesg | tee -r boot.log  

Resposta: B  
`tee` sem opções sobrescreve o arquivo de destino
