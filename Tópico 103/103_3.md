# Tópico 103.3: Gerenciamento de arquivos  

## 1. O que o exame cobra

### Áreas de conhecimento principais

- Copiar, mover e remover arquivos e diretórios individualmente.
- Copiar vários arquivos e diretórios **recursivamente**.
- Remover arquivos e diretórios **recursivamente**.
- Usar wildcards simples e avançados nos comandos.
- Usar `find` para localizar e **agir** sobre arquivos por tipo, tamanho ou data.
- Usar `tar`, `cpio` e `dd`.

### Lista de termos e utilitários do tópico

| Categoria | Comandos |
|---|---|
| Listar / criar / remover | `ls`, `touch`, `mkdir`, `rmdir` |
| Copiar / mover / apagar | `cp`, `mv`, `rm` |
| Localizar | `find` |
| Identificar tipo | `file` |
| Compactar | `gzip`, `gunzip`, `bzip2`, `bunzip2`, `xz`, `unxz` |
| Arquivar | `tar`, `cpio` |
| Cópia de baixo nível | `dd` |
| Padrões | *file globbing* (wildcards) |

## 2. Conceitos base: caminhos, inodes e timestamps

### 2.1 Caminhos absolutos e relativos

| Tipo | Começa com | Exemplo | Depende de onde estou? |
|---|---|---|---|
| **Absoluto** | `/` | `/etc/ssh/sshd_config` | Não |
| **Relativo** | qualquer outra coisa | `../docs/leia.txt` | **Sim** (do diretório atual) |

Atalhos especiais:

| Símbolo | Significado |
|---|---|
| `.` | diretório atual |
| `..` | diretório pai |
| `~` | home do usuário atual (expandido pelo shell) |
| `~maria` | home do usuário `maria` |
| `-` | em `cd -`, volta ao diretório anterior (`$OLDPWD`) |

### 2.2 Tudo é arquivo — e arquivo é inode

No Linux, o **nome** de um arquivo **não** é o arquivo em si. O nome é apenas uma *entrada de diretório* (um "link") que aponta para um **inode**. O inode guarda os metadados e a localização dos dados:

- dono (UID) e grupo (GID);
- permissões;
- tamanho;
- timestamps;
- ponteiros para os blocos de dados;
- contador de links.

Consequências importantes para este tópico:

- **Renomear/mover dentro do mesmo sistema de arquivos** só altera a entrada de diretório. O inode e os dados **não** são copiados (por isso é instantâneo).
- **Remover** (`rm`) apaga a entrada de diretório. Os dados só são liberados quando o contador de links chega a **0** e nenhum processo mantém o arquivo aberto.
- **Copiar** cria um **novo inode** com novos dados.

Para ver o número do inode: `ls -i arquivo`.

### 2.3 Os três timestamps

| Timestamp | Nome | Atualizado quando... | Opção do `find` |
|---|---|---|---|
| **atime** | access time | o conteúdo é lido (veja a nota abaixo) | `-atime`, `-amin` |
| **mtime** | modification time | o **conteúdo** é modificado | `-mtime`, `-mmin` |
| **ctime** | change time | o **inode** muda (permissões, dono, nome/links, conteúdo) | `-ctime`, `-cmin` |

> ⚠️ **ctime NÃO é "creation time"!** É *change time*. Pegadinha clássica. A data de criação real (*birth time*) só existe em alguns sistemas de arquivos e aparece no `stat` como `Birth`.

> ℹ️ Por padrão, a maioria dos sistemas monta com `relatime`, então o **atime** não é atualizado a cada leitura (somente se estiver mais velho que o mtime/ctime ou com mais de 24 h). Por isso `atime` não é confiável para "último acesso exato".

O `ls -l` mostra o **mtime** por padrão.

## 3. Listando arquivos: `ls`

```bash
ls [opções] [arquivo|diretório ...]
```

### 3.1 Opções essenciais

| Opção | O que faz |
|---|---|
| `-l` | formato longo (permissões, dono, tamanho, data...) |
| `-a` | mostra **todos**, inclusive ocultos (`.`, `..` e `.arquivo`) |
| `-A` | quase todos: ocultos, **exceto** `.` e `..` |
| `-h` | tamanhos legíveis (K, M, G) — usado com `-l` |
| `-d` | lista o **próprio diretório**, não o conteúdo |
| `-R` | recursivo |
| `-t` | ordena por **mtime** (mais novo primeiro) |
| `-r` | **inverte** a ordem |
| `-S` | ordena por **tamanho** (maior primeiro) |
| `-X` | ordena por extensão |
| `-i` | mostra o número do **inode** |
| `-F` | adiciona indicador de tipo (`/` dir, `*` executável, `@` link, `\|` FIFO, `=` socket) |
| `-1` | uma entrada por linha |
| `-n` | UID/GID numéricos em vez de nomes |
| `-u` | com `-l`/`-t`: usa **atime** |
| `-c` | com `-l`/`-t`: usa **ctime** |
| `--full-time` | mostra data/hora completas, com segundos |
| `--color=auto` | colorir por tipo |

### 3.2 Lendo a saída do `ls -l`

```text
-rw-r--r--  1  ana  devs  1024  out 11 10:00  notas.txt
│└──┬───┘  │   │    │     │          │          └─ nome
│   │      │   │    │     │          └─ mtime
│   │      │   │    │     └─ tamanho em bytes
│   │      │   │    └─ grupo
│   │      │   └─ dono
│   │      └─ nº de links físicos (hard links)
│   └─ permissões (dono / grupo / outros)
└─ tipo do arquivo
```

**Primeiro caractere (tipo):**

| Char | Tipo |
|---|---|
| `-` | arquivo regular |
| `d` | diretório |
| `l` | link simbólico |
| `b` | dispositivo de bloco (ex.: `/dev/sda`) |
| `c` | dispositivo de caractere (ex.: `/dev/tty`) |
| `p` | pipe nomeado (FIFO) |
| `s` | socket |

### 3.3 Exemplos

```bash
ls -lah /var/log          # longo, com ocultos, tamanhos legíveis
ls -lt                    # mais recentes primeiro
ls -ltr                   # mais antigos primeiro (ótimo para "o último fica embaixo")
ls -lS                    # maiores primeiro
ls -ld /etc               # info do diretório /etc, não do conteúdo
ls -li                    # com inode
ls -l --time=atime        # mostra atime em vez de mtime
ls -A                     # ocultos sem . e ..
```

> 💡 `ls -l /etc` lista o **conteúdo**; `ls -ld /etc` mostra o **diretório em si**. Muito útil para conferir permissões de pastas.

## 4. Criando arquivos e alterando datas: `touch` e `stat`

### 4.1 `touch`

Duas funções: **criar arquivo vazio** (se não existir) e **atualizar timestamps**.

```bash
touch arquivo                 # cria vazio (ou atualiza atime/mtime para agora)
touch a.txt b.txt c.txt       # vários de uma vez
touch -c arquivo              # NÃO cria se não existir
touch -a arquivo              # altera só o atime
touch -m arquivo              # altera só o mtime
touch -t 202610111530.45 f    # [[CC]YY]MMDDhhmm[.ss]
touch -d "2026-10-11 15:30" f # data em texto livre
touch -d "yesterday" f
touch -r referencia.txt f     # copia os timestamps de outro arquivo
```

| Opção | Significado |
|---|---|
| `-a` | só acesso (atime) |
| `-m` | só modificação (mtime) |
| `-c` | não cria arquivos novos |
| `-t STAMP` | usa data no formato `[[CC]YY]MMDDhhmm[.ss]` |
| `-d STRING` | usa data descrita em texto |
| `-r REF` | usa os tempos do arquivo de referência |

> ℹ️ O `touch` **nunca** consegue definir o **ctime**: o ctime sempre vira "agora" quando o inode é alterado (e alterar timestamps altera o inode).

### 4.2 `stat`

Mostra todos os metadados de uma vez:

```bash
stat arquivo
```

```text
  File: arquivo
  Size: 1024        Blocks: 8     IO Block: 4096   regular file
Device: 801h/2049d  Inode: 131090  Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/ ana)   Gid: ( 1000/ ana)
Access: 2026-10-11 10:00:00.000000000 -0300
Modify: 2026-10-11 10:00:00.000000000 -0300
Change: 2026-10-11 10:00:00.000000000 -0300
 Birth: 2026-10-11 09:50:00.000000000 -0300
```

## 5. Criando e removendo diretórios: `mkdir` e `rmdir`

### 5.1 `mkdir`

```bash
mkdir projeto                  # cria um diretório
mkdir a b c                    # vários
mkdir -p projeto/src/lib       # -p cria TODA a hierarquia (e não reclama se já existir)
   mkdir -p app/{src,docs,tests}  # brace expansion + -p (muito comum)

mkdir -m 700 privado           # já cria com permissão 700
mkdir -v novo                  # verbose
```

| Opção | Significado |
|---|---|
| `-p` | cria diretórios **pais** conforme necessário; sem erro se já existir |
| `-m MODO` | define permissões na criação |
| `-v` | imprime cada diretório criado |

> Sem `-p`, `mkdir a/b/c` **falha** se `a/b` não existir: `No such file or directory`.

### 5.2 `rmdir`

Remove **somente diretórios vazios**.

```bash
rmdir vazio
rmdir -p a/b/c      # remove c, depois b, depois a (se cada um ficar vazio)
```

Se o diretório tiver algo: `rmdir: failed to remove 'x': Directory not empty`.
Para apagar diretório **com conteúdo**, use `rm -r` (seção 8).

## 6. Copiando: `cp`

```bash
cp [opções] ORIGEM DESTINO
cp [opções] ORIGEM... DIRETÓRIO
cp [opções] -t DIRETÓRIO ORIGEM...
```

### 6.1 Opções importantes

| Opção | O que faz |
|---|---|
| `-r` / `-R` | **recursivo** (obrigatório para copiar diretórios) |
| `-a` | **arquivo/backup**: equivale a `-dR --preserve=all` (recursivo + preserva links, dono, permissões, timestamps, atributos) |
| `-p` | preserva **modo, dono e timestamps** |
| `-i` | **interativo**: pergunta antes de sobrescrever |
| `-f` | força (remove destino que não pode ser aberto e tenta de novo) |
| `-n` | **não** sobrescreve arquivo existente |
| `-u` | copia só se a origem for **mais nova** que o destino (ou se o destino não existir) |
| `-v` | verbose |
| `-l` | cria **hard links** em vez de copiar dados |
| `-s` | cria **links simbólicos** em vez de copiar |
| `-d` | copia links simbólicos **como links** (não segue) |
| `-L` | **segue** links simbólicos (copia o alvo) |
| `-b` / `--backup` | faz backup do destino antes de sobrescrever (`arquivo~`) |
| `-t DIR` | define o diretório de destino **antes** das origens |
| `-T` | trata o destino como arquivo normal, nunca como diretório |

### 6.2 O que acontece numa cópia "comum" (sem `-p`/`-a`)

A cópia é um **arquivo novo**:

- **dono** = quem executou o `cp`;
- **timestamps** = agora;
- **permissões** = as da origem **filtradas pelo `umask`**.

Com `-p` ou `-a`, esses atributos são preservados. (Para copiar dono diferente do seu, é preciso ser root.)

### 6.3 Exemplos

```bash
cp relatorio.txt /tmp/                 # copia mantendo o nome
cp relatorio.txt /tmp/copia.txt        # copia com novo nome
cp a.txt b.txt c.txt /backup/          # várias origens: o último DEVE ser um diretório
cp -i *.conf /etc/backup/              # pergunta antes de sobrescrever
cp -r /etc/ssh /tmp/ssh_bkp            # diretório (recursivo)
cp -a /home/ana /backup/               # backup fiel (preserva tudo)
cp -u *.txt /backup/                   # só os novos/modificados
cp -t /backup a.txt b.txt              # destino antes das origens
cp arquivo.conf{,.bak}                 # = cp arquivo.conf arquivo.conf.bak
```

### 6.4 Armadilha: `cp -r origem destino` e a barra final

```bash
cp -r dir1 dir2
```

| Situação | Resultado |
|---|---|
| `dir2` **não existe** | `dir2` **vira uma cópia** de `dir1` |
| `dir2` **já existe** | cria `dir2/dir1` (a cópia vai **para dentro**) |

Para copiar **o conteúdo** de `dir1` para dentro de `dir2`:

```bash
cp -r dir1/. dir2/       # copia tudo, INCLUSIVE ocultos
cp -r dir1/* dir2/       # NÃO copia ocultos (o * não casa com .nome)
```

> ❗ Sem `-r`, copiar diretório dá: `cp: -r not specified; omitting directory 'dir1'`.

> ℹ️ Em distribuições da família RHEL, o `.bashrc` do **root** costuma ter `alias cp='cp -i'`, `alias mv='mv -i'` e `alias rm='rm -i'`. Para ignorar o alias: `\cp`, `command cp` ou `/bin/cp`.

## 7. Movendo e renomeando: `mv`

Não existe um comando "renomear" no POSIX: **renomear é mover** para outro nome.

```bash
mv [opções] ORIGEM DESTINO
mv [opções] ORIGEM... DIRETÓRIO
mv [opções] -t DIRETÓRIO ORIGEM...
```

### 7.1 Opções

| Opção | O que faz |
|---|---|
| `-i` | pergunta antes de sobrescrever |
| `-f` | força, sem perguntar |
| `-n` | nunca sobrescreve |
| `-u` | só move se a origem for mais nova |
| `-v` | verbose |
| `-b` | faz backup do destino sobrescrito |
| `-t DIR` | destino primeiro |

### 7.2 Exemplos

```bash
mv antigo.txt novo.txt              # renomear
mv arquivo.txt /tmp/                # mover
mv arquivo.txt /tmp/outro.txt       # mover + renomear
mv a.txt b.txt c.txt /destino/      # vários (último = diretório)
mv pasta1 pasta2                    # se pasta2 existe → pasta2/pasta1; senão renomeia
mv -i *.log /var/old/               # pergunta antes de sobrescrever
```

### 7.3 O que acontece por baixo

| Cenário | Comportamento |
|---|---|
| **Mesmo sistema de arquivos** | só troca a entrada de diretório (chamada `rename`); **mesmo inode**; instantâneo |
| **Sistemas de arquivos diferentes** | **copia** os dados e **depois remove** a origem (novo inode; demora conforme o tamanho) |

- `mv` **não precisa de `-r`** para diretórios.
- Por padrão, **sobrescreve sem avisar**.

### 7.4 Renomear em lote: `rename`

`mv` não renomeia vários arquivos de uma vez. Para isso existe `rename`, mas **cuidado: há duas versões**:

```bash
# util-linux (RHEL/Fedora/openSUSE): rename ANTIGO NOVO arquivos...
rename .txt .md *.txt

# Perl (Debian/Ubuntu): rename 's/expressão/substituição/' arquivos...
rename 's/\.txt$/.md/' *.txt
```

## 8. Removendo: `rm`

```bash
rm [opções] ARQUIVO...
```

> ⚠️ **Não existe lixeira.** `rm` é irreversível na prática.

### 8.1 Opções

| Opção | O que faz |
|---|---|
| `-r` / `-R` | **recursivo** (necessário para diretórios com conteúdo) |
| `-f` | **força**: ignora inexistentes, **não pergunta** |
| `-i` | pergunta antes de **cada** remoção |
| `-I` | pergunta **uma vez** se for remover mais de 3 arquivos ou recursivamente |
| `-d` | remove **diretórios vazios** (como `rmdir`) |
| `-v` | verbose |
| `--preserve-root` | (padrão) recusa operar recursivamente em `/` |

### 8.2 Exemplos

```bash
rm arquivo.txt
rm -i *.tmp                 # confirma um a um
rm -f lixo.txt              # sem perguntas e sem erro se não existir
rm -r projeto_antigo/       # apaga diretório e todo o conteúdo
rm -rf /tmp/build           # recursivo + forçado (perigoso!)
rm -d pasta_vazia           # equivalente ao rmdir
```

### 8.3 Arquivos com nomes problemáticos

```bash
rm -- -arquivo         # "--" marca o fim das opções
rm ./-arquivo          # caminho relativo explícito
rm "nome com espaço"   # aspas (ou \ antes do espaço)
```

### 8.4 Boas práticas de segurança

- Rode primeiro `ls` com o **mesmo padrão** para ver o que será apagado: `ls *.tmp` → depois `rm *.tmp`.
- Use `rm -i` ou `rm -I` em padrões amplos.
- Desconfie de **espaço extra**: `rm -rf /tmp /build` ≠ `rm -rf /tmp/build`.
- Variáveis vazias são perigosas: `rm -rf "$DIR"/*` com `$DIR` vazio vira `rm -rf /*`.

## 9. Wildcards (file globbing) e brace expansion

### 9.1 A ideia central

Os wildcards são **expandidos pelo shell, ANTES de o comando rodar**. O comando **nunca** vê o `*`: ele recebe a lista já expandida.

```bash
ls *.txt
# o shell expande para:
ls a.txt b.txt relatorio.txt
```

> ❗ Globbing **não é regex**. `*` em glob significa "qualquer coisa"; em regex significa "repetição do anterior". São mundos diferentes (regex é do tópico 103.7).

### 9.2 Metacaracteres básicos

| Padrão | Casa com | Exemplo | Resultado |
|---|---|---|---|
| `*` | **zero ou mais** caracteres quaisquer | `*.log` | `a.log`, `erros.log`* |
| `?` | **exatamente um** caractere | `arq?.txt` | `arq1.txt`, `arqA.txt` (não `arq10.txt`) |
| `[abc]` | **um** caractere da lista | `arq[123].txt` | `arq1.txt`, `arq2.txt`, `arq3.txt` |
| `[a-z]` | **um** caractere do intervalo | `[a-c]*` | começa com a, b ou c |
| `[!abc]` ou `[^abc]` | **um** caractere **fora** da lista | `arq[!0-9].txt` | `arqA.txt` (não `arq1.txt`) |
| `\` | escapa o próximo caractere | `\*` | o asterisco literal |

\* Veja a regra dos arquivos ocultos abaixo: `*` **não** casa com nomes que começam com `.`.

### 9.3 Classes POSIX (dentro de colchetes)

Mais seguras que `[a-z]`, pois intervalos podem depender do *locale*:

| Classe | Significado |
|---|---|
| `[[:digit:]]` | dígitos 0-9 |
| `[[:alpha:]]` | letras |
| `[[:alnum:]]` | letras e dígitos |
| `[[:upper:]]` | maiúsculas |
| `[[:lower:]]` | minúsculas |
| `[[:space:]]` | espaço, tab, quebra de linha |
| `[[:punct:]]` | pontuação |

```bash
ls [[:upper:]]*          # começam com maiúscula
ls *[[:digit:]].txt      # terminam com dígito antes de .txt
ls arq[[:digit:]][[:digit:]].log   # arq01.log ... arq99.log
```

### 9.4 Arquivos ocultos

Por padrão, `*` e `?` **não casam** com nomes que começam com ponto:

```bash
ls *         # NÃO mostra .bashrc
ls .*        # mostra ocultos (cuidado: pode incluir . e .. em shells antigos)
ls -A        # forma segura de ver ocultos
ls * .*      # visíveis + ocultos
cp -r dir1/. dir2/    # copia conteúdo incluindo ocultos
```

### 9.5 Brace expansion `{ }`

> ⚠️ Tecnicamente **não é globbing**: é uma expansão do bash que acontece **antes** do globbing e **não exige que os arquivos existam** — apenas gera texto.

```bash
echo arq{1,2,3}.txt          # arq1.txt arq2.txt arq3.txt
echo {a..e}                  # a b c d e
echo {1..5}                  # 1 2 3 4 5
echo {01..10}                # 01 02 ... 10 (com zeros à esquerda)
echo {1..10..2}              # 1 3 5 7 9 (passo 2)
mkdir -p proj/{src,docs,tests}
touch relatorio_{jan,fev,mar}.txt
cp arquivo.conf{,.bak}       # cp arquivo.conf arquivo.conf.bak
mv nome.{txt,md}             # mv nome.txt nome.md
```

### 9.5.1 Comparação rápida: `{}` vs `[]` vs `*`

| Padrão | Precisa existir arquivo? | Tipo |
|---|---|---|
| `a{1,2}` | **Não** (só gera texto) | brace expansion |
| `a[12]` | **Sim** (só aparece o que existir) | glob |
| `a*` | **Sim** | glob |

### 9.6 Aspas e escape: quando o shell NÃO expande

| Forma | Efeito |
|---|---|
| `'*.txt'` (aspas simples) | **nada** é expandido |
| `"*.txt"` (aspas duplas) | glob **não** é expandido (variáveis e `$()` ainda são) |
| `\*` | escapa um caractere |

Isso é crucial com `find -name`:

```bash
find . -name "*.txt"     # ✅ o find recebe *.txt e ele mesmo faz a correspondência
find . -name *.txt       # ❌ o shell pode expandir antes, se houver .txt no diretório atual
```

### 9.7 Quando nada casa

Por padrão, o bash passa o **padrão literal** ao comando (`ls *.xyz` → `ls: cannot access '*.xyz'`). Isso é configurável:

```bash
shopt -s nullglob     # padrão sem correspondência vira "nada"
shopt -s failglob     # padrão sem correspondência vira erro
```

### 9.8 Globbing estendido (`extglob`)

```bash
shopt -s extglob
ls !(*.txt)        # tudo, exceto .txt
ls +(a|b)*         # um ou mais "a" ou "b" no início
ls @(*.jpg|*.png)  # .jpg OU .png
ls ?(x)file        # zero ou uma ocorrência de x
ls *(x)file        # zero ou mais
```

## 10. Localizando e agindo: `find`

O `find` percorre a árvore de diretórios, **avalia testes** em cada arquivo e **executa ações** nos que passam.

```bash
find [onde procurar] [opções globais] [testes] [ações]
```

Se omitir o caminho, o GNU `find` usa o diretório atual (`.`).

### 10.1 Anatomia

```bash
find /var/log -type f -name "*.log" -size +10M -mtime +30 -exec gzip {} \;
#    └──┬──┘  └──────────────── testes ─────────────────┘ └─── ação ───┘
#     caminho
```

- Os testes são ligados por **AND** implícito.
- Se você **não** informar nenhuma ação, o padrão é **`-print`**.

### 10.2 Testes por nome

| Teste | Descrição |
|---|---|
| `-name 'padrão'` | glob no **nome base** (só o nome, não o caminho), **diferencia** maiúsculas |
| `-iname 'padrão'` | igual, **ignorando** maiúsculas/minúsculas |
| `-path 'padrão'` | glob no **caminho completo** |
| `-regex 'expr'` | regex no caminho completo |

> ℹ️ Em `find -name`, o `*` **casa** com arquivos ocultos (diferente do shell).

```bash
find / -name "passwd"               # exatamente "passwd"
find /etc -name "*.conf"
find . -iname "readme*"             # README, readme, ReadMe...
find /home -path "*/Downloads/*"
```

### 10.3 Testes por tipo (`-type`)

| Letra | Tipo |
|---|---|
| `f` | arquivo regular |
| `d` | diretório |
| `l` | link simbólico |
| `b` | dispositivo de bloco |
| `c` | dispositivo de caractere |
| `p` | FIFO (pipe nomeado) |
| `s` | socket |

```bash
find /etc -type d          # só diretórios
find /dev -type b          # dispositivos de bloco
find . -type l             # links simbólicos
```

### 10.4 Testes por tamanho (`-size`)

Formato: `-size [+|-]N[unidade]`

| Unidade | Significado |
|---|---|
| `b` | blocos de **512 bytes** (**padrão** se omitir a unidade!) |
| `c` | **bytes** |
| `w` | palavras de 2 bytes |
| `k` | KiB (1024 bytes) |
| `M` | MiB |
| `G` | GiB |

| Notação | Significa |
|---|---|
| `+N` | **maior que** N |
| `-N` | **menor que** N |
| `N` | **exatamente** N |

```bash
find / -type f -size +100M          # maiores que 100 MiB
find . -size -10k                   # menores que 10 KiB
find . -size 0                      # arquivos vazios  (ou: -empty)
find . -size +1G
find . -size 512c                   # exatamente 512 bytes
```

> ⚠️ **Arredondamento para cima:** o `find` arredonda o tamanho **para cima** à unidade antes de comparar. Assim, `-size -1M` só casa com arquivos de **0 byte**, e `-size 1M` casa com arquivos de 1 byte até 1 MiB.
> ⚠️ `-size 10` (sem unidade) significa **10 blocos de 512 bytes**, não 10 bytes.

### 10.5 Testes por tempo

**Em dias (24 h):** `-atime`, `-mtime`, `-ctime`
**Em minutos:** `-amin`, `-mmin`, `-cmin`

| Notação | Significado em `-mtime` |
|---|---|
| `-mtime 0` | modificado nas **últimas 24 h** |
| `-mtime 1` | modificado **entre 24 h e 48 h atrás** |
| `-mtime +7` | modificado **há mais de 7 dias** (ou seja, ≥ 8 dias; a parte fracionária é descartada) |
| `-mtime -7` | modificado **há menos de 7 dias** (últimos 7 dias) |

> 🧠 **Regra mnemônica:** `+` = mais **velho** que, `-` = mais **novo** que. O número sem sinal = exatamente aquele "dia" (janela de 24 h).

```bash
find /tmp -type f -mtime +30            # não modificados há mais de 30 dias
find . -type f -mtime -1                # alterados no último dia
find /var/log -mmin -60                 # alterados na última hora
find . -newer referencia.txt            # mais novos que referencia.txt (mtime)
find . -newermt "2026-10-01"            # modificados após 01/10/2026
find . -newermt "2026-10-01" ! -newermt "2026-10-08"   # entre as duas datas
```

### 10.6 Testes por dono, grupo e permissões

| Teste | Descrição |
|---|---|
| `-user nome` | pertence ao usuário |
| `-group nome` | pertence ao grupo |
| `-uid N` / `-gid N` | por número |
| `-nouser` / `-nogroup` | dono/grupo **inexistente** no sistema (arquivos "órfãos") |
| `-perm MODO` | permissões **exatamente** `MODO` |
| `-perm -MODO` | **todos** os bits de `MODO` ligados (pode ter mais) |
| `-perm /MODO` | **qualquer um** dos bits de `MODO` ligado |
| `-empty` | arquivo vazio ou diretório vazio |
| `-links N` | número de hard links |

```bash
find / -user joao -type f
find /home -nouser                      # arquivos de usuário que foi apagado
find / -perm 644                        # exatamente rw-r--r--
find / -perm -4000 -type f 2>/dev/null  # arquivos com SUID ligado
find / -perm -2000 -type f 2>/dev/null  # arquivos com SGID ligado
find /tmp -perm /o+w                    # gravável por "outros" (qualquer bit w em others)
find . -type d -empty                   # diretórios vazios
```

### 10.7 Opções que controlam a busca

| Opção | Descrição |
|---|---|
| `-maxdepth N` | desce **no máximo** N níveis (`1` = só o diretório indicado) |
| `-mindepth N` | ignora níveis menores que N |
| `-depth` | processa o **conteúdo antes** do diretório |
| `-xdev` / `-mount` | **não atravessa** outros sistemas de arquivos |
| `-prune` | não desce no diretório que casou |

> ⚠️ Coloque `-maxdepth`/`-mindepth` **antes** dos testes, ou o GNU `find` avisa.

```bash
find . -maxdepth 1 -type f          # arquivos só do diretório atual
find / -xdev -type f -size +500M    # só na partição raiz
find . -path ./node_modules -prune -o -type f -print   # ignora node_modules
```

### 10.8 Operadores lógicos

| Operador | Equivale a | Observação |
|---|---|---|
| `-a` / `-and` | E | **padrão** entre testes |
| `-o` / `-or` | OU | menor precedência |
| `!` / `-not` | NÃO | maior precedência |
| `\( ... \)` | agrupamento | parênteses **escapados** (ou entre aspas) |

Precedência: `!` > `-a` > `-o`.

```bash
find . -name "*.jpg" -o -name "*.png"                 # ❌ pode surpreender com ações
find . \( -name "*.jpg" -o -name "*.png" \) -type f   # ✅ agrupado
find . -type f ! -name "*.txt"                        # tudo que NÃO é .txt
find . -type f -size +1M -a -mtime -7
```

### 10.9 Ações

| Ação | O que faz |
|---|---|
| `-print` | imprime o caminho (padrão) |
| `-print0` | imprime separando por **NUL** (para nomes com espaço/quebra de linha) |
| `-ls` | formato longo, como `ls -dils` |
| `-delete` | **apaga** os arquivos encontrados |
| `-exec CMD {} \;` | executa `CMD` **uma vez por arquivo** |
| `-exec CMD {} +` | executa `CMD` **com vários arquivos** por chamada (mais eficiente) |
| `-ok CMD {} \;` | como `-exec`, mas **pergunta antes de cada execução** |

#### `-exec`: `{}` e o terminador

- `{}` é substituído pelo **caminho do arquivo** encontrado.
- `\;` (ponto-e-vírgula **escapado**) encerra o comando → 1 execução por arquivo.
- `+` encerra o comando → junta vários arquivos numa execução só (como o `xargs`).

```bash
find . -name "*.tmp" -exec rm {} \;               # remove, 1 chamada por arquivo
find . -name "*.log" -exec ls -l {} +             # uma chamada com vários arquivos
find /home -name "*.bak" -ok rm {} \;             # pergunta antes de cada rm
find . -type f -name "*.sh" -exec chmod +x {} \;
find /etc -type f -name "*.conf" -exec cp {} /backup/ \;
find . -type f -exec grep -l "ERRO" {} +          # quais arquivos contêm "ERRO"
```

#### `-delete` e `xargs`

```bash
find /tmp -type f -mtime +30 -delete              # simples e rápido
find . -name "*.o" -print0 | xargs -0 rm          # seguro com espaços nos nomes
```

> ⚠️ `-delete` é uma **ação**: se vier **antes** dos testes, apaga tudo que foi percorrido. Teste primeiro com `-print` e só depois troque por `-delete`.
> ⚠️ `-delete` implica `-depth` e **não pergunta**.

### 10.10 Mais exemplos de prova

```bash
# Arquivos .conf em /etc modificados nas últimas 24h
find /etc -name "*.conf" -mtime -1

# Arquivos grandes (>50 MiB) na partição raiz, sem erros de permissão
find / -xdev -type f -size +50M 2>/dev/null

# Arquivos de um usuário alterados na última hora
find /home -user ana -mmin -60

# Comprimir logs com mais de 30 dias
find /var/log -name "*.log" -mtime +30 -exec gzip {} \;

# Copiar todas as imagens para um diretório
find . -type f \( -iname "*.jpg" -o -iname "*.png" \) -exec cp {} /backup/img/ \;

# Listar executáveis SUID
find / -type f -perm -u+s 2>/dev/null
```

> 💡 O `2>/dev/null` descarta os erros ("Permission denied") — redirecionamento é do tópico 103.4.

### 10.11 Tabela-resumo de `find`

| Quero... | Use |
|---|---|
| nome exato (case-sensitive) | `-name` |
| nome ignorando maiúsc./minúsc. | `-iname` |
| só arquivos / diretórios / links | `-type f` / `d` / `l` |
| maiores / menores que | `-size +N` / `-size -N` |
| alterados há mais de N dias | `-mtime +N` |
| alterados nos últimos N dias | `-mtime -N` |
| alterados nos últimos N minutos | `-mmin -N` |
| mais novos que outro arquivo | `-newer ARQ` |
| de um dono | `-user NOME` |
| com permissão exata / todos os bits / qualquer bit | `-perm M` / `-perm -M` / `-perm /M` |
| limitar profundidade | `-maxdepth N` |
| executar comando | `-exec CMD {} \;` ou `-exec CMD {} +` |
| apagar | `-delete` |

## 11. Identificando tipos: `file`

O `file` descobre o tipo **olhando o conteúdo** (números mágicos / *magic numbers*), **não a extensão**.

```bash
file arquivo
file /bin/ls /etc/passwd foto.png
file -b arquivo            # sem o nome (brief)
file -i arquivo            # tipo MIME (ex.: text/plain; charset=utf-8)
file -L link               # segue links simbólicos
file -z arquivo.gz         # olha dentro de arquivos compactados
file -s /dev/sda1          # lê dispositivos de bloco (partição/sistema de arquivos)
```

Exemplos de saída:

```text
/etc/passwd: ASCII text
/bin/ls:     ELF 64-bit LSB pie executable, x86-64, dynamically linked ...
foto.png:    PNG image data, 800 x 600, 8-bit/color RGBA
backup.tgz:  gzip compressed data, from Unix
/bin/sh:     symbolic link to dash
```

- A base de padrões fica em arquivos de *magic* (por exemplo `/usr/share/misc/magic.mgc` ou `/usr/share/file/magic.mgc`).
- Um arquivo renomeado (`foto.png` que na verdade é um `.zip`) **será identificado corretamente** pelo `file`.

## 12. Compactação: `gzip`, `bzip2`, `xz`

### 12.1 Ideia geral

Compactadores atuam em **um arquivo por vez** e, por padrão, **substituem o original** pelo compactado. Para juntar vários arquivos/diretórios, usa-se **`tar`** (seção 13) e depois compacta-se o resultado (`.tar.gz`, `.tar.bz2`, `.tar.xz`).

| Ferramenta | Extensão | Descompactar | Ver sem extrair | Velocidade | Taxa de compressão |
|---|---|---|---|---|---|
| `gzip` | `.gz` | `gunzip` / `gzip -d` | `zcat` | **mais rápido** | boa |
| `bzip2` | `.bz2` | `bunzip2` / `bzip2 -d` | `bzcat` | médio | melhor que gzip |
| `xz` | `.xz` | `unxz` / `xz -d` | `xzcat` | **mais lento** | **a melhor** |

Ordem usual de eficiência: **gzip < bzip2 < xz** (em tamanho final, quanto mais à direita, menor o arquivo).

### 12.2 `gzip` / `gunzip`

```bash
gzip arquivo                # gera arquivo.gz e REMOVE arquivo
gzip -k arquivo             # mantém o original (--keep)
gzip -9 arquivo             # compressão máxima (1 = rápido ... 9 = máxima; padrão 6)
gzip -c arquivo > arq.gz    # envia para stdout, mantém original
gzip -d arquivo.gz          # descompacta (igual a gunzip)
gunzip arquivo.gz           # descompacta e remove o .gz
gzip -l arquivo.gz          # mostra tamanho compactado/original e taxa
gzip -t arquivo.gz          # testa a integridade
gzip -r diretorio/          # compacta CADA arquivo dentro do diretório (não cria 1 arquivo só!)
zcat arquivo.gz             # exibe o conteúdo descompactado (gunzip -c)
```

Ferramentas relacionadas: `zcat`, `zless`, `zmore`, `zgrep`, `zdiff` (operam em arquivos `.gz` sem descompactar no disco).

### 12.3 `bzip2` / `bunzip2`

```bash
bzip2 arquivo               # gera arquivo.bz2 e remove o original
bzip2 -k arquivo            # mantém o original
bzip2 -9 arquivo            # tamanho de bloco 900k (padrão = -9)
bzip2 -d arquivo.bz2        # descompacta
bunzip2 arquivo.bz2
bzip2 -c arquivo > a.bz2    # stdout
bzip2 -t arquivo.bz2        # testa integridade
bzcat arquivo.bz2
```

### 12.4 `xz` / `unxz`

```bash
xz arquivo                  # gera arquivo.xz e remove o original
xz -k arquivo               # mantém o original
xz -9 arquivo               # compressão máxima (0 a 9; padrão 6)
xz -T0 arquivo              # usa todos os núcleos disponíveis
xz -d arquivo.xz            # descompacta
unxz arquivo.xz
xz -l arquivo.xz            # informações
xzcat arquivo.xz
```

### 12.5 Opções comuns aos três

| Opção | Significado |
|---|---|
| `-k` | **keep**: mantém o arquivo original |
| `-d` | **decompress** |
| `-c` | escreve na **saída padrão** (não altera/remove o original) |
| `-t` | **testa** a integridade |
| `-1` … `-9` | nível de compressão (rápido → máximo) |
| `-v` | verbose (mostra a taxa de compressão) |
| `-f` | força (sobrescreve) |

> 💡 `zip`/`unzip` (formato `.zip`, compatível com Windows) **diferem** dos três acima: o zip **guarda vários arquivos num único contêiner** e **mantém os originais**. Já `gzip`/`bzip2`/`xz` **não arquivam**, só compactam.

## 13. Arquivamento: `tar`

`tar` (*tape archive*) **junta** vários arquivos e diretórios **em um único arquivo** (o *tarball*), preservando estrutura, permissões, dono e timestamps. **Por si só, não compacta** — a compressão vem de uma opção extra (`-z`, `-j`, `-J`) que chama `gzip`, `bzip2` ou `xz`.

### 13.1 Modos de operação (escolha **um**)

| Opção | Nome longo | Função |
|---|---|---|
| `-c` | `--create` | **cria** um arquivo novo |
| `-x` | `--extract` | **extrai** |
| `-t` | `--list` | **lista** o conteúdo |
| `-r` | `--append` | **acrescenta** arquivos ao final (só em tar **não compactado**) |
| `-u` | `--update` | acrescenta só os que são **mais novos** (só em tar **não compactado**) |
| `-A` | `--catenate` | concatena outro `.tar` ao arquivo |
| `-d` | `--diff` / `--compare` | **compara** o arquivo com o sistema de arquivos |
| — | `--delete` | remove membros do arquivo (não funciona em fita) |

### 13.2 Modificadores

| Opção | Função |
|---|---|
| `-f ARQ` | **nome do arquivo** do tar (`-f -` = stdin/stdout). **Deve ser seguido do nome** |
| `-v` | verbose (lista o que está sendo processado) |
| `-z` | usa **gzip** (`.tar.gz` / `.tgz`) |
| `-j` | usa **bzip2** (`.tar.bz2` / `.tbz2`) |
| `-J` | usa **xz** (`.tar.xz` / `.txz`) |
| `-a` | escolhe a compressão **pela extensão** do nome |
| `-C DIR` | **muda para DIR** antes de operar (na extração: destino) |
| `-p` | **preserva permissões** exatas (ignora umask; padrão para root ao extrair) |
| `--exclude=PADRÃO` | **ignora** itens que casam com o padrão |
| `-X ARQ` | lê padrões de exclusão de um arquivo |
| `-T ARQ` | lê a **lista de arquivos** a incluir de um arquivo |
| `--strip-components=N` | remove N níveis de diretório dos nomes na extração |
| `-h` | **segue** links simbólicos (arquiva o alvo) |
| `-P` | mantém `/` inicial (caminhos absolutos) |
| `-g ARQ` | backup **incremental** com arquivo de snapshot |

### 13.3 Os comandos que você precisa saber de cor

```bash
# CRIAR
tar -cvf backup.tar /etc /home/ana         # só arquiva (sem compressão)
tar -czvf backup.tar.gz  /etc              # arquiva + gzip
tar -cjvf backup.tar.bz2 /etc              # arquiva + bzip2
tar -cJvf backup.tar.xz  /etc              # arquiva + xz

# LISTAR (sem extrair)
tar -tvf backup.tar
tar -tzvf backup.tar.gz

# EXTRAIR
tar -xvf backup.tar                        # extrai no diretório atual
tar -xzvf backup.tar.gz
tar -xjvf backup.tar.bz2
tar -xJvf backup.tar.xz
tar -xvf backup.tar.gz -C /tmp/restore     # extrai em outro diretório (o dir deve existir)
```

> 🧠 **Mnemônicos:** `c`reate, `x`tract, `t`able-of-contents/lis`t`, `v`erbose, `f`ile, `z` = gzip, `j` = bzip2, `J` = xz.
> Em versões recentes do GNU tar, a **extração detecta a compressão automaticamente**, mas na prova pode aparecer o `z`/`j`/`J` explícito.

### 13.4 Estilos de sintaxe (todos equivalentes)

```bash
tar -czvf a.tgz dir      # com hífen, opções agrupadas
tar czvf a.tgz dir       # estilo antigo (sem hífen) — válido!
tar --create --gzip --verbose --file=a.tgz dir   # nomes longos
```

> ⚠️ **`-f` deve vir por último no grupo**, pois o próximo argumento é o nome do arquivo:
> `tar -cfz a.tgz dir` ❌ → cria um arquivo chamado `z`.
> `tar -czf a.tgz dir` ✅

### 13.5 Mais exemplos

```bash
# Extrair UM arquivo/diretório específico (use o caminho exatamente como aparece no tar -t)
tar -xzvf backup.tar.gz etc/hosts

# Extrair com wildcard (precisa de --wildcards)
tar -xzvf backup.tar.gz --wildcards '*.conf'

# Adicionar arquivo a um tar NÃO compactado
tar -rvf backup.tar novo.txt

# Excluir itens
tar -czvf site.tgz --exclude='*.log' --exclude='cache' /var/www

# Backup a partir de outro diretório (evita guardar o caminho completo)
tar -czvf etc.tgz -C / etc
# → dentro do tar ficam nomes como  etc/hosts  (relativos)

# Pular o primeiro nível ao extrair
tar -xzvf pacote-1.0.tar.gz --strip-components=1 -C /opt/pacote

# Usar uma lista de arquivos
tar -czvf lista.tgz -T arquivos.txt

# Comparar com o disco
tar -dzvf backup.tar.gz

# Copiar uma árvore preservando tudo, via pipe, sem arquivo intermediário
tar -cf - /origem | tar -xf - -C /destino

# Backup remoto via SSH
tar -czf - /etc | ssh usuario@servidor "cat > /backup/etc.tgz"
```

### 13.6 Caminhos absolutos × relativos

Ao criar com caminho absoluto (`tar -cf a.tar /etc/hosts`), o GNU tar mostra:

```text
tar: Removing leading `/' from member names
```

Ele **remove a barra inicial** por segurança, para que a extração **não sobrescreva** o `/etc/hosts` real. Dentro do arquivo fica `etc/hosts`. Só com `-P` o `/` é mantido (perigoso).

### 13.7 Permissões e dono na extração

| Quem extrai | Comportamento padrão |
|---|---|
| **root** | preserva permissões exatas **e dono/grupo** (`--same-owner`) |
| **usuário comum** | arquivos passam a ser do usuário; permissões **filtradas pelo umask**, a menos que use `-p` |

### 13.8 Extensões comuns

| Extensão | Significado |
|---|---|
| `.tar` | só arquivado |
| `.tar.gz` / `.tgz` | tar + gzip |
| `.tar.bz2` / `.tbz2` | tar + bzip2 |
| `.tar.xz` / `.txz` | tar + xz |

## 14. Arquivamento: `cpio`

`cpio` (*copy in, copy out*) também cria e extrai arquivos, mas tem uma diferença fundamental em relação ao `tar`:

> 🔑 **No modo de criação, o `cpio` lê a lista de arquivos pela entrada padrão (stdin)** — quase sempre alimentada por `find` ou `ls`. Ele não recebe nomes como argumentos.

### 14.1 Os três modos

| Modo | Opção | O que faz | Entrada | Saída |
|---|---|---|---|---|
| **copy-out** | `-o` / `--create` | **cria** um arquivo | lista de nomes (stdin) | arquivo (stdout ou `-O`) |
| **copy-in** | `-i` / `--extract` | **extrai** (ou lista com `-t`) | arquivo (stdin ou `-I`) | arquivos no disco |
| **copy-pass** | `-p` / `--pass-through` | **copia** uma árvore para outro diretório (sem criar arquivo) | lista de nomes (stdin) | destino (argumento) |

> 🧠 Mnemônico: **o**ut = criar, **i**n = extrair, **p**ass = copiar direto.

### 14.2 Opções úteis

| Opção | Significado |
|---|---|
| `-v` | verbose |
| `-t` | **lista** o conteúdo (com `-i`) |
| `-d` | **cria diretórios** conforme necessário (na extração) — sem ele, diretórios não são criados |
| `-m` | **preserva mtime** na extração |
| `-u` | sobrescreve incondicionalmente (substitui arquivos mais novos) |
| `-H FORMATO` | formato do arquivo: `newc`, `crc`, `odc`, `tar`, `ustar`... |
| `-O ARQ` / `-I ARQ` | arquivo de saída / de entrada (em vez de stdout/stdin) |
| `-A` | acrescenta a um arquivo existente |
| `-0` | nomes separados por NUL (combine com `find -print0`) |
| `--no-absolute-filenames` | extrai caminhos absolutos como relativos (mais seguro) |

### 14.3 Exemplos

```bash
# CRIAR
find /etc -name "*.conf" | cpio -ov > conf.cpio
ls arq* | cpio -ov > arqs.cpio
find . -depth -print | cpio -ov > tudo.cpio
find . -print0 | cpio -0ov > seguro.cpio        # nomes com espaço

# LISTAR
cpio -tv < conf.cpio

# EXTRAIR
cpio -idv < conf.cpio                           # recria os diretórios
cpio -idmv < conf.cpio                          # + preserva mtime
cpio -idv --no-absolute-filenames < conf.cpio

# COPIAR UMA ÁRVORE (pass-through)
find /origem -depth -print | cpio -pdm /destino

# CRIAR COM COMPRESSÃO (cpio não comprime sozinho)
find . | cpio -o -H newc | gzip > initrd.img
# EXTRAIR um initramfs
zcat initrd.img | cpio -idmv
```

> ⚠️ Se os nomes entraram como **caminhos absolutos** (`/etc/hosts`), a extração tenta recriá-los **nos mesmos caminhos absolutos** — pode sobrescrever arquivos reais. Prefira nomes relativos (`cd /etc && find . | cpio -o`).
> ℹ️ O formato **`newc`** com `gzip` é o usado em **initramfs/initrd** (e pacotes RPM são cpio por dentro — `rpm2cpio pacote.rpm | cpio -idmv`).

### 14.4 `tar` × `cpio`

| Característica | `tar` | `cpio` |
|---|---|---|
| Lista de arquivos | **argumentos** | **stdin** (via `find`/`ls`) |
| Modo "copiar árvore" (sem arquivo) | via pipe `tar \| tar` | **`-p`** nativo |
| Compressão embutida | sim (`-z`, `-j`, `-J`) | **não** (use `gzip` em pipe) |
| Uso típico hoje | backups, distribuição de código | **initramfs**, pacotes RPM |
| Cria diretórios ao extrair | **automaticamente** | só com **`-d`** |

---

## 15. Cópia bruta de blocos: `dd`

O `dd` (*data duplicator*, apelidado de *"disk destroyer"*) copia dados **bloco a bloco**, **sem se importar com sistema de arquivos** — por isso serve para clonar discos, partições, gravar imagens e manipular o MBR.

### 15.1 Sintaxe

`dd` **não usa hífens**: seus parâmetros são `chave=valor`.

```bash
dd if=ENTRADA of=SAÍDA [bs=...] [count=...] [skip=...] [seek=...] [conv=...] [status=...]
```

| Parâmetro | Significado |
|---|---|
| `if=` | **input file** (padrão: stdin) |
| `of=` | **output file** (padrão: stdout) |
| `bs=` | **block size** para leitura **e** escrita |
| `ibs=` / `obs=` | block size só de entrada / só de saída |
| `count=` | copia **apenas N blocos** (de entrada) |
| `skip=` | **pula N blocos** no **início da ENTRADA** |
| `seek=` | **pula N blocos** no **início da SAÍDA** |
| `conv=` | conversões (veja abaixo) |
| `status=` | `none`, `noxfer`, `progress` |

> 🧠 **`skip` = entrada (input), `seek` = saída (output).** Pegadinha frequente.

### 15.2 Sufixos de tamanho

| Sufixo | Valor |
|---|---|
| `K`, `M`, `G` | **potências de 1024** (KiB, MiB, GiB) |
| `KB`, `MB`, `GB` | **potências de 1000** |
| `c` | 1 byte |
| `b` | 512 bytes |

Exemplos: `bs=1M` = 1 048 576 bytes; `bs=1MB` = 1 000 000 bytes.

### 15.3 Opções de `conv=` mais cobradas

| Valor | Efeito |
|---|---|
| `notrunc` | **não trunca** o arquivo de saída (essencial ao escrever **parte** de um arquivo/dispositivo) |
| `noerror` | **continua** após erros de leitura |
| `sync` | **preenche com zeros** blocos incompletos (use com `noerror` para manter o alinhamento) |
| `fsync` | grava fisicamente os dados no disco antes de terminar |
| `ucase` / `lcase` | converte para **maiúsculas** / **minúsculas** |
| `swab` | troca **pares de bytes** |

### 15.4 Exemplos

```bash
# Backup do MBR (primeiros 512 bytes do disco)
dd if=/dev/sda of=mbr.bkp bs=512 count=1

# Restaurar o MBR completo
dd if=mbr.bkp of=/dev/sda bs=512 count=1

# Restaurar SÓ o código de boot (446 bytes), preservando a tabela de partições
dd if=mbr.bkp of=/dev/sda bs=446 count=1

# Criar arquivo de 100 MiB preenchido com zeros
dd if=/dev/zero of=teste.img bs=1M count=100

# Arquivo de 1 GiB "esparso" (sem gravar de fato) — usa seek
dd if=/dev/zero of=esparso.img bs=1 count=0 seek=1G

# Arquivo com dados aleatórios
dd if=/dev/urandom of=aleatorio.bin bs=1K count=10

# Clonar disco inteiro (cuidado com a direção!)
dd if=/dev/sda of=/dev/sdb bs=64K conv=noerror,sync status=progress

# Imagem de disco compactada
dd if=/dev/sda bs=4M | gzip > sda.img.gz
gunzip -c sda.img.gz | dd of=/dev/sda bs=4M

# Criar ISO de um CD/DVD
dd if=/dev/cdrom of=disco.iso

# Gravar ISO em pendrive
dd if=distro.iso of=/dev/sdX bs=4M status=progress conv=fsync

# Apagar um disco (sobrescrever com zeros)
dd if=/dev/zero of=/dev/sdX bs=1M

# Converter texto para maiúsculas
dd if=entrada.txt of=saida.txt conv=ucase

# Ler a partir do 3º bloco de 512 bytes e copiar 1 bloco
dd if=/dev/sda of=bloco.bin bs=512 skip=2 count=1
```

### 15.5 Estrutura do MBR (muito cobrada)

| Bytes | Conteúdo |
|---|---|
| 0 – 445 (**446 bytes**) | código do *boot loader* (bootstrap) |
| 446 – 509 (**64 bytes**) | **tabela de partições** (4 entradas × 16 bytes) |
| 510 – 511 (**2 bytes**) | assinatura de boot `0x55AA` |
| **Total** | **512 bytes** |

### 15.6 Acompanhando o progresso

```bash
dd if=/dev/zero of=big.img bs=1M count=5000 status=progress   # progresso embutido
# Em outro terminal (alternativa clássica):
kill -USR1 $(pidof dd)          # dd imprime estatísticas parciais
```

Saída final (por padrão, em **stderr**):

```text
100+0 records in
100+0 records out
104857600 bytes (105 MB, 100 MiB) copied, 0.12 s, 870 MB/s
```

### 15.7 ⚠️ Cuidados

- **Confira `if` e `of`**: inverter os dois sobrescreve a origem com o destino.
- `dd` **não pede confirmação** e **não tem desfazer**.
- Antes de escrever em `/dev/sdX`, confirme o dispositivo com `lsblk` ou `fdisk -l`.
- Desmonte partições antes de clonar/gravar (`umount`).
- `bs` maior (1M–4M) é **muito** mais rápido que o padrão (512 bytes).

## 17. Pegadinhas clássicas de prova

1. **`cp` sem `-r` em diretório** → erro `omitting directory`.
2. **`*` não casa com arquivos ocultos** (`.bashrc`). Para incluí-los: `.*` ou `-A`/`dir/.`
3. **O shell expande o glob, não o comando.** Por isso, em `find -name`, **use aspas**.
4. **`ctime` ≠ criação.** É a mudança do **inode**.
5. **`-mtime +7` = mais de 7 dias** (≥ 8 dias completos), **não** "7 dias ou mais".
6. **`-size 10` = 10 blocos de 512 bytes.** Use `c`, `k`, `M`, `G` explicitamente.
7. **`-size -1M` só casa arquivos vazios** (arredondamento para cima).
8. **`find -exec ... \;` × `+`:** `\;` = 1 chamada por arquivo; `+` = vários por chamada.
9. **`-delete` antes dos testes** apaga tudo. Teste com `-print`.
10. **`rmdir` só apaga vazio.** Com conteúdo: `rm -r`.
11. **`mv` entre partições** = copiar + apagar (novo inode). Na mesma partição = só `rename`.
12. **`gzip`/`bzip2`/`xz` apagam o original** (a não ser com `-k` ou `-c`).
13. **`gzip -r dir` não cria um arquivo único**: compacta cada arquivo separadamente. Para isso, use `tar`.
14. **`tar` sem `-z/-j/-J`** não comprime (só junta). Extensão `.tar.gz` ≠ obrigatoriamente compactado, o conteúdo é que importa (`file` mostra).
15. **`tar -cfz`** cria um arquivo chamado `z`: **`-f` precisa vir por último**.
16. **`tar` remove a `/` inicial** dos caminhos (`Removing leading '/'`).
17. **`-r` e `-u` do `tar` não funcionam em arquivos compactados.**
18. **`cpio -o` lê nomes do stdin**; esquecer o `find`/`ls` é erro comum. Sem `-d`, não recria diretórios.
19. **`dd`: `skip` mexe na entrada, `seek` na saída.** E `conv=notrunc` evita truncar o destino.
20. **`dd if=... of=...` não usa hífen**, e `bs=1M` ≠ `bs=1MB`.
21. **MBR = 446 (boot) + 64 (partições) + 2 (assinatura) = 512 bytes.**
22. **`file` olha o conteúdo, não a extensão.**
23. **`brace expansion {a,b}` não exige que o arquivo exista**; `[ab]` exige.
24. **Em RHEL, root costuma ter `cp`/`mv`/`rm` com alias `-i`.**
