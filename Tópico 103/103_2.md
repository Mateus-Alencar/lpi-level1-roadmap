# Tópico 103.2 - Processar fluxos de texto usando filtros

### 1. Visão geral

Este tópico do exame LPIC-1 (101/102) avalia a capacidade de **manipular conteúdo de arquivos de texto** usando comandos de filtro — programas que recebem texto pela entrada padrão (stdin), transformam esse texto de alguma forma, e enviam o resultado para a saída padrão (stdout). Esses filtros são a base do estilo Unix de "combinar ferramentas pequenas via pipe (`|`)" para resolver tarefas complexas.

**Comandos cobrados oficialmente:** `cat`, `cut`, `expand`, `fmt`, `head`, `join`, `nl`, `od`, `paste`, `pr`, `sed`, `sort`, `split`, `tail`, `tr`, `unexpand`, `uniq`, `wc`

Vou explicar cada um com sintaxe, opções mais cobradas e exemplos práticos.

---

### 2. Conceitos-chave antes de começar

- **stdin / stdout / stderr**: todo filtro, por padrão, lê da entrada padrão e escreve na saída padrão. Se você não passar um arquivo como argumento, o comando espera texto digitado ou vindo de um pipe.
- **Pipe (`|`)**: conecta a saída de um comando à entrada do próximo. Ex.: `cat arquivo.txt | sort | uniq`
- **Redirecionamento**: `>` (sobrescreve), `>>` (concatena/acrescenta), `<` (usa arquivo como entrada).
- A maioria desses comandos aceita **múltiplos arquivos** como argumento e, se nenhum for informado, lê de stdin.

---

### 3. `cat` — concatenar e exibir arquivos

Exibe o conteúdo de um ou mais arquivos, concatenando-os na saída.

```bash
cat arquivo.txt
cat arquivo1.txt arquivo2.txt > unido.txt
```

**Opções importantes:**

| Opção | Função |
| --- | --- |
| `-n` | numera todas as linhas |
| `-b` | numera apenas linhas não vazias |
| `-s` | comprime múltiplas linhas em branco em uma só (squeeze) |
| `-A` | mostra caracteres não imprimíveis (`$` no fim da linha, `^I` para tab) |
| `-E` | mostra `$` no final de cada linha |
| `-T` | mostra tabs como `^I` |

> **Dica de prova:** `tac` é o `cat` "de trás para frente" — exibe as linhas do arquivo em ordem inversa (última linha primeiro). É um comando separado, mas costuma ser citado junto de `cat`.

```bash
tac arquivo.txt
```

---

### 4. `head` e `tail` — início e fim de arquivos

**`head`** mostra as primeiras linhas de um arquivo (padrão: 10 linhas). **`tail`** mostra as últimas linhas (padrão: 10 linhas).

```bash
head arquivo.txt          # 10 primeiras linhas
head -n 5 arquivo.txt     # 5 primeiras linhas
head -5 arquivo.txt       # forma abreviada (equivalente)
tail -n 20 arquivo.txt    # 20 últimas linhas
```

**Opção mais cobrada em prova: `tail -f`**

```bash
tail -f /var/log/syslog
```

Mantém o comando "vivo", exibindo novas linhas conforme são adicionadas ao arquivo — muito usado para monitorar logs em tempo real. Use `Ctrl+C` para sair.

Outras opções úteis:

- `head -c 100 arquivo` → primeiros 100 bytes
- `tail -c 100 arquivo` → últimos 100 bytes
- `tail -n +5 arquivo` → exibe a partir da linha 5 até o final (o `+` é a pegadinha clássica de prova)

---

### 5. `wc` — contar palavras, linhas e caracteres

```bash
wc arquivo.txt
```

Saída padrão: `linhas palavras bytes nome_do_arquivo`

| Opção | Função |
| --- | --- |
| `-l` | conta apenas linhas |
| `-w` | conta apenas palavras |
| `-c` | conta bytes |
| `-m` | conta caracteres (relevante em locales multibyte/UTF-8) |
| `-L` | mostra o comprimento da linha mais longa |

```bash
wc -l arquivo.txt        # número de linhas
cat arquivo.txt | wc -l  # mesma coisa via pipe
```

### 6. `sort` — ordenar linhas de texto

```bash
sort arquivo.txt
```

Por padrão, ordena alfabeticamente (ordem ASCII/locale).

| Opção | Função |
| --- | --- |
| `-r` | ordem reversa (decrescente) |
| `-n` | ordenação **numérica** (essencial: sem isso, "10" vem antes de "2") |
| `-f` | ignora maiúsculas/minúsculas (fold case) |
| `-u` | remove duplicatas (equivalente a `sort \| uniq`) |
| `-k N` | ordena pela coluna/campo N |
| `-t ','` | define o delimitador de campo (ex.: vírgula, para CSV) |
| `-b` | ignora espaços em branco no início |
| `-M` | ordena por nomes de meses (jan, fev, mar...) |
| `-h` | ordena por números "legíveis por humanos" (ex.: 2K, 1G) |

**Exemplo clássico de prova — ordenar CSV pela segunda coluna, numericamente:**

```bash
sort -t ',' -k2 -n arquivo.csv
```

**Combinando `sort` com múltiplos critérios:**

```bash
sort -k1,1 -k2n arquivo.txt   # ordena por campo 1 (texto), depois campo 2 (numérico)
```

---

### 7. `uniq` — eliminar ou contar linhas duplicadas adjacentes

> **Pegadinha clássica:** `uniq` só remove duplicatas **consecutivas**. Por isso quase sempre é usado depois de `sort`.

```bash
sort arquivo.txt | uniq
```

| Opção | Função |
| --- | --- |
| `-c` | conta quantas vezes cada linha se repete |
| `-d` | mostra apenas as linhas que **têm** duplicatas |
| `-u` | mostra apenas as linhas que **não** têm duplicatas (únicas) |
| `-i` | ignora diferenças de maiúsculas/minúsculas |

```bash
sort arquivo.txt | uniq -c | sort -rn   # ranking de linhas mais frequentes
```

---

### 8. `cut` — extrair colunas/campos de cada linha

Extrai "fatias" de cada linha: por posição de caractere ou por campo delimitado.

| Opção | Função |
| --- | --- |
| `-c LISTA` | seleciona por posição de caractere (ex.: `-c1-5`) |
| `-f LISTA` | seleciona por campo (ex.: `-f1,3`) |
| `-d DELIM` | define o delimitador de campo (padrão é TAB) |
| `--complement` | inverte a seleção (mostra tudo, exceto o listado) |
| `-s` | omite linhas que não contêm o delimitador |

```bash
cut -d ':' -f1 /etc/passwd        # extrai a 1ª coluna (nome do usuário) do /etc/passwd
cut -c1-10 arquivo.txt            # os 10 primeiros caracteres de cada linha
cut -d ',' -f1,3-5 dados.csv      # campos 1, e do 3 ao 5
```

---

### 9. `paste` — combinar linhas de arquivos lado a lado

Enquanto `cat` empilha arquivos verticalmente, `paste` os junta **horizontalmente**, linha a linha.

```bash
paste arquivo1.txt arquivo2.txt
```

Por padrão, separa os campos com TAB.

| Opção | Função |
| --- | --- |
| `-d DELIM` | define outro delimitador (ex.: `-d ','`) |
| `-s` | junta todas as linhas de **um mesmo arquivo** em uma única linha (serial) |

```bash
paste -d ',' nomes.txt idades.txt   # combina em CSV
paste -s arquivo.txt                # transforma todas as linhas em uma só linha
```

---

### 10. `join` — juntar linhas de dois arquivos por um campo comum

Funciona como um `JOIN` de banco de dados: combina linhas de dois arquivos que compartilham um campo-chave. **Pré-requisito importante: os dois arquivos precisam estar ordenados (`sort`) pelo campo usado na junção.**

```bash
join arquivo1.txt arquivo2.txt
```

| Opção | Função |
| --- | --- |
| `-1 N` | número do campo-chave no primeiro arquivo |
| `-2 N` | número do campo-chave no segundo arquivo |
| `-t DELIM` | delimitador de campo |
| `-a N` | inclui também linhas sem correspondência do arquivo N |

```bash
sort f1.txt > f1s.txt
sort f2.txt > f2s.txt
join -1 1 -2 1 f1s.txt f2s.txt
```

---

### 11. `split` — dividir um arquivo em partes menores

Útil para fragmentar arquivos grandes (ex.: antes de enviar por e-mail ou gravar em mídia).

```bash
split -l 1000 arquivo.txt parte_    # divide em pedaços de 1000 linhas
split -b 10M arquivo.iso pedaco_    # divide em pedaços de 10 MB
```

| Opção | Função |
| --- | --- |
| `-l N` | N linhas por arquivo |
| `-b TAM` | tamanho em bytes por arquivo (aceita sufixos K, M, G) |
| `-d` | usa sufixos numéricos (00, 01, 02...) em vez de letras (aa, ab, ac...) |

Os arquivos resultantes recebem o prefixo informado + um sufixo sequencial (`parte_aa`, `parte_ab`, ...).

### 12. `fmt` e `fold` — reformatar largura de texto

**`fmt`**: reformata parágrafos de texto, ajustando quebras de linha a uma largura ideal (respeita palavras — não corta no meio delas).

```bash
fmt -w 60 arquivo.txt
```

**`fold`**: quebra linhas em um número fixo de colunas, **cortando palavras** se necessário (não é "esperto" como o `fmt`).

```bash
fold -w 40 arquivo.txt
fold -s -w 40 arquivo.txt   # -s evita cortar no meio de palavras
```

> **Diferença chave de prova:** `fmt` reflui parágrafos preservando palavras inteiras; `fold` simplesmente quebra a linha na coluna N, mesmo no meio de uma palavra (a menos que use `-s`).

### 13. `expand` e `unexpand` — converter tabs ↔ espaços

```bash
expand arquivo.txt      # converte TABs em espaços
unexpand -a arquivo.txt # converte espaços em TABs
```

| Opção | Função |
| --- | --- |
| `-t N` | define o tamanho da tabulação (padrão: 8) |
| `-a` (unexpand) | converte espaços em TAB em toda a linha, não só no início |

---

### 14. `nl` — numerar linhas

Similar a `cat -n`, mas com muito mais controle de formatação.

```bash
nl arquivo.txt
```

| Opção | Função |
| --- | --- |
| `-b a` | numera **todas** as linhas (inclusive vazias) |
| `-b t` | numera apenas linhas com texto (comportamento padrão) |
| `-i N` | incrementa a numeração de N em N |
| `-s STR` | define o separador entre número e texto |
| `-w N` | largura do campo de numeração |

```bash
nl -b a -i 5 arquivo.txt   # numera todas as linhas, incrementando de 5 em 5
```

---

### 15. `pr` — formatar texto para impressão

Formata arquivos em páginas, com cabeçalhos, rodapés e colunas — pensado para saída em impressora.

```bash
pr arquivo.txt
```

| Opção | Função |
| --- | --- |
| `-l N` | linhas por página |
| `-d` | espaçamento duplo |
| `-h TITULO` | define um cabeçalho personalizado |
| `-columns N` | formata em N colunas |

---

### 16. `od` — dump octal / visualização binária

Exibe o conteúdo de um arquivo em formatos não textuais (octal, hexadecimal, decimal, ASCII) — essencial para inspecionar arquivos binários ou caracteres invisíveis.

```bash
od -c arquivo.txt    # mostra caracteres (inclusive de controle, como \t \n)
od -x arquivo.bin    # dump em hexadecimal
od -An -tx1 arquivo  # hex sem o offset à esquerda
```

| Opção | Função |
| --- | --- |
| `-c` | exibe como caracteres ASCII |
| `-x` / `-t x1` | exibe em hexadecimal |
| `-o` (padrão) | exibe em octal |
| `-A` | formato do endereço/offset (`d`=decimal, `x`=hex, `n`=nenhum) |

---

### 17. `tr` — traduzir ou remover caracteres

`tr` **não aceita nome de arquivo como argumento** — só funciona com stdin/pipe. É outra pegadinha comum de prova.

```bash
cat arquivo.txt | tr 'a-z' 'A-Z'     # minúsculas para maiúsculas
echo "ola mundo" | tr ' ' '_'        # espaços por underline
```

| Opção | Função |
| --- | --- |
| `-d` | deleta os caracteres do conjunto especificado |
| `-s` | comprime (squeeze) caracteres repetidos consecutivos em um só |
| `-c` | usa o complemento do conjunto (tudo, exceto o listado) |

```bash
cat arquivo.txt | tr -d '0-9'        # remove todos os dígitos
cat arquivo.txt | tr -s ' '          # comprime espaços múltiplos em um único
```

### 18. `sed` — editor de fluxo (stream editor)

O mais poderoso e mais cobrado dos filtros de texto. Aplica comandos de edição linha a linha, sem abrir um editor interativo.

**Sintaxe básica de substituição:**

```bash
sed 's/padrao/substituto/' arquivo.txt
```

| Componente | Função |
| --- | --- |
| `s` | comando de substituição |
| `g` | flag: substitui **todas** as ocorrências na linha (sem ela, só a 1ª) |
| `i` | flag: ignora maiúsculas/minúsculas |
| `p` | flag: imprime a linha (útil com `-n`) |
| `-n` | suprime a saída padrão (usado com `p` para exibir só o que interessa) |
| `-i` | edita o arquivo **in place** (modifica o arquivo original) |
| `-e` | permite combinar múltiplas expressões |

**Exemplos essenciais para o exame:**

```bash
sed 's/gato/cachorro/' arquivo.txt        # troca a 1ª ocorrência por linha
sed 's/gato/cachorro/g' arquivo.txt       # troca TODAS as ocorrências
sed -i 's/gato/cachorro/g' arquivo.txt    # troca e SALVA no próprio arquivo
sed '2d' arquivo.txt                      # deleta a linha 2
sed '/padrao/d' arquivo.txt               # deleta linhas que contêm "padrao"
sed -n '5,10p' arquivo.txt                # exibe só as linhas 5 a 10
sed '3a\texto novo' arquivo.txt           # adiciona linha após a linha 3
sed '3i\texto novo' arquivo.txt           # insere linha antes da linha 3
```

> **Dica de prova:** `sed -i.bak 's/x/y/' arquivo` cria um backup (`arquivo.bak`) antes de editar in place.

### 19. `grep`, `egrep`, `fgrep` — buscar padrões (relevante ao tópico, embora tecnicamente do 103.7)

Ainda que a busca por padrões seja formalmente o objetivo 103.7, `grep` aparece constantemente combinado aos filtros deste tópico, então vale revisar o essencial:

```bash
grep 'padrao' arquivo.txt
grep -i 'padrao' arquivo.txt     # ignora maiúsculas/minúsculas
grep -v 'padrao' arquivo.txt     # inverte: mostra linhas que NÃO batem
grep -r 'padrao' /diretorio/     # busca recursiva
grep -n 'padrao' arquivo.txt     # mostra o número da linha
grep -c 'padrao' arquivo.txt     # conta quantas linhas casam
grep -E 'padrao1|padrao2' arq    # regex estendida (equivale a egrep)
```

### 20. Combinando filtros com pipes (o "espírito" do tópico 103.2)

A prova adora testar a combinação de vários comandos em uma pipeline só. Exemplos típicos:

```bash
# Top 5 palavras mais frequentes em um arquivo
cat arquivo.txt | tr ' ' '\n' | sort | uniq -c | sort -rn | head -5

# Contar quantos usuários existem no /etc/passwd
cut -d ':' -f1 /etc/passwd | wc -l

# Listar processos ordenados por uso de memória, mostrando os 3 maiores
ps aux | sort -k4 -rn | head -3

# Remover linhas em branco e duplicadas de um arquivo
sed '/^$/d' arquivo.txt | sort | uniq
```

### 22. Pegadinhas mais comuns na prova

1. **`uniq` sem `sort` antes** — não remove duplicatas não adjacentes.
2. **`sort` sem `-n`** — ordena "10", "2", "33" como texto (10 vem antes de 2).
3. **`tr` não aceita arquivo como argumento** — precisa de pipe ou `<`.
4. **`tail -n +N`** — exibe a partir da linha N (não confundir com `tail -n N`, que mostra as últimas N linhas).
5. **`fmt` vs `fold`** — `fmt` nunca corta palavras; `fold` corta, a menos que use `-s`.
6. **`join` exige arquivos ordenados** pelo campo de junção.
7. **`sed 's/x/y/'` sem `g`** troca só a primeira ocorrência por linha.
8. **`sed -i`** modifica o arquivo original — cuidado ao testar comandos.
