#  Tópico 103.1: Trabalhar na Linha de Comando

## 1. O que é o Bash

O **bash** (Bourne Again SHell) é o shell padrão na maioria das distribuições Linux. É um interpretador de comandos: lê o que você digita, interpreta e executa.

```bash
echo $BASH_VERSION      # mostra a versão do bash em uso
echo $0                 # mostra o shell atual (ex: -bash ou /bin/bash)
```

Outros shells existem (`sh`, `dash`, `zsh`, `ksh`), mas o bash é o foco da prova.

## 2. Comandos simples e sequências em uma linha

### 2.1 Separando comandos na mesma linha

| Operador | Significado |
| --- | --- |
| `;` | Executa o comando seguinte **sempre**, independente do resultado do anterior |
| `&&` | Executa o comando seguinte **somente se** o anterior teve sucesso (status 0) |
| `\|\|` | Executa o comando seguinte **somente se** o anterior falhou (status ≠ 0) |
| `&` | Executa o comando em **segundo plano** (background) |

```bash
pwd; whoami; date                 # executa os três, um após o outro
mkdir teste && cd teste           # só entra na pasta se ela foi criada com sucesso
ls arquivo.txt || echo "não existe"
sleep 30 &                        # roda em background, libera o terminal
```

### 2.2 Verificando o status de saída

```bash
echo $?      # mostra o código de retorno do último comando (0 = sucesso; 1 = erro; 2 = uso incorreto do comando)
```

### 2.3 Pipes e redirecionamento (revisão rápida — aprofundado em outro tópico)

```bash
comando1 | comando2     # a saída do comando1 vira entrada do comando2
comando > arquivo        # redireciona saída padrão (sobrescreve)
comando >> arquivo       # redireciona saída padrão (acrescenta)
comando < arquivo        # redireciona entrada padrão
```

## 3. Variáveis de ambiente e variáveis de shell

### 3.1 Diferença fundamental

- **Variável de shell**: existe apenas no shell atual, não é passada para processos filhos.
- **Variável de ambiente**: exportada, é herdada por qualquer processo/subshell criado a partir dali.

```bash
MINHA_VAR="valor"        # variável de shell (local)
export MINHA_VAR         # agora também é variável de ambiente
# ou em uma linha:
export OUTRA_VAR="valor"
```

### 3.2 Comandos principais

| Comando | Função |
| --- | --- |
| `set` | Lista **todas** as variáveis (shell + ambiente) e funções definidas no shell atual |
| `env` | Lista **apenas** as variáveis de ambiente (as exportadas) |
| `export` | Marca uma variável como variável de ambiente (ou exibe as já exportadas com `export -p`) |
| `unset` | Remove uma variável (de shell ou de ambiente) |
| `echo $VAR` | Mostra o valor da variável `VAR` |

```bash
set                    # todas as variáveis do shell
env                    # só as exportadas
export -p              # lista variáveis exportadas no formato "declare -x"
unset MINHA_VAR         # apaga a variável
```

⚠️ **Pegadinha clássica de prova**: `set` sem argumentos mostra mais variáveis que `env`, porque `set` inclui as variáveis locais não exportadas.

### 3.3 Variáveis de ambiente importantes

| Variável | Conteúdo |
| --- | --- |
| `$PATH` | Lista de diretórios onde o shell procura executáveis |
| `$HOME` | Diretório home do usuário |
| `$USER` | Nome do usuário logado |
| `$PWD` | Diretório de trabalho atual |
| `$OLDPWD` | Diretório anterior (usado por `cd -`) |
| `$SHELL` | Caminho do shell padrão do usuário |
| `$PS1` | Formato do prompt principal do shell |
| `$LANG` / `$LC_*` | Configurações de idioma/localização |
| `$0` | Nome do shell/script em execução |
| `$?` | Código de saída do último comando |
| `$$` | PID do shell atual |

```bash
echo $PATH
echo $HOME
echo "Usuário: $USER, PID: $$"
```

### 3.4 Editando o PATH

```bash
echo $PATH
export PATH=$PATH:/opt/meuprograma/bin    # adiciona um diretório ao PATH
export PATH=/opt/meuprograma/bin:$PATH    # adiciona no início (tem prioridade)
```

### 3.5 Aspas (Quoting)

Fundamental para controlar como o shell interpreta variáveis, espaços e caracteres especiais.

| Tipo | Símbolo | Comportamento |
| --- | --- | --- |
| Aspas duplas | `" "` | Expande variáveis (`$VAR`) e substituição de comandos, mas protege espaços e a maioria dos caracteres especiais |
| Aspas simples | `' '` | **Literal total** — nada é expandido, nem variáveis |
| Backslash | `\` | Escapa (neutraliza) o caractere especial seguinte |
| Crase / `$()` | `` ` ` `` ou `$()` | Substituição de comando — executa o comando e substitui pelo resultado |

```bash
NOME="Mundo"
echo "Olá, $NOME"      # → Olá, Mundo   (expande)
echo 'Olá, $NOME'      # → Olá, $NOME   (literal)
echo Olá,\ $NOME        # → Olá, Mundo   (escapa o espaço)

DATA=$(date +%Y-%m-%d)  # forma moderna, preferida
DATA=`date +%Y-%m-%d`   # forma antiga (crases), ainda cai em prova
echo "Hoje é $DATA"
```

## 4. Histórico de comandos

O bash mantém um histórico dos comandos digitados.

### 4.1 Arquivo de histórico

- `~/.bash_history` — arquivo onde o histórico é **gravado ao final da sessão** (ou via `history -a`).
- Enquanto o shell está aberto, o histórico fica em memória; só é escrito no arquivo quando a sessão termina normalmente.

### 4.2 Comando `history`

```bash
history            # lista todo o histórico com números
history 10         # lista os últimos 10 comandos
history -c         # limpa o histórico da sessão atual (em memória)
history -w         # grava o histórico da memória no arquivo agora
history -a         # anexa novos comandos da sessão ao arquivo
!123                # reexecuta o comando de número 123 do histórico
!!                   # reexecuta o último comando
!ping                # reexecuta o último comando que começou com "ping"
```

### 4.3 Atalhos úteis de edição de linha (Emacs-style, padrão do bash)

| Atalho | Ação |
| --- | --- |
| `Ctrl+R` | Busca reversa no histórico (incremental) |
| `Ctrl+A` | Vai para o início da linha |
| `Ctrl+E` | Vai para o fim da linha |
| `Ctrl+U` | Apaga da posição do cursor até o início |
| `Ctrl+K` | Apaga da posição do cursor até o fim |
| `Ctrl+C` | Cancela o comando atual |
| `Ctrl+D` | Fecha o shell (EOF) / apaga caractere à frente |
| `Tab` | Autocompletar |

### 4.4 Variáveis relacionadas ao histórico

| Variável | Função |
| --- | --- |
| `$HISTSIZE` | Número de comandos mantidos em memória durante a sessão |
| `$HISTFILESIZE` | Número máximo de linhas guardadas no arquivo `.bash_history` |
| `$HISTFILE` | Caminho do arquivo de histórico (padrão: `~/.bash_history`) |
| `$HISTCONTROL` | Controla duplicatas/espaços (ex: `ignoredups`, `ignorespace`, `ignoreboth`) |

```bash
export HISTSIZE=1000
export HISTFILESIZE=2000
export HISTCONTROL=ignoredups
```

## 5. Invocando comandos: dentro e fora do PATH

### 5.1 O que é o PATH e como funciona a busca

Quando você digita um comando, o shell procura um executável com esse nome em cada diretório listado em `$PATH`, na ordem em que aparecem, e executa o **primeiro** que encontrar.

```bash
echo $PATH
# ex: /usr/local/bin:/usr/bin:/bin:/usr/local/games
```

### 5.2 Comandos para investigar como um comando será executado

| Comando | Função |
| --- | --- |
| `type comando` | Diz **como** o comando será interpretado: alias, função, builtin (interno do shell) ou arquivo executável (e onde) |
| `which comando` | Mostra o **caminho completo** do executável que seria chamado, procurando no PATH |
| `whereis comando` | Mostra binário, código-fonte e páginas de manual (não se limita ao PATH) |
| `man comando` | Exibe o manual (documentação) do comando |
| `uname` | Mostra informações do sistema/kernel |

```bash
type cd            # cd is a shell builtin
type ls             # ls is /usr/bin/ls  (ou aliased, dependendo do sistema)
type -a python      # mostra TODAS as ocorrências (alias, função, builtins, todos os caminhos no PATH)

which ls            # /usr/bin/ls
which -a ls         # mostra todas as ocorrências no PATH, não só a primeira

uname               # Linux
uname -a             # todas as informações: kernel, hostname, versão, arquitetura
uname -r             # apenas a versão do kernel
```

> [!WARNING]  
> **Diferença importante para a prova**: `type` é um **builtin do bash** e entende aliases/funções/builtins; `which` é um **programa externo** que só enxerga o PATH (não sabe de aliases e funções do shell, em muitos sistemas).

### 5.3 Executando comandos que NÃO estão no PATH

Se o diretório do executável não está no `$PATH`, é preciso indicar o caminho explicitamente:

```bash
./meuscript.sh         # executa no diretório atual (precisa do "./")
/opt/app/bin/programa    # caminho absoluto
../pasta/script.sh      # caminho relativo
```

Sem o `./` ou caminho, o bash procuraria `meuscript.sh` apenas nos diretórios do PATH — e falharia com "command not found" se ele não estiver lá (o diretório atual `.` **não** costuma estar no PATH por padrão, por segurança).

### 5.4 Permissão de execução

Um script só roda diretamente se tiver permissão de execução:

```bash
chmod +x meuscript.sh
./meuscript.sh
```

## 7. Resumo — pontos que mais caem na prova

- `set` mostra mais variáveis que `env` (inclui as não exportadas).
- `export VAR=valor` transforma uma variável de shell em variável de ambiente.
- `unset VAR` remove a variável.
- Aspas simples `'...'` = literal; aspas duplas `"..."` = expande `$var` e `` `cmd` ``.
- `history -c` limpa da memória; `history -w` grava no arquivo.
- `.bash_history` só é atualizado ao encerrar a sessão (ou com `history -a`/`-w`).
- `!!` repete o último comando; `!n` repete o comando número `n`.
- `type` é builtin e reconhece alias/função/builtin/arquivo; `which` só busca no PATH.
- Para rodar um executável fora do PATH (ex: no diretório atual), é necessário `./` ou caminho completo.
- `&&` só executa o segundo comando se o primeiro teve sucesso; `||` só se falhou; `;` executa sempre.
