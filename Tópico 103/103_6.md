## 1. Objetivos oficiais

Os três conhecimentos principais cobrados:

- Saber qual é a **prioridade padrão** de um processo criado.
- **Executar** um programa com prioridade **maior ou menor** que a padrão.
- **Alterar** a prioridade de um processo **já em execução**.

Termos e utilitários da lista oficial:

| Utilitário | Para que serve neste tópico |
|------------|-----------------------------|
| `nice`     | Iniciar um comando com um valor de nice diferente do padrão |
| `renice`   | Mudar o nice de um processo que já está rodando |
| `ps`       | Exibir o valor de nice (e prioridade) dos processos |
| `top`      | Exibir e alterar o nice interativamente |

---

## 2. Conceitos fundamentais

### 2.1 Escalonador (scheduler)

O **escalonador do kernel** decide qual processo usa a CPU e por quanto tempo. Em um sistema com mais processos prontos para rodar do que núcleos disponíveis, eles disputam tempo de CPU.

A prioridade influencia **quanto tempo de CPU** um processo recebe em relação aos outros **quando há disputa**. Se a CPU está ociosa, mudar o nice praticamente não muda nada na prática.

### 2.2 Dois conceitos que não se confundem

| Conceito | Sigla | Quem controla | Onde aparece |
|----------|-------|---------------|--------------|
| **Niceness** (gentileza) | `NI` | O **usuário/administrador** | `ps -l`, `top`, `renice`, `nice` |
| **Prioridade** do kernel | `PRI` / `PR` | O **kernel** (derivada do nice) | `ps -l`, `top` |

O que **você** altera com `nice` e `renice` é o **nice**. A prioridade (`PR`/`PRI`) é calculada pelo kernel a partir dele.

### 2.3 A lógica invertida (decore isto)

> **Quanto MENOR o valor de nice, MAIOR a prioridade.**
> **Quanto MAIOR o valor de nice, MENOR a prioridade.**

O nome vem do conceito: um processo "bonzinho" (*nice*, valor alto) **cede** CPU aos outros.

```
-20 ............ 0 ............ 19
Maior prioridade   Padrão     Menor prioridade
(menos "nice")                (mais "nice")
```

### 2.4 Herança

Um processo filho **herda** o nice do pai. Por isso, se você abre um shell com nice 10, todos os comandos executados nele rodam com nice 10 (a menos que alterados).

```bash
nice -n 10 bash     # novo shell com nice 10
nice                # imprime 10
ls                  # roda com nice 10 (herdado)
```

## 3. Valores de nice: o que a prova cobra

| Item | Valor |
|------|-------|
| Faixa de nice | **-20 a +19** |
| Nice padrão de um processo normal | **0** |
| Mais alta prioridade (menor nice) | **-20** |
| Mais baixa prioridade (maior nice) | **19** |
| Incremento padrão do comando `nice` (sem `-n`) | **+10** |
| Quem pode usar valores **negativos** | Somente o **root** |

> Valores fora da faixa são **ajustados** ao limite (ex.: `nice -n 100` resulta em 19; `nice -n -100` como root resulta em -20).

### 3.1 Relação com a coluna PR do `top`

Para processos de **escalonamento normal** (a imensa maioria):

```
PR = 20 + NI
```

| NI  | PR (top) |
|-----|----------|
| -20 | 0        |
| -10 | 10       |
| 0   | 20       |
| 10  | 30       |
| 19  | 39       |

Processos de **tempo real** (políticas `SCHED_FIFO`/`SCHED_RR`) aparecem com `rt` ou com PR negativo no `top`. Eles **não** são controlados por nice (veja a seção 11).

> **Atenção ao `PRI` do `ps -l`:** o número exibido varia conforme a versão do `procps` (em sistemas atuais, um processo com nice 0 costuma mostrar `PRI` 80; em outros, 20). **Não decore o valor absoluto do `PRI`; foque no `NI`**, que é o que a prova pergunta.

## 4. Visualizando a prioridade (`ps` e `top`)

### 4.1 `ps -l` (formato longo)

```bash
ps -l
```

Saída típica:

```
F S   UID     PID    PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1000    2310    2301  0  80   0 -  2412 do_wai pts/0    00:00:00 bash
0 R  1000    2455    2310  0  80   0 -  1888 -      pts/0    00:00:00 ps
```

Colunas relevantes: **`PRI`** (prioridade do kernel) e **`NI`** (nice).

### 4.2 `ps` com colunas personalizadas (`-o`)

```bash
ps -o pid,ni,pri,comm -p 2310
ps -eo pid,ni,comm
ps -eo pid,ni,comm --sort=-ni     # maiores nices primeiro (menor prioridade)
ps -eo pid,ni,comm --sort=ni      # menores nices primeiro (maior prioridade)
```

Nomes de colunas úteis com `-o`:

| Coluna | Significado |
|--------|-------------|
| `ni` / `nice` | Valor de nice |
| `pri` | Prioridade |
| `pid` | ID do processo |
| `comm` | Nome do comando |
| `cls` | Classe de escalonamento (`TS`, `FF`, `RR`...) |
| `rtprio` | Prioridade de tempo real |

### 4.3 `top`

No `top`, as colunas **`PR`** e **`NI`** aparecem por padrão:

```
  PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
 2501 aluno     30  10   10.2g   1.1g   2.0m R  98.0   3.5   0:12.33 stress
 1021 root      20   0  172364  14344   9532 S   0.3   0.1   0:01.02 systemd
```

Teclas úteis dentro do `top`:

| Tecla | Ação |
|-------|------|
| `r`   | **Renice** (alterar nice de um processo) |
| `k`   | Matar (enviar sinal a) um processo |
| `u`   | Filtrar por usuário |
| `P`   | Ordenar por uso de CPU |
| `M`   | Ordenar por uso de memória |
| `q`   | Sair |

## 5. Iniciando um processo com prioridade diferente (`nice`)

### 5.1 Sintaxe

```bash
nice [OPÇÃO] [COMANDO [ARGUMENTOS]...]
```

### 5.2 Comportamentos

| Comando | Efeito |
|---------|--------|
| `nice` | Sem argumentos: **imprime o nice atual** do shell |
| `nice comando` | Executa o comando com nice **+10** (incremento padrão) |
| `nice -n 5 comando` | Soma **+5** ao nice atual |
| `nice -5 comando` | Forma antiga, equivale a `-n 5` (**+5**) |
| `nice -n -5 comando` | Soma **-5** (aumenta prioridade). **Só root** |
| `nice --5 comando` | Forma antiga, equivale a `-n -5` (**-5**). **Só root** |
| `nice -n 19 comando` | Menor prioridade possível |
| `nice -n -20 comando` | Maior prioridade possível (**só root**) |

> **Pegadinha clássica:** `nice -5 comando` **não** significa "nice igual a menos cinco". Significa **+5**. O valor **negativo** exige o traço duplo: `nice --5` ou, de forma moderna e clara, `nice -n -5`.

### 5.3 É um **incremento**, não um valor absoluto

O `nice` **soma** o valor ao nice atual do shell:

```bash
nice                       # 0
nice -n 5 nice             # 5   (0 + 5)
nice -n 5 nice -n 5 nice   # 10  (0 + 5 + 5)
```

Se o shell já estiver com nice 10 e você executar `nice -n 5 comando`, o comando rodará com **15**.

### 5.4 Exemplos

```bash
# Backup pesado sem atrapalhar o sistema
nice -n 19 tar czf /backup/home.tar.gz /home

# Compilação em baixa prioridade
nice -n 10 make -j4

# Como root: tarefa crítica com alta prioridade
sudo nice -n -10 ./processamento_urgente.sh

# Verificar o nice efetivo
nice -n 7 ps -o pid,ni,comm
```

### 5.5 Erro comum: usuário comum tentando prioridade negativa

```bash
$ nice -n -5 ls
nice: cannot set niceness: Permission denied
```

> Em algumas versões do `nice` o comando ainda executa, mas **sem** alterar a prioridade (apenas avisa). O ponto para a prova: **usuário comum não consegue** diminuir o nice abaixo do seu limite.

## 6. Alterando a prioridade de um processo em execução (`renice`)

### 6.1 Sintaxe

```bash
renice [-n] PRIORIDADE [-p] PID...
renice [-n] PRIORIDADE -g PGID...
renice [-n] PRIORIDADE -u USUÁRIO...
```

### 6.2 Opções de seleção de alvo

| Opção | Alvo |
|-------|------|
| `-p`, `--pid` | **PID** do processo (padrão se nada for informado) |
| `-g`, `--pgrp` | **ID de grupo de processos** (afeta todos do grupo) |
| `-u`, `--user` | **Usuário** (afeta **todos** os processos dele) |

### 6.3 Exemplos

```bash
# Define nice 10 para o PID 1234
renice -n 10 -p 1234

# Sintaxe antiga (ainda aceita)
renice 10 1234
renice +10 1234

# Define nice 5 para vários PIDs
renice -n 5 -p 1234 1235 1236

# Altera todos os processos do usuário "joao"
sudo renice -n 5 -u joao

# Altera todo um grupo de processos
renice -n 10 -g 3000

# Prioridade alta (só root)
sudo renice -n -5 -p 1234
```

### 6.4 Saída do comando

```
1234 (process ID) old priority 0, new priority 10
```

### 6.5 **`renice` define um valor ABSOLUTO**

Diferente do `nice` (que soma), o `renice` **substitui** o nice atual pelo valor informado:

```bash
# Processo está com nice 5
renice -n 10 -p 1234
# Agora está com nice 10 (e NÃO 15)
```

## 7. Alterando a prioridade pelo `top`

1. Execute `top`.
2. Pressione **`r`**.
3. Informe o **PID** do processo desejado e tecle Enter.
4. Informe o **novo valor de nice** e tecle Enter.

```
PID to renice [default pid = 2501]: 2501
Renice PID 2501 to value: 15
```

- Usuário comum: só pode **aumentar** o nice de processos **seus**.
- Root: pode informar qualquer valor entre -20 e 19.
- Se não tiver permissão, o `top` exibe uma mensagem de erro.

---

## 8. Regras de permissão

| Situação | Usuário comum | Root |
|----------|:-------------:|:----:|
| Iniciar comando com nice **positivo** (`nice -n 10`) | ✅ | ✅ |
| Iniciar comando com nice **negativo** (`nice -n -5`) | ❌ | ✅ |
| `renice` **aumentando** o nice (menos prioridade) de **processo próprio** | ✅ | ✅ |
| `renice` **diminuindo** o nice (mais prioridade) de processo próprio | ❌ | ✅ |
| `renice` de processo de **outro usuário** | ❌ | ✅ |
| Reverter um nice já aumentado para um valor menor | ❌ | ✅ |

### Exemplo prático da regra "sem volta"

```bash
$ sleep 500 &
[1] 4010
$ renice -n 10 -p 4010
4010 (process ID) old priority 0, new priority 10
$ renice -n 5 -p 4010          # tentando DIMINUIR o nice
renice: failed to set priority for 4010 (process ID): Permission denied
$ sudo renice -n 5 -p 4010     # root consegue
4010 (process ID) old priority 10, new priority 5
```

> Isso decorre do limite `RLIMIT_NICE` (padrão 0 para usuários comuns), que pode ser ajustado para usuários/grupos específicos em `/etc/security/limits.conf` (veja seção 11).

## 9. Diferenças `nice` × `renice` (pegadinhas)

| Característica | `nice` | `renice` |
|----------------|--------|----------|
| Quando usar | Ao **iniciar** um comando | Em processo **já em execução** |
| Alvo | Um **comando novo** | PID, grupo (`-g`) ou usuário (`-u`) |
| Como o valor é interpretado | **Incremento** (soma ao nice atual) | **Valor absoluto** (substitui) |
| Valor padrão se omitido | **+10** | Não há padrão (valor é obrigatório) |
| Forma antiga | `nice -5` = +5; `nice --5` = -5 | `renice 5 PID` |
| Imprime nice atual | Sim (`nice` sem argumentos) | Não |

## 10. Combinando com jobs e `nohup`

### 10.1 Em segundo plano

```bash
nice -n 15 ./script_longo.sh &
```

### 10.2 Com `nohup` (sobrevive ao logout)

```bash
nohup nice -n 10 ./script_longo.sh &
```

### 10.3 Renice de um job em background

```bash
sleep 300 &
# [1] 5120
renice -n 8 -p 5120
# ou usando $!, que guarda o PID do último processo em background
renice -n 8 -p $!
```

### 10.4 Conferindo

```bash
ps -o pid,ni,comm -p 5120
```

## 11. Tópicos extras

> Não fazem parte da lista oficial de comandos do 103.6, mas ajudam a entender o contexto e podem aparecer como alternativas em questões.

### 11.1 `chrt` — políticas de escalonamento / tempo real

`nice` só afeta processos na política normal (`SCHED_OTHER`). Para tempo real, usa-se `chrt`:

```bash
chrt -p 1234               # mostra política e prioridade do PID
sudo chrt -f 50 comando    # SCHED_FIFO, prioridade RT 50
sudo chrt -r 20 comando    # SCHED_RR (round-robin), prioridade RT 20
```

| Política | Tipo | Observação |
|----------|------|------------|
| `SCHED_OTHER` (TS) | Normal | Padrão; controlada por **nice** |
| `SCHED_BATCH` | Normal | Para cargas em lote, sem interatividade |
| `SCHED_IDLE` | Normal | Só roda quando nada mais quer CPU |
| `SCHED_FIFO` (FF) | Tempo real | Roda até terminar/ceder |
| `SCHED_RR` (RR) | Tempo real | Como FIFO, com fatias de tempo |

Prioridades de tempo real vão de 1 a 99 (maior número = **maior** prioridade, ao contrário do nice).

### 11.2 `ionice` — prioridade de E/S (disco)

`nice` afeta **CPU**, não disco. Para I/O:

```bash
ionice -c 3 comando        # classe "idle": só usa disco ocioso
ionice -c 2 -n 7 comando   # best-effort, prioridade 7 (menor)
ionice -p 1234             # consulta o PID
```

### 11.3 `/etc/security/limits.conf`

Permite conceder a usuários/grupos o direito de usar nice mais baixo:

```
# <domínio>  <tipo>  <item>  <valor>
joao         hard    nice    -5
@devs        soft    nice    0
```

### 11.4 Escalonador do kernel

O Linux usa o **CFS** (*Completely Fair Scheduler*) por muitos anos; em kernels mais recentes (6.6+) foi substituído pelo **EEVDF**. Em ambos, o nice funciona como **peso**: nice menor = maior fatia de CPU. Para a prova, o importante é o conceito, não o algoritmo.

### 11.5 Autogroup

Em muitas distribuições desktop, o kernel agrupa processos por sessão (`autogroup`). Isso pode fazer o `nice` ter efeito **menos perceptível entre sessões diferentes**, pois o escalonamento considera o grupo. É um detalhe que explica "por que meu `nice` parece não fazer diferença" em testes de laboratório.

## 12. Cheat sheet

```bash
# Ver o nice do shell atual
nice

# Iniciar comando com nice padrão de +10
nice comando

# Iniciar com nice específico (incremento)
nice -n 15 comando
nice -n -10 comando          # root

# Ver nice de processos
ps -l
ps -o pid,ni,pri,comm -p PID
ps -eo pid,ni,comm --sort=-ni

# Alterar nice de processo em execução (valor ABSOLUTO)
renice -n 10 -p PID
renice -n 10 -u usuario
renice -n 10 -g PGID

# No top: tecla r -> PID -> valor
top
```

**Números para decorar**

| Item | Valor |
|------|-------|
| Faixa do nice | -20 a 19 |
| Padrão | 0 |
| Incremento padrão do `nice` | +10 |
| Mais prioritário | -20 |
| Menos prioritário | 19 |
| PR no `top` (processo normal) | 20 + NI |
| Negativo só com | root |

**Fórmulas mentais**

- `nice -n X` → nice final = nice atual **+ X**
- `renice -n X` → nice final = **X**
- Prioridade ↑ ⇒ nice ↓

## 13. Armadilhas comuns na prova

1. **Inverter a lógica:** achar que nice maior = mais prioridade. É o contrário.
2. **`nice -5 cmd`:** é **+5**, não -5. Negativo exige `--5` ou `-n -5`.
3. **`nice cmd` sem `-n`:** incremento de **+10**, não 0.
4. **`renice` não soma:** define valor **absoluto**.
5. **Usuário comum não consegue diminuir o nice**, nem de seus próprios processos, depois de ter aumentado.
6. **Usuário comum não altera processo de outro usuário.**
7. **Confundir `NI` com `PR`/`PRI`:** o que você altera é o `NI`.
8. **`renice` precisa de PID** (ou `-g`/`-u`); não aceita nome de comando.
9. **`nice` não funciona em processos de tempo real** (é para `chrt`).
10. **Limite de faixa:** valores além de -20/19 são ajustados, não geram erro.
11. **`nice` sem argumentos** imprime o nice atual, não executa nada.
12. **`top` usa `r` para renice** (e `k` para kill, que é do 103.5).

```bash

```

```bash
sudo renice -n 5 -u $USER

```

### Exercício 10 — Teste de carga visível

Abra dois terminais e rode, em cada um, um loop de CPU (use o mesmo núcleo para ver a disputa):

```bash
# Terminal 1
taskset -c 0 nice -n 0 sh -c 'while :; do :; done'
# Terminal 2
taskset -c 0 nice -n 19 sh -c 'while :; do :; done'
```

No `top` (terceiro terminal), observe que o processo com nice 0 consome muito mais CPU que o de nice 19. Encerre com `Ctrl+C` ou `pkill -f 'while :'`.

> Se não vir diferença clara, lembre-se do **autogroup** (seção 11.5); rodar com `setsid` ou na mesma sessão ajuda.

### Exercício 11 — Renice pelo `top`
1. Inicie `sleep 900 &`.
2. Abra o `top`, pressione `r`, informe o PID e o valor 12.
3. Confirme a coluna `NI`.

### Exercício 12 — Ordenando por nice

- a) `nice`
- b) `renice`
- c) `ionice`
- d) `chrt`

---

## 16. Gabarito comentado

| # | Resp. | Explicação |
|---|:-----:|------------|
| 1 | **b** | A faixa é de -20 (maior prioridade) a 19 (menor). |
| 2 | **b** | `nice -n 19` é a menor prioridade. A opção (a) seria a *maior* e exige root; (c) está errada (`renice` exige PID); (d) `--19` significa **-19**. |
| 3 | **b** | Forma antiga: `-5` equivale a `-n 5` (+5). Para -5 seria `--5` ou `-n -5`. |
| 4 | **c** | O incremento padrão do `nice` é +10; 0 + 10 = 10. |
| 5 | **b** | `renice` define valor **absoluto**: o novo nice é 10, não 15. |
| 6 | **c** | Valores negativos (maior prioridade) são exclusivos do root (salvo limites configurados em `limits.conf`). |
| 7 | **c** | `r` de *renice*. (`k` é kill.) |
| 8 | **b** | `-u` seleciona todos os processos do usuário. `-p` espera PID; `-g` espera grupo de processos; `nice` não tem `-u`. |
| 9 | **b** | `NI` = nice. `PRI` é a prioridade calculada pelo kernel. |
| 10 | **c** | Usuário comum não pode **diminuir** o nice (aumentar prioridade), nem em processo próprio. |
| 11 | **b** | `nice` sem argumentos imprime o nice atual. |
| 12 | **c** | `PR = 20 + NI` para processos normais: 20 + 10 = 30. |
| 13 | **c** | `nice` **soma** ao nice atual: 5 + 10 = 15. |
| 14 | **d** | `renice` aceita PID (`-p`), grupo (`-g`) e usuário (`-u`); não aceita nome de comando. |
| 15 | **c** | `ionice` cuida de E/S. `nice`/`renice` tratam CPU; `chrt` trata políticas de tempo real. |
