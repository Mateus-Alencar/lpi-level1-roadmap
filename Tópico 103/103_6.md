# LPIC-1 — 103.6: Modificar a prioridade de execução de um processo

**Exame 101-500 · Peso 2 · Comandos-chave:** `nice`, `renice`, `ps`, `top`

---

## 1. O que a prova cobra

- Saber a prioridade **padrão** de um processo.
- **Iniciar** um programa com prioridade maior ou menor.
- **Alterar** a prioridade de um processo **já em execução**.

---

## 2. Conceito central

- O que você altera é o **NI (nice)**. O **PR/PRI** é calculado pelo kernel.
- **Lógica invertida:** menor nice = **maior** prioridade; maior nice = **menor** prioridade.
- O processo filho **herda** o nice do pai.
- A prioridade só faz diferença quando há **disputa por CPU**.

```
-20 ............ 0 ............ 19
Maior prioridade   Padrão     Menor prioridade
```

---

## 3. Números para decorar

| Item | Valor |
|------|-------|
| Faixa do nice | **-20 a 19** |
| Padrão | **0** |
| Maior prioridade | -20 |
| Menor prioridade | 19 |
| Incremento padrão do `nice` (sem `-n`) | **+10** |
| Valores negativos | **somente root** |
| PR no `top` (processo normal) | **PR = 20 + NI** |

- Valores fora da faixa são **ajustados** ao limite, sem erro (`nice -n 100` → 19).
- Não decore o valor absoluto de `PRI` no `ps -l` (varia conforme a versão); foque no **NI**.

| NI | PR (top) |
|----|----------|
| -20 | 0 |
| 0 | 20 |
| 10 | 30 |
| 19 | 39 |

---

## 4. `nice` — iniciar um comando

O `nice` **soma** (incremento) ao nice atual do shell.

| Comando | Efeito |
|---------|--------|
| `nice` | **Imprime** o nice atual (não executa nada) |
| `nice cmd` | nice **+10** |
| `nice -n 5 cmd` | **+5** |
| `nice -5 cmd` | forma antiga = **+5** (não é -5!) |
| `nice -n -5 cmd` | **-5** (só root) |
| `nice --5 cmd` | forma antiga = **-5** (só root) |
| `nice -n 19 cmd` | menor prioridade possível |
| `nice -n -20 cmd` | maior prioridade possível (só root) |

Exemplos de soma:

```bash
nice                       # 0
nice -n 5 nice             # 5   (0 + 5)
nice -n 5 nice -n 5 nice   # 10  (0 + 5 + 5)
```

Shell com nice 5 + `nice -n 10 cmd` → **15**.

Usuário comum com valor negativo:

```bash
$ nice -n -5 ls
nice: cannot set niceness: Permission denied
```

---

## 5. `renice` — alterar processo em execução

O `renice` define um **valor ABSOLUTO** (substitui, não soma).

```bash
renice -n 10 -p 1234        # por PID (-p é o padrão se omitir)
renice 10 1234              # sintaxe antiga também vale
renice -n 5 -p 1234 1235    # vários PIDs
renice -n 5 -u joao         # TODOS os processos do usuário
renice -n 10 -g 3000        # grupo de processos
```

| Opção | Alvo |
|-------|------|
| `-p` | PID |
| `-g` | Grupo de processos |
| `-u` | Usuário |

- **Não aceita nome de comando**, só PID, grupo ou usuário.
- Processo com nice 5 + `renice -n 10` → fica **10** (não 15).
- Saída: `1234 (process ID) old priority 0, new priority 10`

---

## 6. Ver a prioridade

```bash
ps -l                                # colunas PRI e NI
ps -o pid,ni,pri,comm -p PID
ps -eo pid,ni,comm --sort=-ni        # maiores nices primeiro (menor prioridade)
ps -eo pid,ni,comm --sort=ni         # menores nices primeiro (maior prioridade)
```

**No `top`:** as colunas `PR` e `NI` aparecem por padrão.

| Tecla | Ação |
|-------|------|
| `r` | **Renice** (pede o PID e depois o novo valor) |
| `k` | Kill (103.5) |
| `u` | Filtrar por usuário |
| `P` | Ordenar por CPU |
| `M` | Ordenar por memória |
| `q` | Sair |

Fluxo do renice no `top`: `r` → PID → Enter → novo nice → Enter.

## 7. Permissões (muito cobrado)

| Situação | Usuário comum | Root |
|----------|:-------------:|:----:|
| Iniciar com nice **positivo** | ✅ | ✅ |
| Iniciar com nice **negativo** | ❌ | ✅ |
| `renice` **aumentando** o nice de processo próprio | ✅ | ✅ |
| `renice` **diminuindo** o nice (mesmo de processo próprio) | ❌ | ✅ |
| `renice` de processo de **outro usuário** | ❌ | ✅ |

**Regra "sem volta":** o usuário comum aumenta o nice (10) e **não consegue voltar** para um valor menor (5). Resultado: `Permission denied`. Só o root consegue.

```bash
$ renice -n 10 -p 4010
4010 (process ID) old priority 0, new priority 10
$ renice -n 5 -p 4010
renice: failed to set priority for 4010 (process ID): Permission denied
$ sudo renice -n 5 -p 4010
4010 (process ID) old priority 10, new priority 5
```

Causa: limite `RLIMIT_NICE` (padrão 0), ajustável em `/etc/security/limits.conf`:

```
joao   hard   nice   -5
```

---

## 8. `nice` × `renice`

| Característica | `nice` | `renice` |
|----------------|--------|----------|
| Quando usar | Ao **iniciar** um comando | Em processo **já em execução** |
| Alvo | Comando novo | PID, grupo (`-g`) ou usuário (`-u`) |
| Valor | **Incremento** (soma) | **Absoluto** (substitui) |
| Padrão se omitir | **+10** | Não há (valor obrigatório) |
| Forma antiga | `nice -5` = +5; `nice --5` = -5 | `renice 5 PID` |
| Imprime nice atual | Sim (sem argumentos) | Não |

---

## 9. Com jobs e `nohup`

```bash
nice -n 15 ./script.sh &              # em segundo plano
nohup nice -n 10 ./script.sh &        # sobrevive ao logout
sleep 300 &
renice -n 8 -p $!                     # $! = PID do último processo em background
ps -o pid,ni,comm -p $!               # conferir
```

## 10. Extras (aparecem como alternativas)

| Ferramenta | Função |
|------------|--------|
| `nice` / `renice` | Prioridade de **CPU** (política normal) |
| `ionice` | Prioridade de **E/S de disco** |
| `chrt` | Políticas de **tempo real** |

```bash
ionice -c 3 cmd            # classe idle: só usa disco ocioso
ionice -c 2 -n 7 cmd       # best-effort, prioridade 7 (menor)
chrt -p 1234               # mostra política e prioridade do PID
sudo chrt -f 50 cmd        # SCHED_FIFO, prioridade RT 50
sudo chrt -r 20 cmd        # SCHED_RR, prioridade RT 20
```

| Política | Tipo | Observação |
|----------|------|------------|
| `SCHED_OTHER` (TS) | Normal | Padrão; controlada por **nice** |
| `SCHED_BATCH` | Normal | Cargas em lote |
| `SCHED_IDLE` | Normal | Só roda se nada mais quiser CPU |
| `SCHED_FIFO` (FF) | Tempo real | Roda até terminar ou ceder |
| `SCHED_RR` (RR) | Tempo real | Como FIFO, com fatias de tempo |

- O nice **não** afeta processos de tempo real.
- Prioridade de tempo real vai de 1 a 99, e **maior número = maior prioridade** (ao contrário do nice).
- Processos de tempo real aparecem como `rt` ou PR negativo no `top`.
- O nice funciona como **peso** no escalonador (CFS, e EEVDF em kernels 6.6+): nice menor = maior fatia de CPU.
- `autogroup` (desktops): pode fazer o nice parecer não ter efeito entre sessões diferentes.

---

## 11. Armadilhas clássicas

1. **Inverter a lógica:** nice maior não é mais prioridade.
2. **`nice -5 cmd`** é **+5**; negativo exige `--5` ou `-n -5`.
3. **`nice cmd`** sem `-n` soma **+10**, não 0.
4. **`nice` soma; `renice` substitui.**
5. Usuário comum **não diminui** o nice, nem de processo próprio.
6. Usuário comum **não mexe** em processo de outro usuário.
7. Confundir `NI` (o que você muda) com `PR`/`PRI`.
8. **`nice` sem argumentos** só imprime o nice atual.
9. `renice` precisa de **PID, `-g` ou `-u`**, nunca nome de comando.
10. `nice` = CPU; `ionice` = disco; `chrt` = tempo real.
11. Valores fora da faixa são ajustados, não geram erro.
12. No `top`, **`r`** = renice e **`k`** = kill.

---

## 12. Cheat sheet

```bash
nice                         # mostra o nice atual
nice cmd                     # +10
nice -n 15 cmd               # +15
nice -n -10 cmd              # -10 (root)

ps -l   # Exibe processos em formato longo, incluindo PID, PPID, prioridade (PRI) e nice (NI)
ps -o pid,ni,pri,comm -p PID # Exibe PID, nice, prioridade, nome do comando de um processo específico
ps -eo pid,ni,comm --sort=-ni # Lista todos os processos ordenados pelo valor de nice em ordem decrescente

renice -n 10 -p PID          # valor ABSOLUTO
renice -n 10 -u usuario
renice -n 10 -g PGID

top                          # tecla r -> PID -> valor
```

**Fórmulas mentais**

- `nice -n X` → nice final = nice atual **+ X**
- `renice -n X` → nice final = **X**
- Prioridade ↑ ⇒ nice ↓
- `NI = 10` → `PR = 30`
